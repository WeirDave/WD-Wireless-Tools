WD Cloud Manager

Manage Ekahau cloud sites and local project folders side by side. Sync, merge, and organize your wireless survey projects.

Getting Started

Step 1
Log In
Click Log In to authenticate with Ekahau Cloud. Your browser will open to complete the login flow.
Step 2
Set Local Folder
Open Settings and set your local folder path — where your .esx project files are stored on disk.
Step 3
Browse
The Sites tab shows the ledger view — cloud sites on the left, local folders on the right.
Step 4
Manage
Rename, delete, create, or merge projects directly from the ledger. Changes sync immediately.
Tip: After logging in, Cloud Manager remembers your session in an encrypted cache protected by Windows Credential Manager or macOS Keychain. Use Menu → Forget Cloud Login to remove it from this computer.

The Ledger View

The main interface is a two-column ledger that shows your Cloud Sites on the left and Local Folders on the right. This makes it easy to see what exists in each location at a glance and spot projects that are only on one side.

  • Cloud Sites (left) — projects stored in Ekahau Cloud, pulled from your account.
  • Local Folders (right) — .esx files found in your configured local folder path.
  • Sites that exist in both locations are shown on the same row when names match.
  • Sites that only exist on one side appear with an empty cell on the other side.
Tip: The ledger auto-refreshes on a configurable interval (see Settings). You can also manually refresh by clicking the refresh button in the toolbar.

The Sites Tree

Each site (or local-only folder) is a collapsible group, like a folder in Windows Explorer. Click the ▸ next to a site's name to expand it and see the individual projects inside — still shown in the same cloud-left / local-right layout, just indented under their site. Sites start expanded so you can scan a large scope at a glance; click the chevron again to collapse a site you don't need right now.

Cloud projects that don't belong to any site at all can't nest under a folder, so they're listed together at the very bottom under Orphan Projects. Use the ↪ button on an orphan row to move it into a site.

How Matching Works

Every Ekahau project has a hidden ID stamped inside its .esx file when it's first created. That ID sticks with the project through every edit, rename, upload, and download. When we see the same hidden ID on your computer AND in Ekahau Cloud, we know it's the same project — no guessing.

For projects where we can't check IDs (created locally and never uploaded, or two files with unrelated histories), we fall back to name-based matching. Exact same name is very reliable. Same site code + similar name is likely. Only similar names is a guess, and we say so.

The five ways WD pairs two files

Every paired row has a small badge in the middle gutter — hover to see the plain-English reason.

BadgeWhat it means
★ You matchedYou linked these manually using the 🔗 Link button. Overrides everything else. Click the badge to unlink.
✓ Same fileSame hidden project ID inside both files — proven, not guessed. This is one project stored in two places.
✓ Name matchesFilenames are identical but no hidden-ID link. Very likely the same project, not proven.
~ Same siteSame site code (like CLMB2) plus similar names. Probably the same project.
? Similar nameSome words in common. Our best guess — worth a look before syncing.

What about file size?

Cloud files and local files store the same content very differently. Ekahau Cloud stores .esx files uncompressed (bigger), while your computer compresses them (smaller). A cloud file that's 6× larger than your local copy is usually still the same project. That's why we don't use size for matching, and we don't show it on file rows — it confuses more than it helps. Size is still shown in the folder-peek popup and Duplicates tab, where you're comparing files of the same kind.

What about dates?

The date shown next to each file is when someone last edited the project inside Ekahau, not when the file was copied to your computer. Two copies with the same date and time are the same version. Different dates just mean someone kept working on one copy after the other. Because the date comes from inside the file, copying / OneDrive sync / renaming don't reset it.

Held Back — pairs WD didn't auto-match

Sometimes two files look related (same site code, overlapping words) but a hard difference stops WD from pairing them automatically — a different building number (Bldg 3 vs Bldg 5), a different street number, or a different survey phase (Baseline vs Cleanroom). Those pairs land in a Held Back section at the bottom of the ledger with the reason spelled out and two buttons:

  • Link anyway — if you know WD is being over-cautious, this pairs them and remembers your decision forever.
  • Not a match — if WD was right to hold them back, this tells it to never suggest the pair again.

When we get it wrong

  • Pair we missed? Click the 🔗 button on either orphan file → pick the counterpart from the list. WD remembers this forever.
  • Pair we shouldn't have made? Click the ≠ button on the mismatched pair. WD will never suggest them again.
  • Held back but you know better? Click Link anyway on the held-back row.
Tip: Click the ⓘ How matching works chip next to the search box in the app for a shorter in-app version of this section.

Managing Sites

Right-click a site or use the action buttons on any row in the ledger to manage it.

Create

Create a new empty site on the cloud side, or a new project folder on the local side. The new entry appears in the ledger immediately.

Rename

Rename a cloud site or local folder directly from the ledger. The change takes effect on the cloud or filesystem right away.

Delete

Remove a cloud site or local folder. You will be prompted to confirm before anything is deleted.

Note: Deleting a cloud site removes it from Ekahau Cloud permanently. Deleting a local folder moves it to the system recycle bin when possible.

Merging Projects

The merge feature lets you compare a cloud site against a local project and sync differences between them.

  1. Select a row where both a cloud site and a local folder exist.
  2. Click Merge to open the merge preview.
  3. The preview shows what has changed — added, modified, or removed files on each side.
  4. Choose which direction to sync: cloud to local, local to cloud, or resolve conflicts individually.
  5. Confirm the merge to apply the changes.

Conflict Resolution

When a file has been modified on both the cloud and local side since the last sync, a conflict is flagged. You choose which version to keep — cloud, local, or skip the file entirely.

Note: Always review the merge preview before confirming. Merging overwrites files on the target side with the selected version.

Settings

Open the Settings panel from the toolbar to configure Cloud Manager.

SettingDescription
Local Folder PathThe directory on your machine where local .esx project files are stored. Cloud Manager scans this folder to populate the right side of the ledger.
Auto-Refresh IntervalHow often the ledger re-fetches cloud sites and re-scans local folders (in seconds). Set to 0 to disable auto-refresh.
Tip: Point the local folder path to the same directory Ekahau AI Pro uses for saving projects. That way the ledger always reflects what Ekahau sees.
