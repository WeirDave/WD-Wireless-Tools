How matching works

Every Ekahau project has a hidden ID stamped inside its .esx file when it's first created. That ID sticks with the project through every edit, rename, upload, and download. When we see the same hidden ID on your computer AND in Ekahau Cloud, we know it's the same project — no guessing.

For projects where we can't check IDs (created locally and never uploaded, or two files with unrelated histories), we fall back to name-based matching. Exact same name is very reliable. Same site code + similar name is likely. Only similar names is a guess, and we say so.

The five ways WD pairs two files

★ You matched You linked these manually. Overrides everything else.
✓ Same file Same hidden project ID inside both .esx files. Definitive — this is one project, in two places.
✓ Name matches Filenames are identical but no hidden-ID link. Very likely the same project, not proven.
~ Same site Same site code (like CLMB2) plus similar name. Probably the same.
? Similar name Some words in common. Our best guess — look before syncing.

What about file size?

Cloud files and local files store the same content very differently. Cloud stores it uncompressed (bigger), your computer compresses it (smaller). A cloud file that's 6× larger than your local copy is usually still the same project. That's why we don't use size for matching, and we don't show it on file rows — it confuses more than it helps. (Size is still shown in the folder-peek popup and Duplicates tab, where you're comparing files of the same kind.)

What about dates?

The date shown is when someone last edited the project inside Ekahau, not when the file was copied to your computer. Two copies with the same date and time are the same version. Different dates just mean someone kept working on one copy after the other.

When a matched pair has different edit dates, you'll see a badge: ⬇ Cloud newer means the cloud copy was edited after the local one (download to get the latest), and ⬆ Local newer means you have edits locally that haven't been uploaded yet.

When we get it wrong

  • Pair we missed? Click the 🔗 button on either orphan file → pick the counterpart. WD remembers this forever.
  • Pair we shouldn't have made? Click the ≠ button on the mismatched pair. WD will never suggest them again.
  • Held back but you know better? Click Link anyway on the held-back row.
