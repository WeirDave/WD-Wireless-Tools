WD Cloud Manager — sharing modal scales to larger orgs. Wider layout (920px cap), share list flows into 2-3 responsive columns instead of a single tall stack, filter input appears when the list exceeds 6 non-owner shares.

Suite `v1.9.56 → v1.9.57`. WD Cloud Manager `v4.9.5 → v4.9.6`.

## the maintainer's ask

> "you made the sharing box great because I only have two people but what if you're in an organization with a dozen people That modal you made won't work so you're going to need to do something else either create a separate web page or make it much wider and have stacking with columns"

Fair — a modal built around 2-3 shared users breaks at 12+. Went with the "wider + column-stacked" option since it keeps the sharing workflow in a familiar modal shape and doesn't require a route change.

## What changed

**Modal width**: `width: 920px; max-width: min(90vw, 920px)`. Base `.modal` was 440px fixed — needed to override both `width` and `max-width` on `.share-modal`. On smaller screens (laptop <1024px) it still respects viewport width via 90vw.

**Share list layout**: was a single vertical stack (`display: flex; flex-direction: column`), now a responsive CSS grid:

```css
.share-list-body {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
  gap: 4px;
}
```

At 920px modal width → 2 columns of ~390px. Narrower screens fall back to 1 column automatically. Each row is a compact card with `name + email | role select | × remove` in a 3-cell grid — the fluid column has `minmax(0, 1fr)` to prevent long emails from pushing the role select off-screen.

**Filter input**: rendered above the list only when more than 6 non-owner shares exist. Case-insensitive substring match against `firstName + lastName + username`. Owner always stays visible under any filter so the sub-header count stays accurate. Focus and cursor position preserved across re-renders (which happen frequently after role changes / removes) via a re-focus + `setSelectionRange` after each render.

**Group Members panel** got the same grid treatment (`minmax(240px, 1fr)`) since a group with 20 members would have had the same problem.

**Max height increases**: share list bumps to 420px (was 340px), group members list to 260px (was 200px). Internal scroll instead of pushing the rest of the modal off-screen.

## Verified in the preview

Steps run in the browser pane:

1. Reloaded `/cloud` — version chip `v4.9.6`.
2. Opened share modal on a 3-share project: modal renders 865px wide (capped at 90vw on this viewport), grid is 2 columns, no filter (below threshold). All 3 rows visible in row 1 of the grid.
3. Simulated a 15-user share list via ctx mutation: grid still 2 columns × ~388px, filter input renders with placeholder "Filter by name or email…", all 15 rows visible.
4. Typed "test5" in the filter: 2 rows visible (Owner + Test User5). Filter input stays focused, cursor at end — typing continues uninterrupted.
5. Cleared filter: all 15 rows back.

Screenshot capture flaky this session (~fifth time modal-heavy screenshots timed out). DOM state confirmed for every check.

## Files changed

- `web/assets/js/cloud.js`:
  - `_shareRender` — wraps the row output in `.share-list-body`; conditionally emits `.share-list-filter` when non-owner count > 6; applies `ctx.shareFilter` substring match; re-focuses input + restores cursor after re-render; empty-search fallback message.
  - `_shareFilterChange(v)` — new handler; stashes filter on `_shareCtx.shareFilter` and re-renders.
  - `_renderGroupMembersPanel` — empty-state class renamed to `.share-group-member-empty` so grid layout doesn't stretch it awkwardly.
- `web/assets/wd-tools.css`:
  - `.modal.share-modal` — widened to 920px cap via explicit `width` + `max-width: min(90vw, 920px)`.
  - `.share-list` becomes a container with padding, no longer displays flex. `.share-list-body` is the new grid.
  - `.share-row` — grid columns tightened to `minmax(0, 1fr) 130px 28px`, added `background: var(--surface-raised)` for card-like appearance against the container.
  - `.share-list-filter` — new; focus state uses accent border.
  - `.share-group-members-list` — same grid treatment (`minmax(240px, 1fr)`), max-height bumped to 260px.
  - `.share-group-member-empty` — new; spans grid full-width for centered display.
- `web/assets/versions.json`, `web/cloud.html` — version chip bump.
