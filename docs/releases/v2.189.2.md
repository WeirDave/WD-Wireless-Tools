# Report: the first page prints on the paper it asks for, and no blank sheet at the end

Suite **2.189.2** ships **Report 2.66.2**. The Report page shows its own tool number, not the suite number.

## What changed

### Page one stayed portrait in Firefox

- **Setting the cover to Landscape moved the cover's text but left the sheet portrait.** Every later page printed on the paper it asked for, so the fault was only ever on page one. "Match all pages" did not change it, because the cover already had the right setting.
- **The cause was in how Firefox prints the page around the report, not in the orientation settings.** Firefox gave some empty spacing around the hidden controls above the report a box of its own on the printout. That box had no paper size, so the sheet it landed on used the printer's default, portrait. The spacing is now removed when a report is built. Chrome and Edge never showed the fault.
- **Where to see it:** Report → Review step, the **Page** control above the cover (**Auto**, **Portrait**, **Landscape**) and **Match all pages**. The control and its defaults are unchanged. The cover still follows the rest of the report on **Auto**.

### A blank sheet after the last page

- **Firefox printed an extra, empty sheet at the end of a report.** On an AP Placement Map it came straight after the AP Labels pages. There were three causes, and each one is fixed:
  - the same empty spacing, this time after the report
  - a landscape cover that was taller than a landscape sheet, which pushed the rest of it onto a blank second sheet. The cover's height is now set for each paper orientation.
  - a nearly full portrait Compass & Antenna Alignment page, where the gap under its last paragraph did not fit and went onto a sheet of its own. That gap is removed in print.

## Verified

- A new browser test drops a two-floor project on the real Report page, builds the AP Placement Map, and prints it. It then reads the paper size of every sheet in the PDF. There must be exactly one sheet per page, and each sheet must match the orientation the page asks for. The test covers three layouts:
  - all landscape
  - a landscape cover with portrait pages after it
  - all portrait
- It was printed here in Firefox 153 and Chromium 141. Before the fix, Firefox printed `P L L L L L` plus a blank sheet for an all-landscape report. After the fix it prints `L L L L L L`. Chromium printed correctly both before and after.
- The test fails if the spacing removal, the cover height or the Compass page change is taken out. Each was taken out one at a time to confirm this.
- Edge is covered by the same test in CI.
