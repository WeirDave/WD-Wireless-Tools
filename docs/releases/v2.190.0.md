# PlanTrim: trimmed CAD floor plans keep their white page, and plans trimmed earlier are repaired on save

Suite **2.190.0** ships **PlanTrim 1.20.0**. The PlanTrim page shows its own tool number, not the suite number.

## What changed

### Trimmed CAD plans showed grey lines on black

- **Affected:** floor plans imported from CAD, which Ekahau stores as SVG drawings, trimmed by suite 2.91.0 through 2.189.1 (PlanTrim 1.7 through 1.19.4). Plans imported from PDF or image files (PNG, JPEG, BMP, GIF, TIFF, WebP) are not affected.
- **Cause:** a vector plan is cropped by moving its visible window, not by cutting pixels. Many CAD drawings paint their white page as "100% of the page", measured from the drawing's origin. Once the window moved, that page no longer covered it, and the area behind the lines became transparent. Shown against a dark background, the plan read as grey lines on black.
- **The drawing itself was never altered.** Every line, wall and label is byte-for-byte what it was before the trim. Only the page behind the drawing stopped covering the plan.
- **New trims keep the page.** Any size a drawing gives as a percentage of the page is now written out as the length it stood for before the window moves, so the page covers the trimmed plan exactly as it covered the original.
- **Plans trimmed by an earlier version are repaired when the project is saved from PlanTrim.** Open the project in PlanTrim. In the floor list, each affected floor shows a **Repair** badge with "Page behind the drawing restored on save". In the floor strip beside the plan, it reads **Repair**. The button below the plan reads **Save repaired .esx** when repairs are the only change, or **Cut and save** when there is also something to trim. As with every PlanTrim save, a new copy is written and the original file is not changed.
- The repair restores the page from the drawing's origin to the far edge of the trimmed plan. The original page size is not stored in a trimmed file, and that is the smallest page that covers everything still shown.
- **A drawing that measures percentages against something other than the page** (a nested SVG frame, a symbol, or clip, mask or pattern content in object-bounding-box units) is no longer cropped. The floor shows **Refused** with the reason, instead of being cropped into a different picture.

### The PlanTrim canvas draws plans on a white page

- The plan in PlanTrim's canvas is drawn on white. Any part of a drawing that is transparent shows as paper rather than as the dark background of the page.

## Verified

- A synthetic CAD plan with a 100% white page, trimmed by the previous version, renders as grey lines on black in Chrome, Edge and Firefox. The same plan trimmed by this version, and the previous version's output repaired by this version, both render white in all three browsers. The test checks all three results by rendering them in each browser.
- Tests cover these cases:
  - a page given in percentages, with and without a viewBox
  - each axis, and a radius measured against the diagonal
  - a page at a fixed size, which is left exactly as it was
  - a gradient percentage, which is left alone
  - a nested frame, which is refused
  - the repair: saving with nothing to cut, analysis reporting it without writing, re-trimming a repaired plan, never repairing a plan no crop has touched, and never repairing twice
- The PlanTrim page's own drawing, save-button and floor-strip code is run against the new report fields. The page is drawn onto white before the plan, and a repair on its own is enough to save.
- 17 of the 18 new tests fail against the previous version. The one that passes checks that a gradient percentage is left alone, which the previous version also did.
- Raster floor plans in nine colour modes (RGB, greyscale, palette, palette with transparency, 1-bit, RGBA, greyscale with alpha, 16-bit, and RGB with a transparent colour) come back from a trim in the same mode and pixel-identical to the region kept.

## Files changed

- `tools/esx_trimmer.py`: vector crops resolve page percentages; `repair_svg` and the repair step on save; the refusal for percentages of another box
- `server.py`: the trim response carries the repaired count
- `web/assets/js/plantrim.js`: saving is available for repairs alone; the Repair row, strip label and messages; the white page under the plan
- `web/assets/wd-tools.css`: the repaired floor row style
- `tests/test_plantrim_svg_background.py`: new
- `tests/test_plantrim_boxes.py`: the save-button tests load the shared check, and cover a repair with nothing to cut
- `web/assets/versions.json`, `README.md`: version numbers
