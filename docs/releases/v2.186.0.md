# Cloud Manager: upload a paired local file as a second cloud project

Suite **2.186.0** ships **Cloud Manager 4.76.0**. The Cloud Manager page shows the Cloud Manager number, not the suite number.

## What changed

### Cloud Manager: keeping both copies

- **A local `.esx` that is already paired with a cloud project can now be uploaded as a separate, new cloud project.** Before this release, **Upload** appeared only on a local file with nothing opposite it. A paired file offered only a download or a replace, so the only way to get it into the cloud was to overwrite one side.
- **Where it is:**
  - In the band under a paired row whose sides differ (for example **"Cloud newer · download"**), under the Cloud column: **"Upload as a new project…"**.
  - On any paired project row, in the local file's **⋯** menu: **"Upload as a new cloud project…"**.
- **What it does:** it asks for a name for the new project. The suggested name is the current name with **"(copy)"** added. The local file is renamed to that name and uploaded into the same site as the project it was paired with. The existing cloud project is not changed. When the upload finishes, the renamed local file pairs with the new cloud project.
- The name of the existing cloud project is refused, so the two projects can be told apart. Nothing is renamed or uploaded in that case.
- If the upload fails after the rename, the message says the local file now has the new name and the existing cloud project was not touched.

## Verified

- New tests render the real row, pull the control back out of the rendered markup and run it against recording stubs. They check that the local file is renamed first, that the renamed path is uploaded into the paired project's site, and that no call names the existing cloud project.
- Cancelling the name prompt, or entering the existing cloud project's name, makes no calls.
- The tests were confirmed to fail when the control's arguments are broken.
