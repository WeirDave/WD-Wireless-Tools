Cloud Manager: unassigned cloud projects whose local .esx sits in the correct site folder are now nested under that site with a "Not assigned" pill and a one-click **Assign to this site** button. Filter rework is coming in the next release.

## What changed

### The problem
A cloud project without a site parent in Ekahau ("unassigned" — you uploaded it but never clicked *Assign to site*) used to always land in the bottom "Unassigned Projects" section of the tree, even when its local `.esx` was sitting in exactly the right site folder. So the pair got visually split: the cloud copy at the bottom, the local copy shown as a `localOnly` child of the correct site above, and nothing tying them together. Common count in a typical workspace: 20–50 rows showing up as "orphan" when they're actually paired.

### Backend: cross-tree pairing pass
After the primary site/folder matching finishes, `build_folder_data()` runs one more pass: for every remaining unassigned cloud project, try to match its name against the pool of `localOnly` `.esx` files across every site in the tree. Successful matches are:
- pulled out of the "Unassigned" bucket,
- nested under the site whose folder holds the local `.esx`,
- tagged `unassigned: true` on the cloud side so the frontend can badge them.

The unassigned bottom section shows only genuine orphans (no local counterpart anywhere) after this pass — the count drops by however many pairs the matcher recovered.

### Frontend: "Not assigned" pill + one-click Assign button
- `cloudCell()` renders an amber **Not assigned** pill (`.ptype-tag.pt-unassigned`) whenever `c.unassigned` is true — visible in Tree, Flat, and the unassigned section.
- On tree-child rows only, a paperclip **Assign to this site** button appears in the row's action cluster. It targets the row's parent site (threaded through `renderTreeChildren` → `cloudCell`) so no picker is needed — one click and Ekahau's own site membership catches up with what the tree already shows.
- Success toast: `Assigned "<project>" to <site>`. The ledger auto-refreshes and the pill / button disappear on the next paint.
- Flat view intentionally omits the button (no natural "parent site" context there); pill still renders so the state is visible.

### Version bumps
- Suite `v1.9.10 → v1.9.11`
- Cloud Manager `v4.2.0 → v4.3.0`

## Files changed
- `tools/cloud_manager.py` — new cross-tree pairing block at the end of `build_folder_data()`. Builds a `path → (children, local_item)` index over every site's `localOnly` bucket, runs `build_matches` between remaining orphans and that pool, moves each hit into the right site's `children.matched` (with `unassigned: True` on the cloud), refreshes the per-site `mismatches`/`summary` fields, and removes moved items from `orphan_cloud`.
- `web/assets/js/cloud.js` — `renderSitesTree()` threads `parentSiteId` / `parentSiteName` into `renderTreeChildren()` → row objects → `cloudCell()`. `cloudCell()` gained `unassignedHtml` (pill) and `assignBtn` (only when unassigned AND `parentSiteId` present). New top-level `assignOrphanToSite(projectId, siteId, projectName, siteName)` POSTs `/api/cloud/assign_to_site` and refreshes on success.
- `web/assets/wd-tools.css` — `.ptype-tag.pt-unassigned` (amber, both themes) and `.icon-btn.assign-btn` (tinted background so the action reads as more than another passive icon).
- `web/assets/versions.json` — suite + cloud bumps.
