Stale-server guard + one-click restart. No more silent-empty dashboards after a `git pull`, no more hunting for the terminal window to restart, no more orphaned server processes.

## What changed

### The problem
`server.py` is a long-running Python process. HTML/CSS/JS and `versions.json` are served fresh from disk on every request, but the Python code stays cached in memory until the process itself restarts. So after a `git pull`, the browser sees the **new** UI, but every `/api/*` call still runs against the **old** backend — and the mismatched response shape (or missing endpoint entirely) shows up as zero counters, empty lists, and "Nothing here for this filter." with no explanation of why. On top of that, closing the browser tab left `python.exe` running as a background task with no obvious way to stop it, and every restart risked leaving another orphan behind.

### 1. Startup version handshake
`server.py` snapshots `versions.json` at process start and exposes it at `GET /api/version` alongside the process's PID and startup timestamp. `wd-shared.js` (loaded by every page) fetches both the on-disk `versions.json` and `/api/version` on load, and again on window focus (throttled to 5s). Any tool version mismatch paints a fixed red banner at the top of every page: *"Server is running old code. Click **Restart now** to load the latest build."* with a per-tool detail line showing exactly which versions diverged (e.g. `suite: running v1.9.8 → latest v1.9.9`). The banner runs on every page in the suite, and is a silent no-op on the hosted GitHub Pages build (no `/api` backend to compare against).

### 2. One-click "Restart now" button
Banner has a white pill button that POSTs `/api/restart`. The endpoint exits the process with sentinel code `42`; the launcher's loop catches that specific code and relaunches on the same port. The frontend polls `/api/version` until a new `startedAt` appears (usually <1s), then reloads the page — banner clears itself because versions now match. If the user launched the server outside `run.bat` (no loop to relaunch it), the polling times out with a clear "Try again" state instead of hanging forever.

### 3. Launcher loop with sentinel exit code
`run.bat` and `run.command` now wrap `python server.py` in a loop that only relaunches on exit code 42. Any other exit (CTRL+C, a clean quit, an actual crash) breaks the loop so the user's explicit shutdown isn't fought, and a crashing server doesn't get into a spin loop.

### 4. Orphan cleanup on launch
`run.bat` and `run.command` now kill any process still listening on port 8675 before launching a new one. Scoped to the listening PID on that specific port so unrelated Python work in other projects isn't touched. This means every double-click of the launcher gives you a fresh, single instance — no more "two servers running, which one is answering?" — and picks up cleanly after any state (orphaned tab close, hung process, whatever).

## Version bumps
- Suite `v1.9.8 → v1.9.9`
- No individual tool versions changed — this is an infrastructure/reliability release.

## Files changed
- `server.py` — startup snapshot of `versions.json`; `GET /api/version`; `POST /api/restart` (exits with code 42 after flushing response).
- `web/assets/js/wd-shared.js` — `WD.checkServerVersion()` version-compare + banner render; `_restartServer()` button handler with `/api/version` polling and reload; runs on `DOMContentLoaded` and `window focus`.
- `web/assets/wd-tools.css` — `.wd-stale-banner`, `.wd-stale-restart` (white pill), `.wd-stale-close`; `body.wd-has-stale-banner` padding so the banner doesn't cover page content.
- `run.bat` — PowerShell one-liner to kill any listener on 8675 before launch; `:start` / `IF ERRORLEVEL 42 GOTO start` loop around `python server.py`.
- `run.command` — `lsof` equivalent for macOS; `while [ $? -eq 42 ]` loop around `python3 server.py`.
- `web/assets/versions.json` — suite version bump.
