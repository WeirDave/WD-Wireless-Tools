# Cloud Manager stops pre-selecting the wrong site in Move to Site

Suite **2.215.0**: Cloud Manager **4.85.0**. Every other tool is unchanged.

## What changed

### Cloud Manager

- **A wrong guess is now an empty row.** In the **"Move to Site"** dialog (the **"Move to Site…"** action on a project's row, and the bulk action on a selection), each project is pre-selected for a destination and marked **"auto"** when a site looks right. That pre-selection now follows the same rules as the pairing of cloud projects with local files, and stays empty when no site is a clear fit. The destination can still be picked by hand.
- **A shared site code is no longer enough on its own.** The project's name also has to have real wording in common with the site's name. A project for one building of a site is no longer filed under a different building of it.
- **Building numbers, street numbers and survey phases are compared.** `Bldg 7` is not offered `Bldg 5`, `1200 Main St` is not offered `1400 Main St`, and `Baseline` is not offered `Remediation`. A year such as `2026` is not read as a street number.
- **Two equally good sites are not resolved by alphabetical order.** When two sites fit a project name equally well, nothing is pre-selected.
- **Version tags are ignored when comparing names.** Tags such as `v3` or `rev2` on a project name no longer lower its similarity to the site's name, so a fresh round of versioned uploads still finds its site.
- A project that sits in a local folder named for a site is still pre-selected into that site.

## Verified

- The suggestion logic is run in Node against invented site and project names: right building, wrong building, different street, tied sites, a clear winner among close names, a year in the name, and version tags. Removing any one rule turns at least one of those cases red.
- The building, street and phase checks are run alongside their server counterpart over the same set of name pairs and agree on every one.
- The full test suite passes.
