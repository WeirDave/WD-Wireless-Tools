# Cloud Manager: a download that would replace local changes can now be confirmed

Suite **2.246.22**, Cloud Manager **4.94.0**. Other tool versions are unchanged.

## What changed

### Cloud Manager (the download button on a matched row)

- **A download that was refused can now go ahead after a confirmation.** When the local file and the cloud copy had both changed since they were last the same, or the local file carried changes the cloud copy lacked, the download stopped with "Not downloaded" and offered no way forward; the only route was to delete the local file and download the project again. The download now asks first. The dialog "Download the cloud copy and discard local changes?" names the file, the date each side was last edited and what is lost, and its button **Download and discard local changes** replaces the local file with the cloud copy. **Cancel** leaves both copies untouched.
- **Nothing changes for an ordinary download.** A cloud copy that is simply newer is downloaded without a question, and a pair whose contents match is still never held up.
- **No copy of the replaced local file is kept**; the cloud copy is the other copy. **Check** on the row shows what differs before choosing.
- **Bulk Sync and the multi-row download still skip such pairs** and report them as skipped; the choice is made one row at a time, from the row's download button.

## Verified

- The server-side download replaces the local file only when the confirmation is sent, and refuses without it for both a pair where both sides changed and a local file with the later date.
- The page's download handler asks once, sends the confirmed request with the override, sends nothing further after a cancel, and never asks for an ordinary download.
- Both new checks fail when the override is removed from either the server or the page.
