WD Cloud Manager — Owner filter (All / Mine / Others), Expand/Collapse, cluster cards, and other tab-switched controls now actually toggle after being cross-injured by two prior releases.

Suite `v1.24.1 → v1.24.2`. Cloud `v4.12.1 → v4.12.2`.

## the maintainer's ask

> "WTH where are the owner filters??!?!?!?"

The Owner-by filter chip row in Cloud's toolbar was invisible.

## Root cause

Two prior releases interacted badly:

- **v1.10.0** converted 35 `style="display:none"` attributes to the native `hidden` HTML attribute across the suite.
- **v1.11.0**'s CSS audit added `[hidden] { display: none !important; }` to reassert the UA rule (which was losing to author class-level `display: flex` etc. — the cluster-card flash bug).

But some JS callsites still toggled visibility with the old pattern: `element.style.display = ''` to show, `element.style.display = 'none'` to hide. That pattern worked when the initial state was `style="display:none"` because `.style.display = ''` cleared the inline style and let the element revert to its class-level `display: flex`. With `hidden` on the element AND `[hidden] { display: none !important }` in CSS, clearing inline `.style.display` leaves `!important` in force — the element stays hidden forever. The `hidden` attribute is the strong signal and only `.hidden = false` clears it.

## Fix

Converted every `.style.display = '' / 'none' / 'block' / 'flex'` in `cloud.js` that targets a `hidden`-attributed element to the proper `.hidden = true / false` toggle. 21 fixes across the file:

- `setAuthState()` — `authLogin`, `authWaiting`
- `showApp()` / `goToDashboard()` — `setupScreen` toggling
- `setupPickFolder()` — `setupFolderPath`, `setupContinueBtn` reveal
- `_syncTabUI()` — `expandAllBtn`, `collapseAllBtn`, `ownerToggle`, `dupDeleteAllToolbarBtn`
- `updateDashboard()` — `dDupAllCard`, `dDupMixedCard`, `dDupLocalCard`, `dDupCloudCard`, `dNameMatchesCard`, `dTypeDesignCard`, `dTypeMeasuredCard`, `dTypeHybridCard`, `dUnassignedCard`
- `renderDuplicates()` — toolbar Delete-all-extras chip
- `openManageShares()` / `_shareRender()` — `shareDangerSlot` show/hide
- `_lpFilter()` — `linkPickerEmpty` show/hide
- `openMergePreview()` — `mergeConflictWrap` guard clause

Callsites that touch elements *without* `hidden` in their initial HTML (e.g. `addNewBtn`, `loginScreen`, `appScreen`, `authChecking`) were left on `.style.display` — that pattern still works for them.

## Broader lesson

`element.style.display` and the `hidden` attribute are incompatible signals when `[hidden]` is enforced with `!important`. Going forward: if an element ships with `hidden` in HTML, JS must toggle it via `.hidden = true/false`, never `.style.display`.
