WD Cloud Manager — rename the two most-confused match badges. `Exact same` → `Same file`; `Same name` → `Name matches`.

Suite `v1.9.28 → v1.9.29`. WD Cloud Manager `v4.6.4 → v4.6.5`.

## The problem the maintainer flagged

The green **✓ Exact same** (id-verified) and blue **✓ Same name** (name-matched) badges read as synonyms. Users hit files they knew were the same project but showed up as the "weaker" blue badge because Ekahau's upload flow doesn't preserve the local `.esx`'s hidden UUID — Pass 0 misses those pairs, Pass 1 catches them by name, and the labels don't communicate that the state is "we're pretty sure but can't prove it."

## The rename

| Match | Was | Is now |
|---|---|---|
| Pass 0 (hidden ID equality) | ✓ Exact same | **✓ Same file** |
| Pass 1 (exact name equality) | ✓ Same name | **✓ Name matches** |
| Pass 2 (site code + fuzzy) | ~ Same site | (unchanged) |
| Pass 3 (fuzzy only) | ? Similar name | (unchanged) |
| Pass −1 (user override) | ★ You matched | (unchanged) |

"Same file" reads as *"one thing in two places"* — the strongest possible claim. "Name matches" reads as *"we're taking the filename at face value"* — clearly a weaker claim than "Same file." Semantic step-down between the two is now visible without hovering.

Tooltips updated to match the new wording. Help modal in the app and the user guide's *How Matching Works* section are all in sync.

## Verified in the preview

Reloaded and counted badges on the maintainer's live data: **60 `Same file`**, **75 `Name matches`**, 1 `Same site`, 1 `Similar name` (real data — no manual pairs at the moment). The green-vs-blue distinction still holds visually; only the words change.
