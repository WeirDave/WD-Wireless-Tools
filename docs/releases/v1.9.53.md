WD Cloud Manager — the Name Matches + Design/Measured/Hybrid filter cards now show in Tree (Sites) view too, not just Flat. Counts walk into each site's project children, and clicking a filter narrows the tree to only sites with matching children.

Suite `v1.9.52 → v1.9.53`. WD Cloud Manager `v4.9.0 → v4.9.1`.

## the maintainer's ask

> "Ummm so i don't know where these filters are but I don't see them?"

The v1.9.51 and v1.9.52 filter cards were gated to the Projects (Flat) view only — mirroring the existing "No Site" card's pattern. But WD defaults to the Tree (Sites) view, so the maintainer (and anyone else who doesn't switch to Flat) never saw the new cards at all. My mistake — the pattern I copied wasn't right for these filters.

## Fix

**Card visibility** — the four new cards (`dNameMatchesCard`, `dTypeDesignCard`, `dTypeMeasuredCard`, `dTypeHybridCard`) now show in both Sites and Projects views. Still hidden in Duplicates (they don't apply to that data shape).

**Count computation in Sites view** — sites view's `data.matched/cloudOnly/localOnly` is site-shaped rows, not project pairs. To keep the Name Matches + type counts meaningful in Sites view, the updater now walks `siteRow.cloud.children` (or `.local.children`) — which carries the actual project pairs — and bumps counters there. Owner filter still applies at the site level, so a site with all-others children still contributes 0 to Mine counts even if its site node is visible.

**Filter behavior in Sites view** — `pass()` for a site row was returning false for type filters (sites don't have `projectType`). New `anyChildMatches(row, predicate)` recurses into `.children.matched/cloudOnly/localOnly` and returns true if ANY child pair matches. Site row surfaces its filtered subtree. Same pattern for `rowIsNameMatch` — a site containing at least one exact-match child stays visible under the filter.
