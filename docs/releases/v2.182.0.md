# Cloud Manager: a folder and a cloud site that no longer pair can be linked by hand

Suite **2.182.0** ships **Cloud Manager 4.74.0**. The Cloud Manager page shows the Cloud Manager number, not the suite number.

## What changed

### Cloud Manager: linking an unpaired folder to its cloud site

- **A folder renamed far enough to stop pairing with its cloud site can now be linked to it by hand.** Cloud Manager pairs a folder with a site by a shared site code or similar wording, because sites carry no Ekahau id. After a larger rename the two showed on the Sites (Tree) view as **"Local folder only"** and **"Cloud site only"**, and the only action offered was **"+ Cloud site"**, which creates a second site.
- **On a "Local folder only" row**, a band beneath the row reads "No cloud site matches this folder. If you renamed it, link it to its site; otherwise create one." Its button, **"Link to a cloud site…"**, opens a picker listing only the cloud sites that have no folder, with sites sharing the folder's site code listed first. The band appears only while at least one cloud site is unpaired.
- **On a "Cloud site only" row**, the same action is in the row's **⋯** menu as **"Link to a local folder…"**. It lists only folders that have no cloud site. There is no band on these rows, because sites shared by other people are often cloud-only and a band on each would crowd the list.
- The folder row's **⋯** menu also carries **"Link to a cloud site…"**, including when no cloud site is unpaired.
- **Picking one only pairs the two. Nothing is renamed yet.** The pair then shows the **"You linked it"** badge and the band every mismatched site already has, with **Local → Cloud** (rename the cloud site to the folder's name), **Cloud → Local** (rename the folder to the site's name) and **Not a match**. **Sync everything** also offers the rename, ticked.
- Clicking the **"You linked it"** badge undoes the link.

### Cloud Manager: the project link picker on the Tree view

- On the Sites (Tree) view, **"Link to a local file…"** and **"Link to a cloud project…"** on an unpaired project now list only projects. Before this release they also listed whole cloud sites or local folders, and picking one linked a project to a site, which never paired.
- They now also include projects inside sites and folders that are themselves unpaired, which were missing before.

## Verified

- New tests drive the real row renderer, the real picker and the real pick handler against a recording server stub. From a "Local folder only" row, **"Link to a cloud site…"** lists exactly the unpaired cloud site, and picking it reaches the server as a manual match of that site's id and the folder's path. The same happens in reverse from the cloud site's menu.
- A folder with no unpaired cloud site to link to has no band, and keeps the menu item.
- On the Tree view, a project's picker lists projects and neither sites nor folders.
- The site matcher pairs a linked site and folder as a manual match whose names differ, which is what brings the rename band and the Sync everything rename with it.
- Each new test was confirmed to fail with the change it covers reverted.

## Files changed

- `web/assets/js/cloud.js`: the unpaired-folder band, the two row-menu items, the site-aware link picker, and the Tree view's project picker
- `tests/test_cloud_link_picker_for_sites.py`: new tests
- `web/assets/versions.json`, `README.md`: version numbers
