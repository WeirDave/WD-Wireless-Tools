WD Cloud Manager — empty cloud sites finally show up under the Mine filter. the maintainer's original "created a site, then couldn't find it" bug from way back.

Suite `v1.9.30 → v1.9.31`. WD Cloud Manager `v4.6.6 → v4.6.7`.

## The bug (from way back)

the maintainer created a new cloud-only site via `+ New Site`. Under owner filter `Mine`, the site was invisible. Under `All`, it appeared. Root cause: site-level ownership can only be inferred from nested projects, and an empty site has no nested projects. The old logic gave up and hid the site whenever ANY owner filter was active.

## The fix

Change the empty-site fallback in `_siteOwnedVisible` and `childOwnerHit` from "hide when any owner filter is active" to context-specific defaults:

- **Under `All`**: show (no filter).
- **Under `Mine`**: show. Ekahau's site listing only returns sites the current user has access to, and freshly-created empty sites are almost always the user's — hiding them under Mine is the wrong default.
- **Under `Others`**: hide. Empty-site bleed-through under Others was actively misleading in the past (11 empty sites appearing with zero Others content). Without a real signal, we lean toward not-Others.

## Verified in the preview

- `All`: 42 sites (all rendered, matches ledger count)
- `Mine`: 42 sites (empty sites now included — was previously hiding them)
- `Others`: 1 site (only the one with actual other-owned content)

The dashboard site counts and the visible ledger rows agree, as they must — `_siteOwnedVisible` and `childOwnerHit` were updated together.
