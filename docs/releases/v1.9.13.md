Cloud Manager: one-click **Auto-assign N matches** banner clears every unassigned cloud project the tree already paired to its site folder, in a single action.

## What changed

### The problem
v1.9.11 taught the tree to nest unassigned cloud projects under the site their local `.esx` already lives in, with a red **Not assigned** pill and a per-row 📎 **Assign to this site** button. That worked — one click per row. But a fresh workspace can surface 20+ of these at once, and clicking each one is tedious for what is, from Ekahau's point of view, a trivial metadata fix. There was no way to say "just do all of them."

### The batch action
When at least one unassigned cloud project sits in the right site folder locally, a compact banner now appears above the site tree:

> 📎 **17** unassigned cloud projects already sit in the right site folder locally — Ekahau just doesn't know yet. **[Auto-assign 17]**

Clicking the button fans each assignment out through the Operations Deck — the same pipeline bulk uploads/downloads use — so:

- Each project becomes its own deck card with a real title (`Assigning "<project>" to <site>`).
- Failures show inline with a **Retry** button; successes tick over to ✅.
- The ledger auto-refreshes as each op settles, so the red pills disappear one by one and the count reconciles as you watch.

Individual 📎 rows still work exactly as before; the banner is purely additive.

### Version bumps
- Suite `v1.9.12 → v1.9.13`
- Cloud Manager `v4.3.0 → v4.4.0`

## Files changed
- `web/assets/js/cloud.js` — new `_collectAutoAssignable(visibleSiteRows)` walks the tree and returns every `children.matched` pair whose `cloud.unassigned` is set. `renderSitesTree()` renders the `.auto-assign-banner` (only when the list is non-empty) with a count and an **Auto-assign N** button. New top-level `autoAssignAllMatched()` rebuilds the list at click time (in case of intervening re-render), toasts a summary, then enqueues one `assign_to_site` op per pair via `opEnqueue({ retryFn, run })`. Helper `_visibleSiteRowsForBatch()` reconstructs the same row set the tree used, so banner count and batch action can never drift apart.
- `web/assets/wd-tools.css` — new `.auto-assign-banner` styled in the red family (same hue as the pill it summarises, so the eye connects "count of red pills below" → "click here to fix them all") with a bold left rule; dark-mode variant included.
- `web/assets/versions.json` — suite + cloud bumps.
