# Cloud Manager downloads projects in bulk, including a colleague's, into a folder chosen up front

Suite **2.230.0**, Cloud Manager **4.89.0**. Every other tool is unchanged.

## What changed

### Cloud Manager

- **Projects under "Unassigned Projects — no site" can be ticked.** On the **Tree** view that group had no checkboxes, so the projects a colleague shares (only the owner can put a project in a site, so they always land there) could not be selected one by one, and **Select all** skipped them. Every row now has a checkbox, and they take part in **Select all**, **Select cloud side**, Download, Share and Delete like any other row.
- **New: "Download…" in the selection bar.** Tick one or more cloud projects, whoever owns them, and press **Download…**. It sits first in the bar and shows the number selected. A project that already has a local copy is left out and counted in the dialog; refreshing those stays with **Sync**.
- **The dialog says where everything goes before anything is fetched.** It shows the project folder, a **Save into** list of every local folder (a folder with no cloud site is fine) plus **A new folder…**, and a table of the full path each file will be saved as. **Download N** stays off until a folder is chosen.
- **A site's own folder is the default when every selected project has one.** **Each project's own site folder** is then preselected. Otherwise nothing is preselected, so no folder is invented.
- **"If a file of that name is already there"** offers **Keep both (the new one gets a timestamp)**, the default, **Skip it** and **Replace it (no copy is kept)**. Skipped files are counted in the result as "skipped (already there)" instead of as failures.
- **The row's own Download asks the same question first.** For a project in no site, the row's **Download** (in the row's action area) opens the dialog before fetching. It no longer saves into a new folder named after the project and then opens the site picker afterwards. For a project that has a site folder, its confirmation now shows the full path.
- **Cloud → Local no longer invents a folder per project.** A cloud-only project with no site folder used to be saved into a new folder named after itself, one per project. Its confirmation now says that the local folder is chosen next, and the same dialog opens for those.

## Verified

- The tree is rendered by the real function and every unassigned project draws a checkbox that resolves to a row the actions understand; putting `noCheckbox` back turns the test red.
- The selection bar's **Download…** is driven through the real handler against a recording server: a colleague's and an owned project download together into the chosen folder, a cancelled dialog fetches nothing, a typed new folder is the folder used, and a name such as `..` leaves the button off. Excluding other people's projects from the handler turns the tests red.
- The path shown in the dialog is asserted for both the bulk and the row routes, and the server writes the file exactly where the dialog said, with no project-named folder left behind.
- The suite passes.
