# AP Labeler draws its row and column lines in Auto, and a half-typed spacing no longer floods the plan

Suite **2.218.0**: AP Labeler **2.19.0**. Every other tool is unchanged.

## What changed

### AP Labeler

- **Auto now draws the lines.** With **Ordering** on any Rows or Columns option and **"Line Spacing"** left blank (*Auto*), dashed lines mark each place where one row ends and the next begins (or one column and the next). They are the breaks the numbering really uses, so the lines explain the order. Zigzag Rows draws them too. A plan whose APs form a single row has nothing to separate and shows none.
- **A line of text under the box says what it is doing.** Auto describes the lines; a typed number says a line is drawn every that many pixels of the plan image and that clearing the box returns to Auto.
- **A half-typed number no longer floods the plan.** The box's minimum is 10 px. A smaller value counts as Auto until the number is finished, for the numbering and the lines alike, with a note saying so. Typing `120` used to draw one line per pixel at `1` (a thousand or more on a large drawing) and rebuild them on every key.
- The dashed lines are more visible on a white plan, in both themes.

## Verified

- The real line-drawing function is run against a recording plan box: Auto draws the gap midpoints for rows, zigzag rows and columns, an order without rows draws nothing, a single row draws nothing, `1` falls back to Auto, and `120` draws one line per 120 px. Removing the Auto lines, lowering the minimum, or dropping Zigzag Rows turns the tests red.
- Checked in a Chromium browser on synthetic projects: the keys `1`, `0`, `0` all land in the box, and the hint and line count follow each one.
- The suite passes.
