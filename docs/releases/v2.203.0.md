# Capacity builds and edits its own templates, and opens on your default

Suite **2.203.0**: Capacity **1.8.0**, Prep **2.3.0**.

## What changed

### Capacity

- **Templates are built and edited in Capacity.** A template is a list of devices: a device profile, a usage profile, and how many of that device each person carries. **New template** opens an editor with one row per device; the **Device profile** and **Usage profile** pickers list the profiles Ekahau puts in the open project, and **Devices per person** takes any number. **+ Add a device** adds a row, **Remove** takes one away, and the total per person - and for the headcount on the page - updates as the rows change. **Save template** keeps it.
- **Edit, Duplicate, Delete.** Under the template list, **Edit** opens the chosen template in the same editor; renaming it there renames it rather than making a second one. Editing the shipped example saves a copy of it as a template of your own, and the example stays as it was. **Duplicate** starts a new template from the chosen one. **Delete** asks first: one press changes the button to name the template, a second press deletes it.
- **A default template, picked when a project opens.** **★ Make default** marks the chosen template as the default, shown with "★ default" in the list. From then on, opening a project picks it and works out what it would write, so **Apply and download** is ready without choosing anything. With a single template and no default, that template is picked.
- **The page is in the order of the job.** **1 — Template** shows the templates, the buttons above, and the chosen template's devices: per person and for the headcount on the page. **2 — Apply it to this project** holds the headcount, what happens to floors that already have devices, and the floor-by-floor plan. **3 — What this project already has** is the project's existing capacity, read only.
- **A template from a project that already has capacity.** **Make a template from this project…**, under **3 — What this project already has**, opens the editor filled in from the project's existing devices. Entering how many people the project was designed for works out the devices per person.

### Prep

- **Prep starts on the default capacity template.** The **Capacity template** picker in Prep opens on the template marked as default in Capacity, until a different one is picked by hand. When no capacity template exists, the step says to build one in Capacity.

## Verified

- In headless Firefox, against the real app with an invented project: a template built in the editor with two rows (2 and 1 devices per person) is saved, picked and shown at "3 devices per person"; **Make default** stores it as the default and marks it in the list; Prep then opens on it; and opening the project again picks it without a click and plans it. Editing the shipped example saves a copy beside it. **Delete** names the template on the first press and removes it on the second.
- Through the server: every device and usage profile in a project is offered with its definition; a built template carries only the profiles its rows use; a row with no number or no profile is refused with its row number; a template with no name is refused; renaming in the editor leaves one file; the shipped example is never deleted; and a built template of 1.5 devices per person plans 60 devices for 40 people.
- The full test suite passes.
