# Capacity builds and edits its own templates and opens on the default one; Settings gets a side list

Suite **2.203.0**: Capacity **1.8.0**, Prep **2.3.0**, Cloud Manager **4.78.2**, Home, Settings.

## What changed

### Capacity

- **Templates are built and edited in Capacity.** A template is a list of devices: a device profile, a usage profile, and how many of that device each person carries. **New template** opens an editor with one row per device; the **Device profile** and **Usage profile** pickers list the profiles Ekahau puts in the open project, and **Devices per person** takes any number. **+ Add a device** adds a row, **Remove** takes one away, and the total per person - and for the headcount on the page - updates as the rows change. **Save template** keeps it.
- **Edit, Duplicate, Delete.** Under the template list, **Edit** opens the chosen template in the same editor; renaming it there renames it rather than making a second one. Editing the shipped example saves a copy of it as a new template, and the example stays as it was. **Duplicate** starts a new template from the chosen one. **Delete** asks first: one press changes the button to name the template, a second press deletes it.
- **A default template, picked when a project opens.** **★ Make default** marks the chosen template as the default, shown with "★ default" in the list. From then on, opening a project picks it and works out what it would write, so **Apply and download** is ready without choosing anything. With a single template and no default, that template is picked.
- **The page is in the order of the job.** **1 — Template** shows the templates, the buttons above, and the chosen template's devices: per person and for the headcount on the page. **2 — Apply it to this project** holds the headcount, what happens to floors that already have devices, and the floor-by-floor plan. **3 — What this project already has** is the project's existing capacity, read only.
- **A template from a project that already has capacity.** **Make a template from this project…**, under **3 — What this project already has**, opens the editor filled in from the project's existing devices. Entering how many people the project was designed for works out the devices per person.

### Cloud Manager

- **The Peek button no longer runs over a folder's file counts.** The eye button beside a local folder carried the word "Peek" inside a small circle, and the word spilled out over the counts beside it. On a window wider than 1100 pixels it is now a rounded button wide enough for the word; narrower windows keep the plain eye in a circle.

### Home

- **Capacity's tile says what Capacity does now**, in the tile's own words: "Put your device mix into a project from a template".
- **On a large monitor the tiles are larger.** On a window at least 1800 pixels wide and 1000 tall, the launcher widens to about 1560 pixels, the tool pictures grow to 128 pixels, and the names and descriptions are larger. Smaller windows keep the sizes they had.

### Prep

- **A step that cannot run says so in one line.** When **Requirement areas** or **Wall types** cannot run on a project, the step in the left-hand list says "Cannot run — select this step to read why", and the full reason - which can name every profile a project is missing - appears at the top of that step's panel on the right. It used to fill the left-hand list as a column of red text.
- **The trim panel says what automatic means.** "Automatic: Prep finds the building and keeps it, with the space above around it - the dashed outline on the plan", and the margin is labelled **Space to leave around the building**, the same words PlanTrim uses.
- **Prep starts on the default capacity template.** The **Capacity template** picker in Prep opens on the template marked as default in Capacity, until a different one is picked by hand. When no capacity template exists, the step says to build one in Capacity.

### Settings

- **A side list of sections.** Settings now has a list down the left - Suite, then one entry per tool in that tool's colour. Selecting an entry shows that section alone, so the page no longer scrolls through every tool at once. On a narrow window the list sits above the sections and they fold open and closed as before.
- **The tool menus land on the tool's section.** **Settings** in a tool's menu opens Settings with that tool's section already selected.
- **Larger type** for section names, field labels, hints and the overview, and **Save** / **Cancel** stay at the bottom of the window while scrolling.
- **The Quick Walls default template is explained in plain words**: the template picked here is the one Quick Walls opens with, and the one **Auto-apply on open** puts into a project.

## Verified

- In headless Firefox, the real **Peek** button on the Cloud page: at 1600 pixels its label sits inside the button and clear of the text beside it (before the change it overran by 13 pixels); at 1000 pixels the label is hidden and the button is a 26-pixel circle.

- In headless Firefox: selecting **Quick Walls** in the Settings side list shows that section alone and marks it as the current one; **Settings** in a tool's menu opens on that tool's section.

- In headless Firefox, against the real app with an invented project: a template built in the editor with two rows (2 and 1 devices per person) is saved, picked and shown at "3 devices per person"; **Make default** stores it as the default and marks it in the list; Prep then opens on it; and opening the project again picks it without a click and plans it. Editing the shipped example saves a copy beside it. **Delete** names the template on the first press and removes it on the second.
- Through the server: every device and usage profile in a project is offered with its definition; a built template carries only the profiles its rows use; a row with no number or no profile is refused with its row number; a template with no name is refused; renaming in the editor leaves one file; the shipped example is never deleted; and a built template of 1.5 devices per person plans 60 devices for 40 people.
- The full test suite passes.
