# Quick Walls shortcuts, PlanTrim's crop box and Capacity's steps work again

Suite **2.201.1**, Quick Walls **7.70.1**, PlanTrim **2.0.1**, Capacity **1.6.1**, Scale **1.6.1**, Cloud Manager **4.78.1**.

## What changed

### Quick Walls

- **Dragging a wall type onto a keyboard shortcut slot assigns it.** Every drag event on a slot ran the drag-start handler, so a drop on an empty slot assigned nothing, the dragged card stayed greyed out, and Firefox reported "Modifications are not allowed for this document" on every movement over a slot. Each drag event now reaches its own handler, so dropping onto a free slot assigns the type, dropping onto a taken slot replaces it, and dragging one slot onto another swaps them.

- **Visual Wall Swap's controls are all reachable on a laptop screen.** At 1366 pixels wide the **Selected** panel was squeezed to fit the window and cut off **Change checked to**, **Swap** and **Delete selected**, with no scroll bar to reach them. Only the list of selected walls shrinks and scrolls now, and the sidebar scrolls when the window is shorter than all of it.
- **Visual Wall Swap's sidebar is wider and easier to read.** It opens at about a fifth of the window, between 380 and 560 pixels, instead of a fixed 320, and its text is larger throughout. Dragging the divider still sets any width, and a width set that way is kept.

### PlanTrim

- **A trimmed copy of a project opens with its plan centred and ready to draw on.** Saved keep-regions are remembered per project, and a trimmed copy carries the same project as its original, so the rectangle drawn on the full-size original was laid over the smaller sheet. It sat off the drawing, the plan was pushed to the edge of the stage and shaded as though all of it would be cut, **Reset view** did not bring it back, and no rectangle could be drawn or adjusted. A saved rectangle is now only restored onto a sheet it fits. One that does not fit is left in place for the file it was drawn on, and the floor's card in the **Floors** list says "a box saved for a larger copy of this sheet does not fit this one, so it was not used".

### Capacity

- **Applying a template is now step 1, at the top of the page.** The template list used to be in the third card, below a read-only table and the save form. **Apply a template** now comes first, **What this project asks for** second, marked "read only", and **Save as a template** third.
- **The steps on the left respond when pressed.** Each step in the **Steps** list is marked as the current one, and its card is scrolled to and outlined. Previously they only scrolled, so on a window tall enough to show every card, pressing one changed nothing. **Save as a template** says why it is not available when the open project has no requirement areas.
- **Templates look like a choice.** Each template under **Pick a template** has a round marker that fills in when it is chosen, and highlights when pointed at.

### Scale

- **The full-size logo and the title are back, below the converter.** 1.6.0 moved the converter up by shrinking the logo beside a one-line title. The converter stays at the top; the accepted formats follow it; and the logo at its full size, the **Scale & unit converter** title and the paste examples now sit beneath both.

### Cloud Manager

- **The email box in the Share dialog responds to the keyboard again.** Pressing Enter, typing a comma, leaving the box and the arrow keys in the suggestion list all reached the typing handler only, so a typed address was never turned into a recipient. Enter now adds the address, leaving the box adds it, and Up/Down move through the remembered names.

## Verified

- In headless Firefox, against the real app with an invented project open, a drag from the Bookshelf card onto an empty slot now fills that slot and leaves no card greyed. The same check on the previous code left the slot empty and the card grey.
- In headless Firefox, typing an address into the Share dialog and pressing Enter now adds it as a recipient and clears the box; on the previous code nothing was added.
- In headless Firefox, a project whose saved rectangle belongs to a sheet twice as wide now opens with the plan centred on the stage, no rectangle on it, the floor card explaining why, the saved rectangle still stored, and a rectangle drawn with the mouse landing where it was dragged. On the previous code the rectangle sat off the plan and a mouse drag drew nothing. Checked at 2519×1279 and 1366×1080.
- In headless Firefox at 1366×768 and 2519×1279, with every wall on an invented floor selected and every group expanded, **Change checked to**, **Swap**, **Delete selected** and both Quick Swap pickers can each be scrolled to and are not covered. On the previous code three of them were clipped at 1366×768.
- In headless Firefox at 2519×1279 with an invented project, the template list is the first card, pressing a step marks it current and outlines its card, and choosing a template marks it chosen and plans it. All three failed on the previous code.
- A new check reads every page and script and fails if a control sends different events to one handler, or names its handler twice. It finds both of the shapes fixed here.
- The full test suite passes.
