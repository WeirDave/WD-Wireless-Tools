Cloud Manager: the red **⮕** arrow between a cloud-only project and its empty local slot is now a real button. Click it to download the `.esx`; the moment it lands, the **Move to Site** picker pops so you can sort it straight into a site folder — pick an existing site, or `+ Create new site…` and it's created + populated in one motion.

Suite `v1.8.43 → v1.8.44`. WD Cloud Manager `v3.46 → v3.47`.

## What changed

### The gap this fills

On the **Project Files** tab, cloud-only orphans (a project sitting in Ekahau Cloud with no matching local `.esx`) rendered a red **⮕** in the gutter. It *looked* clickable — same glyph as the working ⬅ upload button one row down — but it was a decorative `<span>` with no handler. To actually pull the project down you had to tick its checkbox and use the **Sync →** toolbar button, which handles the batch case but is unintuitive for a single row.

The symmetry problem was real: the ⬅ on a local-only row is a per-row **upload** button, so the ⮕ on a cloud-only row obviously *should* be a per-row **download** button.

And there was a second gap — even after downloading, the file lands in an auto-created folder named after the project at the root of the local dir. Sorting it into the right site folder was a separate second click (**Move to site…** in the toolbar). Two operations for what feels like one gesture.

Now both are one click:

- Click the red ⮕ on a cloud-only row → confirm the download
- The `.esx` downloads to an auto-folder named after the project
- The **Move to Site** picker opens immediately with that fresh local file pre-selected
- Pick an existing site (cloud, local, or matched), or **+ Create new site…**, or Cancel to leave it where it landed

Cancel is safe — the file is already downloaded, it just stays in the auto-folder instead of moving. You can move it later with the ↪ button on the local side.

### Why not open the picker *first* and download straight into the chosen folder?

Considered it. Rejected because:
- Symmetry with the ⬅ upload arrow (which fires immediately, no picker) — the maintainer's principle is "symmetry is my friend"
- Download-first means if the user changes their mind about the destination, the file is still saved to disk (Ekahau Cloud rate-limits repeated downloads of the same project, so re-fetching costs real time)
- The Move-to-Site picker reuses existing plumbing — no new "pending download" concept in the modal state

## Verification

1. Open Cloud Manager, switch to **Project Files**
2. Filter by **Cloud Only** to isolate cloud orphans
3. Click the red **⮕** on any row
4. Confirm the "Download … from Ekahau Cloud? You'll pick a site folder next." prompt
5. `.esx` downloads (progress toast); Move-to-Site picker appears with the label `Downloaded: <name> — move into…`
6. Pick an existing site → file moves into that site's local folder
7. Or pick **+ Create new site…** → enter a name → cloud site is created and the local file is dropped into a matching folder
8. Or Cancel → file remains in its auto-created folder at the local root
