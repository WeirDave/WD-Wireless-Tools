WD Cloud Manager — jump-nav letters stay clickable while a letter filter is active. No more "stuck on one letter."

Suite `v1.9.37 → v1.9.38`. WD Cloud Manager `v4.6.12 → v4.6.13`.

## The bug the maintainer hit

Clicked S in the jump-nav — filter applied, S rows showed. Tried to click W → nothing. Every other letter chip was disabled. Only way out was clicking S again to clear the filter.

## Root cause

`_renderJumpNav` builds the "enabled letter" set by looking at which `[data-jump-letter]` elements are in the DOM. When a letter filter is active, only that letter's section renders — so DOM only contains one `[data-jump-letter]` element, so only one chip gets marked enabled.

## The fix

Cache the "enabled letter" set from the DOM only when NO letter filter is active (that's the moment we can see the full alphabet's actual content). While filter IS active, use the cached set so every letter that would have content stays clickable — click any of them to switch the filter directly.

The cache updates every time the user un-filters (or filters change), so if the underlying data changes (new site created, existing site deleted, owner filter switched), the set catches up on the next un-filtered render.

## Verified in the preview

- Initial state: 16 letters enabled (ABCDFHILMOPSTUVW — everything with content in the Mine owner filter).
- Click S → filter to S, 34 rows shown, all 16 chips still enabled.
- Click W → switches to W, 4 rows (WLHM* first), still all 16 chips enabled.
- Click W again → filter clears, 170 rows back.

## Files changed

- `web/assets/js/cloud.js` — added `_jumpNavPresentCache`; `_renderJumpNav` refreshes it only when `activeLetter` is null and uses the cached set otherwise; skips empty placeholders when building the fresh set so disabled letters don't get counted.
- `web/assets/versions.json`, `web/cloud.html` — version chip bump.
