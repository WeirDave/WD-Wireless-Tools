Small cleanup pass on the CSS token layer. No user-visible behaviour change; the tokens just make more sense now.

Suite `v1.26.0 → v1.26.1`.

## What changed

### `--card-bg` and `--card-hover` are now home-only

Before v1.26.1, both `--card-bg` and `--card-hover` were declared four times: base `:root`, light `[data-theme="light"]`, `body.tool-home`, and light-themed `body.tool-home`. On every declaration outside of Home, they simply aliased `--surface` and `--surface-hover` — pure noise.

The tokens exist because Home wants a *third* elevation layer:

- `--bg` — page background
- `--surface` — menus and header chrome
- `--card-bg` — the tool tiles + the pill theme-toggle (elevated one notch above `--surface`)

That third layer is only meaningful on Home. Everywhere else, the layer collapses into `--surface`.

**Fix.** Removed the redundant aliases from both `:root` and `[data-theme="light"]`. Kept the explicit `body.tool-home` and `[data-theme="light"] body.tool-home` overrides — those are load-bearing. Every use site was already written as `var(--card-bg, var(--surface))` / `var(--card-hover, var(--surface-hover))`, so the fallback silently kicks in outside Home. Added an explanatory comment above `body.tool-home` describing the elevation layers so future readers don't wonder why these tokens only exist for one tool.

Net: `-2` declarations at `:root`, `-2` at light `:root`. Same rendered output.

## User-visible behavior change

None. The theme-toggle pill and the Home tool tiles look identical to v1.26.0 — verified against computed styles on both `/` and `/cloud` in dark mode.

3. Toggle to light theme on either page — colors flip cleanly without any missing fallback.
