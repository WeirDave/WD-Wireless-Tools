*"Do we have a check for new version built into this? We need to build one because this runs locally."* — Dave, noticing the obvious gap.

The suite has been running locally on people's machines since v1.0, but there was no way for anyone to know when a newer release was available short of visiting the GitHub page. Fine when Dave was the only user; broken UX now that the tool ships to installers who won't hunt for updates.

**New: Help &rarr; About &amp; Updates.** Every page's help-menu now opens the same About panel — installed version, personal-site + repo links, and a **Check for updates** button that hits GitHub's Releases API and compares tags. Three states: on the latest release (green ✓), newer available (amber ⇩ with a one-click Download link), or GitHub unreachable (rose ⚠ with a fallback link to browse releases). The Home page gets a matching **About** button in the top corner.

**New: 24h auto-check + banner.** On page load the app checks upstream at most once every 24h (cached in `localStorage` — well under GitHub's 60 req/hr unauth cap). If a newer release exists, a subtle amber banner slides in above the topbar with the new version number and a Download button. Dismiss it and it stays hidden until the *next* release. Nothing checked, nothing surfaced — silent when there's nothing to say.

**Consolidated:** the per-tool About modals in Cloud Manager, Quick Walls, and Squirrel — three separate copies with slightly different framing — are gone, replaced by the shared panel that carries the suite version, GitHub repo link, `weirdave.com` link, and update check.

Suite `v1.29.14 → v1.30.0`.

## Files changed

- `web/assets/js/wd-shared.js` — new `WD.openAbout()` / `WD.closeAbout()` inject a shared About modal on first use. `WD.checkForUpdates({force})` fetches `versions.json` for the local version and `api.github.com/repos/WeirDave/WD-Wireless-Tools/releases/latest` for the upstream tag, compares via a numeric part-wise comparator, and caches the result for 24h. Manual click from the About modal bypasses cache; a per-`DOMContentLoaded` non-forced call reuses the cache and only re-hits GitHub when the cache is stale. `_maybeShowUpdateBanner` renders/removes a top-of-viewport banner if a newer release exists and the user hasn't dismissed *this specific* version.
- `web/assets/wd-tools.css` — styles for `.wd-about-*` (hero, update row, spinner, sections, credit), `.wd-update-banner`, and `.home-about-btn`. New `body.wd-has-update-banner` reserves 40px of top padding; `body.wd-has-update-banner .dz-topbar { top: 40px }` bumps the fixed dropzone topbars used by Walls and Report so they don't hide behind the banner. Combined `body.wd-has-stale-banner.wd-has-update-banner` handles both banners stacking.
