# Prep: the wall template is applied in full, the way Quick Walls applies it

Suite **2.178.1** ships **Prep 1.11.1**. The Prep page shows the Prep number, not the suite number.

## What changed

### Prep: Load the wall types

- **The chosen wall template now reaches the project in full.** Before this release, Prep added only the wall types the project did not already have and left every other type as it was. Every Ekahau project already contains Ekahau's stock wall types, so a template that recolours those types or sets their number keys had almost no effect: its own additional types were added, and the stock types kept Ekahau's colours and 1–9 key layout.
- Types the project already has are now set to the template's version: colour, number key, attenuation and the rest. This is what **Apply template** in Quick Walls has always done, so a template now gives the same result whichever tool applies it.
- Walls already drawn stay on their types. The project's own id for each type is kept, and only the type's properties change.
- A type Ekahau has since renamed (for example `Dry Wall` in an older project, `Wall, Dry` in the template) is updated in place and takes the template's name, so the project still has one of each type rather than two.
- **Where it is:** Prep, step **1 — What to do**, the **Load the wall types** option with its **Template** dropdown underneath. It is ticked by default, and the dropdown opens on your default wall template.
- **The preview says which types change.** In step **2 — What that would do**, the **Wall types** card lists the types being added and, separately, the types being "set to the template's version", with a count such as "5 to add, 12 to update". Types already identical to the template are counted and left alone, so running Prep again on a prepared project reports nothing to do.
- A type edited in Ekahau after preparing (a colour, a key or an attenuation) is set back to the template's version if Prep is run again with that template. This matches Quick Walls.

## Verified

- The shipped WD template applied to a project containing Ekahau's stock types: every type ends up exactly as the template defines it, the number keys 1–9 match the template's layout with no key held by two types, the three recoloured types (Elevator Shaft, Door Steel Fire/Exit, Window Thick) carry the template's colours, no type appears twice, and every existing type keeps its id.
- Running it a second time changes nothing.
- The Prep preview offers **Prepare** when the only work is updating existing types, and reports nothing to do when every type already matches.
- These checks fail against the previous release.
