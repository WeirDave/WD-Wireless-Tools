The home page listed five tools with no version numbers at all, and every version display anywhere in the suite (tool headers, About modals) was a hand-edited hardcoded string scattered across separate HTML files — exactly the kind of drift that just caused the v1.9.5/v1.9.6 release notes to briefly disagree with reality.

Every version is now centralized in one file: `web/assets/versions.json`. Bump a tool's version there once and it propagates everywhere that tool's version is shown — its own header, its own About modal, and its card on the home page — with no hunting down scattered spans.

Suite `v1.9.6 → v1.9.7`. No individual tool version changed in this release — this is infrastructure only.

## What changed

### One JSON file, one place to edit

`web/assets/versions.json` holds every version: `suite`, `cloud`, `walls`, `report`, `scale`, `organizer`.

### `WD.applyVersions()` in `wd-shared.js`

Runs on every page load (it's loaded suite-wide already). Finds any element tagged `data-ver="<key>"` — regardless of its class, so it works equally on a header `<span class="ver">`, an About-modal line, or a new home-page badge — and replaces its text with `"v" + versions[key]`. If the fetch fails (offline, stale cache), it silently leaves whatever fallback text is already sitting in the HTML rather than showing a blank version.

Wired into: home page card badges (new — the home page previously showed no version at all), Cloud Manager header + About modal, Quick Walls header + dropzone (all 3 screens: landing, editor, Visual Wall Swap), WD Report header + dropzone, WD Scale header, WD Squirrel header, and the hosted-site suite version chip.

### Resolves relative to how the script itself loaded

The `versions.json` fetch doesn't hardcode `/assets/versions.json` — it derives the URL from `document.currentScript.src` (captured synchronously at parse time, before it's cleared). That matters because the GitHub Pages hosted build serves the suite from a repo subpath (`username.github.io/WD-Wireless-Tools/…`), not the domain root, and some hosted pages live a directory deep (`/walls/index.html`) with `wd-shared.js` referenced via a relative `../assets/js/wd-shared.js`. Deriving the fetch URL from the script's own resolved location makes it correct in every context — local Flask app, hosted root, and hosted nested pages alike — without special-casing any of them.
