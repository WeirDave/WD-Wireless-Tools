WD Cloud Manager — Manage Sharing modal. Add/remove/re-role users on any cloud project without leaving WD. Wraps the four `/shareapi/v1/projects/users/*` endpoints captured from Ekahau's web UI.

Suite `v1.9.41 → v1.9.42`. WD Cloud Manager `v4.7.1 → v4.8.0` (minor bump — new feature).

## What's new

Every cloud project row on the ledger gets a 👥 icon in the actions bar. Click it to open a Manage Sharing modal that shows:

- **All current shares** — one row per user with their name, email, and role as a dropdown (or a fixed "Owner" pill for the project owner, since owners can't be reassigned via the API).
- **Add someone** — email input + role dropdown + Add button at the bottom.
- **Remove someone** — ✕ button on any non-owner row.
- **Change role** — pick a new role from any user's dropdown; delete + re-add happens under the hood.

Share-count badge on the 👥 icon itself so at rest you see how many people have access without opening the modal.

## Roles

Ekahau's API accepts four role values on writes:

| Value | Label in modal | What it grants |
|---|---|---|
| `OWNER` | **Owner** | Full control, can't be reassigned via API |
| `WRITE_SHARE_USER` | **Can edit & share** | Full edit access, can re-share |
| `WRITE_USER` | **Can edit** | Edit access, no re-share |
| `READ_USER` | **View only** | Read-only |

Note from the maintainer's capture: **Ekahau silently downgrades external emails (outside your org) to `READ_USER` regardless of what role you request.** That's a licensing-tier behavior on their side, not something we can override. The modal has a footnote explaining this so users don't think it's a bug.

## Endpoints wrapped

Captured from Ekahau's own web UI:

- `POST /shareapi/v1/projects/users/list` — read current shares (body: `[projectId]`, response keyed by projectId)
- `POST /shareapi/v1/projects/users` — add share (body: `{projectIds, emailAddresses, userGroupIds, role}`)
- `POST /shareapi/v1/projects/users/delete` — remove share (body: `{projectIds, email}`)

Not used yet: `PUT /shareapi/v1/projects/users/toggle-userGroup`. That endpoint operates on entire named user-groups (add/remove a saved group in bulk), not individual users. Per-user role change happens via delete+re-add since Ekahau's API doesn't expose a single "update role" endpoint.
