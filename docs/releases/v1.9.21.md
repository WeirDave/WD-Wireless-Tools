WD Cloud Manager — bulk-delete on tree-child rows now hits the correct Ekahau endpoint (project vs site) and shows accurate confirmation copy.

Suite `v1.9.20 → v1.9.21`. WD Cloud Manager `v4.5.2 → v4.5.3`.

## The bug the maintainer hit

Checked both cloud + local boxes on a tree-child pair, clicked **Delete selected**, got a red error toast that flashed away too fast to read. Root cause:

`bulkDelete → confirmDelete` was passing `currentTab` as the kind argument to `pyApi('delete_cloud', currentTab, id)`. On the tree view `currentTab === 'sites'`, but tree-child rows are PROJECTS. The backend routed the cloud project's UUID to Ekahau's site-delete endpoint (`api.delete_sites([id])`), which rejected it because that ID isn't a site.

Same wrong assumption also drove the confirmation dialog copy: it read *"1 cloud site(s) and 1 local folder(s) and all their contents"* for a project-level tree-child delete.

## The fix — each selected item carries its own context

`bulkDelete` now attaches a `context` field ('sites' or 'projects') to every item it queues for deletion, derived from the key prefix:

- `ct:` / `ct-c:` / `ct-l:` prefixes → context is `'projects'` (tree-child rows are always projects regardless of what tab we're on).
- Anything else → falls back to `currentTab`.

`confirmDelete` passes each item's context to `delete_cloud` instead of the global `currentTab`. The confirmation dialog inspects contexts per side and picks the right noun — "cloud project(s)" / ".esx file(s)" for project-level items, "cloud site(s)" / "folder(s) and all their contents" for site-level items. Mixed selections (unusual) get "cloud item(s)" / "local item(s)".

## Verified in the preview

- Checked both cell boxes on a tree-child pair → clicked Delete selected → intercepted network calls confirm:
  - `POST /api/cloud/delete_cloud` body: `{"kind":"projects","id":"…"}` ✓ (was `"kind":"sites"` before)
  - `POST /api/cloud/delete_local` body: `{"path":"…"}` ✓ (unchanged)
- Confirmation dialog copy: *"Permanently delete 1 cloud project(s) and 1 local .esx file(s). This cannot be undone."* ✓ (was "cloud site(s) and folder(s) and all their contents" before)
