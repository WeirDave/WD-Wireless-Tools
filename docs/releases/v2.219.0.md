# AP Labeler's Line Spacing box accepts any whole number, and is tested with real keys in every browser

Suite **2.219.0**: AP Labeler **2.19.1**. Every other tool is unchanged.

## What changed

### AP Labeler

- **Any whole number of 10 or more is a valid Line Spacing.** The box (under **Ordering**, for the Rows and Columns options) declared a step of 10, so a value such as 55 or 125 was flagged as invalid by the browser while AP Labeler used it. Older Firefox paints such a box red, which reads as the box refusing the number. The step is now 1, so the browser and AP Labeler agree.

## Verified

- The real page is driven with real key presses in Firefox, Chrome and Edge: `1`, `12` and `120` all land in the box with focus kept, `1` falls back to Auto, `12` draws a line every 12 px and `120` a line every 120 px, clearing the box returns to Auto, and 55 and 125 are valid to the browser. Putting the step of 10 back turns the Firefox run red.
- The same checks were run by hand in Firefox 157 and a Chromium build on synthetic projects of several sizes (up to 2,400 access points on four floors). A key press reaches the box and is painted within about 130 ms in every case.
- The suite passes.
