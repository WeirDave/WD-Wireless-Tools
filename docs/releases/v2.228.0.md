# Report starts every revision at v1, so a saved report always carries a version

Suite **2.228.0**: Report **2.72.0**. Every other tool is unchanged.

## What changed

### Report

- **A revision is always in the saved file name.** With no revision saved, the name used to end at the site, so the version segment was simply missing. Every report now starts at **v1**, for example `Report - AP Installation - <site> - v1.pdf`. The same value appears on the cover page, the page footer, the **Revision** box in a report's **Configure** step and the file-name preview, so they cannot disagree.
- **To use a different revision:** set it once under **Settings → Report → Revision**, which applies to every report, or type it into **Revision** in a report's **Configure** step for that report only. A different name can also be typed in the Save dialog.
- **To leave the revision off the name altogether:** untick **Include the revision in the saved file name** in **Settings → Report**. It is on by default.
- The **Revision** box in Settings now shows the placeholder "Blank uses v1".
- **The saved name follows the settings.** A project opened before the saved revision had loaded was named without it, and the name stayed that way. The name is now rebuilt when the settings arrive.

## Verified

- Firefox 157 dropped a synthetic project on the Report page and read back the tab title, which is the name the Save dialog offers: no revision saved gives `… - v1`, an empty one gives `… - v1`, and `Rev B` gives `… - Rev B`.
- The test fails when the default is removed.
- The full test suite passes.
