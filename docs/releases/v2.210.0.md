# Capacity shows devices per person between headcount and device count

Suite **2.210.0**: Capacity **1.11.0**. Every other tool is unchanged.

## What changed

### Capacity

- **Each floor shows the multiplier from people to devices.** Under **2 — Apply it to this project**, the line beside each floor's **"People on this floor"** box now reads, for example, *"250 people × 3 devices each = 750 devices"* instead of only *"750 devices"*. A floor left blank still shows *"building number ·"* in front, and uses the number in **"Each floor is for"**.
- **The per-floor table's total row** reads *"Per floor, 200 people × 3 devices each = 600 devices"*.
- **The message after "Apply and download"** gives the multiplier: *"… 1350 devices for 450 people at 3 devices each."*
- **Where rounding moves the total, the line says so.** Each device type is rounded on its own, so at small headcounts the total can differ from people × devices per person: 15 people on the shipped "Office, Wi-Fi 6E (example)" template show *"15 people × 3 devices each ≈ 48 devices (each device type is rounded on its own)"*.
- **The arithmetic is unchanged and was correct.** A number typed for a floor replaces the building number for that floor and is never added to it. Re-applying with **"Replace device counts"** sets the count again rather than adding to it.

## Verified

- A synthetic two-floor project with the shipped example template (3.0 devices per person), building set to 200 and one floor set to 250, writes 750 and 600 devices, read back from the written `.esx`.
- The plan built by the server is drawn by the real Capacity page in Node, and the multiplier shown on each floor matches the server's count. The new tests fail with the old floor text.
- The full test suite passes.

## Files changed

- `tools/capacity_profiles.py`: the plan and apply results carry `devicesPerPerson`
- `web/assets/js/capacity.js`: multiplier on each floor, the total row and the result message
- `tests/test_capacity_shows_the_multiplier.py` (new)
