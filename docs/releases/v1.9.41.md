WD Cloud Manager — bulk **Verify pairs** button now enables when tree-child name-match rows are checked. Per-row Verify already worked; the batch path was overlooking per-side selection keys.

Suite `v1.9.40 → v1.9.41`. WD Cloud Manager `v4.7.0 → v4.7.1`.

## The bug the maintainer hit

Per-row Verify worked (tested twice). Checked 3 name-match rows in the tree to bulk-verify them → "Verify pairs" button never enabled.

## Root cause

Tree-child rows use PER-SIDE selection keys (`ct-c:<cloudId>`, `ct-l:<localPath>`) so users can delete just one side of a pair without touching the other. Checking a name-match row's checkbox puts BOTH per-side keys into `selected` (6 entries for 3 rows, matching the "6 selected" indicator).

But `updateBulkBar`'s `verifyableCount` only counted entries with `kind: 'pair'`. Per-side keys have `kind: 'cloud'` or `kind: 'local'` — so `verifyableCount` stayed 0 and the button never enabled.

Same blind spot in `bulkVerifyNameMatches` — it would have collected zero targets.

## The fix

Both `updateBulkBar` and `bulkVerifyNameMatches` now recognize per-side keys and look up the companion `ct:<cloudId>` entry to check its `matchType`. Dedup by `cloudId` so a fully-checked row (both sides) counts as one verify, not two.

- `ct-c:<cloudId>` → look up `rowData['ct:' + cloudId]` directly.
- `ct-l:<localPath>` → scan `ct:*` entries once for a matching `localPath` (there's no direct index; O(N) over per-site child count, cheap).

Also handles the top-level `p:<id>` pair keys unchanged for the flat projects view.

## Verified in the preview

Checked 3 tree-child name-match rows → "6 selected" → `bulkVerifyBtn.disabled === false` → simulated the collection logic → 3 unique pair targets, deduped from the 6 selection entries.
