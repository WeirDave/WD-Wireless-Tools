Pure CSS health pass — the ad-hoc hex palette flagged during the v1.11.0 audit is now a proper design-system layer. Zero user-facing behavior change; everything renders identically.

Suite `v1.12.0 → v1.13.0`. All tool versions unchanged.

## What shipped

Nine soft-tint hex literals were still scattered across `wd-tools.css` after v1.11.0 called them out. Now they're first-class `:root` tokens:

```css
--blue-soft:   #6bb3e0;   /* used ~18× — light blue on dark chrome */
--purple-soft: #b48ce8;   /* used ~10× */
--teal-soft:   #7dd6c6;   /* used ~4×  */
--amber-soft:  #f0b85f;   /* used ~3×  */

--match-name:    #4a90d9;   /* semantic: name-match badge      */
--type-design:   #a855f7;   /* semantic: design project chip   */
--type-measured: #f59e0b;   /* semantic: measured project chip */
--type-hybrid:   #14b8a6;   /* semantic: hybrid project chip   */
--type-shared:   #22c55e;   /* semantic: shared with group     */
```

41 raw hex sites in `wd-tools.css` swapped to `var(--*)`. A rebrand of any of these tones now touches one line, not forty-one.

## What did NOT ship (and why)

**`--card-bg` / `--card-hover` alias fold** was on the v1.11.0 audit's "still owed" list. Killed after inspection: `body.tool-home` legitimately overrides `--card-bg` to `#18242f` — a value elevated between `--surface (#122431)` and `--surface-raised (#252830)`. The aliases serve a real elevation-layer purpose, not just aliasing. Removing them would collapse the home-page card visual distinction.

Marked in memory as intentionally resolved (not folded).

## Verified in the browser

- All 12 tokenized surfaces measured via `getComputedStyle` — every one resolves to the expected RGB value that the old hex would have produced (spot check: `.dash-card.cloud-only` border = `rgb(107, 179, 224)` = `#6bb3e0` = `--blue-soft` ✓; `.peek-type.plan` color = `rgb(180, 140, 232)` = `#b48ce8` = `--purple-soft` ✓).
- Home, Cloud, Walls, Report, Scale, Squirrel all reload with no console errors and no visual diff vs. v1.12.0.
- No self-reference cycles (caught one during editing — the `:root` declarations themselves had to keep the literal hex, since `--blue-soft: var(--blue-soft)` would recurse).

## Files changed

- `web/assets/wd-tools.css` — 41 hex → `var(--*)`, 9 new tokens in `:root`.
- `web/assets/versions.json` — suite bump.

The `/pages/hosted-*.html` stubs (marketing landing pages) still have inline `<style>` blocks with their own duplicated hex values. They don't share `wd-tools.css`, so they're out of scope for this refactor. If the stubs ever adopt the shared stylesheet, they'll pick up the tokens for free.
