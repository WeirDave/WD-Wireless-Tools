WD Wireless Tools now rejects commands submitted by unrelated browser tabs and malicious websites while the local app is running. **v1.29.10 adds a same-origin request boundary around every state-changing Flask API endpoint**, including actions that need no request arguments such as Restart, Forget Cloud Login, and Squirrel's configuration reset.

Normal WD Wireless Tools pages work exactly as before. There are no accounts, passwords, prompts, certificates, or setup steps.

Suite `v1.29.9 → v1.29.10`. Cloud Manager `v4.13.2 → v4.13.3`.

## What's new

### Local API request protection

Every state-changing request from the WD Wireless Tools frontend now carries an app-specific HTTP header. A different website cannot add that header to a request to the local server without browser permission, and the server does not grant cross-origin permission.

The Flask boundary also verifies that API requests use `localhost` or `127.0.0.1` and rejects a supplied browser `Origin` unless it exactly matches the requested local origin. The host check prevents a malicious domain pointed at the loopback address from sidestepping the browser's normal origin separation.

These checks run before API action dispatch, so rejected requests cannot reach Cloud Manager, Squirrel, Quick Walls template actions, or the restart handler.

### What is unchanged

- The server remains bound to `127.0.0.1`.
- WD Wireless Tools pages continue using the same local URLs and controls.
- Backend requests from Cloud Manager to Ekahau Cloud are unaffected; the safeguard applies only to incoming `/api/` browser requests handled by Flask.
- Read-only local version and progress polling continues normally.
