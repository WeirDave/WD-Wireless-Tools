Squirrel gets a bulk rename layer. Set rules once in Settings and every organize applies them — with full undo support so an experimental pattern is always reversible.

Suite `v1.13.0 → v1.14.0`. Squirrel `v1.11 → v1.12`.

## What's new

The Settings modal has a new **Bulk rename patterns** section with five layered transforms applied to every file's target name during organize:

1. **Strip prefix** (regex, anchored at start) — e.g. `IMG_|DSC_` clears out camera-app prefixes.
2. **Prepend site code from parent folder** — pulls the leading `[A-Za-z0-9]+` token from the containing folder name and prepends it. `photo.jpg` inside `SITE3/` becomes `SITE3_photo.jpg`.
3. **Regex find/replace** — arbitrary regex, supports backreferences.
4. **Collapse spaces/underscores** — runs of whitespace or underscores collapse to a single `_`.
5. **Lowercase filenames** — applied last so preceding regex casing survives the pipeline.

All flags default off; the pipeline is a no-op if every rule is unchecked. The file extension is always preserved through every transform.

## Verified end-to-end

Real test folder at `C:\tmp\wd_rn_test_5155` with 5 files:

```
DSC_screenshot.png, IMG_photo1.jpg, IMG_photo2 with spaces.jpg,
REPORT_summary.pdf, notes.txt
```

Config: `strip_prefix: IMG_|DSC_|REPORT_`, `add_site_code: true`, `collapse_spaces: true`, `lowercase: true`.

**Scan result** (dry-run preview):
```
DSC_screenshot.png            -> wd_screenshot.png            [images]
IMG_photo1.jpg                -> wd_photo1.jpg                [images]
IMG_photo2 with spaces.jpg    -> wd_photo2_with_spaces.jpg    [images]
notes.txt                     -> wd_notes.txt                 [reports]
REPORT_summary.pdf            -> wd_summary.pdf               [reports]
```

**Execute**: all 5 renamed correctly on disk, undo log recorded with 5 entries. **Undo**: all 5 restored to original filenames. Round-trip clean, no errors.

## Discoverability

Whenever any rename rule is active, the preview screen shows a new **`N rename rules`** summary chip (blue, hover-title lists which rules are on). That way you can't accidentally run an organize with forgotten rename rules from a previous session — you always see the status.
