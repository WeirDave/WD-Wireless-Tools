# Report and AP Labeler: floor numbers match the floor, not Ekahau's stacking position

Suite **2.189.1** ships **Report 2.66.1** and **AP Labeler 2.14.1**. Each page shows its own tool number, not the suite number.

## What changed

### Floor numbers were one lower than the floor

- **Report and AP Labeler now use the number in the floor's own name.** In a project whose floors are attached to an Ekahau building, both tools read the number Ekahau stores in `buildingFloors.json`. That number is the floor's stacking position in the building, counted from 0. It is not the storey number. As a result, a plan named "Floor 1" was headed **Floor 0** in the Report, and AP Labeler named its APs with floor token **00**. "Floor 3" came out as 2.
- **The floor's name now decides the number.** A number after a floor word ("Level 4", "Floor 2", "FL-7"), an ordinal ("3rd Floor"), or a leading number ("01 - Ground") is used as written.
- **When the name has no number, Ekahau's stacking position is used, counted from 1.** The bottom floor of a building is Floor 1, not Floor 0. If a floor is in no building and its name has no number, the Report uses the plan's name as the heading, as before. AP Labeler numbers it by its position in the list, as before.
- **Where to see it:** the "Floor N" heading on the AP Placement Map pages, the grid overview pages and the reference page heads in the Report. In AP Labeler, it is the auto-detected Floor segment of a structured name.
- **Nothing written to an `.esx` changes** except the AP names AP Labeler produces. Floor tab order in AP Labeler still follows Ekahau's stacking order.

## Verified

- New tests run the Report's real floor heading and AP Labeler's real floor numbering against the shared rule. In a building stacked 0, 1, 2 with plans named "Floor 1" to "Floor 3", both tools now produce 1 to 3. The tests also cover an unnumbered name inside a building, a name that disagrees with the stacking position, and a name that contains a building number and a floor number.
- The tests fail when the shift from 0 is removed, and they fail when the name rule is removed.
