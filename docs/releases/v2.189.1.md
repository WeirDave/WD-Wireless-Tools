# Report and AP Labeler: floor numbers are correct for current Ekahau projects

Suite **2.189.1** ships **Report 2.66.1** and **AP Labeler 2.14.1**. Each page shows its own tool number, not the suite number.

## What changed

### Floor numbers were one lower than the floor

- **Current Ekahau versions store a building's first floor as 0. Older versions stored it as 1.** Report and AP Labeler read the stored number as it stood. On a current project, a plan named "Floor 1" was headed **Floor 0** in the Report, and AP Labeler gave its APs floor token **00**. "Floor 3" came out as 2.
- **The floor's name now decides the number.** A number after a floor word ("Level 4", "Floor 2", "FL-7"), an ordinal ("3rd Floor"), or a leading number ("01 - Ground") is used as written. A floor word takes precedence over any other number in the name, so "Bldg 5 Level 2" is floor 2.
- **When the name has no number, Ekahau's number is read for the version that wrote it.** If a building has a floor stored as 0, it is a current project, and its numbers are shifted up by one. If a building's lowest floor is stored as 1 or higher, it is an older project, and its numbers are used as stored. Each building in a project is judged separately.
- If a floor is in no building and its name has no number, the Report uses the plan's name as the heading, as before. AP Labeler numbers that floor by its position in the list, as before.
- **Where to see it:** in the Report, the "Floor N" heading on the AP Placement Map pages, the grid overview pages and the reference page heads. In AP Labeler, the auto-detected Floor segment of a structured name.
- **Nothing written to an `.esx` changes** except the AP names AP Labeler produces. AP Labeler's floor tabs still follow Ekahau's floor order.
- No other tool in the suite reads Ekahau's floor number. Capacity, Prep, Quick Walls, PlanTrim, Organizer and Cloud Manager are unaffected.

## Verified

- New tests run the Report's real floor heading and AP Labeler's real floor numbering against the shared rule. In a current project stored 0, 1, 2 with plans named "Floor 1" to "Floor 3", both tools produce 1 to 3. The tests also cover these cases:
  - an older project stored 1, 2, 3, which is read as stored
  - a project with one current building and one older building
  - unnumbered floor names
  - a name that contains a building number and a floor number
- The tests fail when the shift is always applied, when it is never applied, and when the check ignores which building a floor is in. They also fail when the name rule is removed.
