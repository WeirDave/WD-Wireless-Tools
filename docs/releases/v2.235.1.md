# Area shapes close on a quick second click everywhere, and Report names a fast-dropped project with its site

Suite **2.235.1**, Report **2.73.1**, Capacity **1.12.1**, Prep **2.8.1**. Every other tool is unchanged.

## What changed

### Capacity and Prep: drawing the requirement area

- **A shape now closes on a quick second click on its last corner, in every browser.** With **Draw a shape** on (Capacity: step **2 — Draw the area**; Prep: the **Areas** stage), clicking the last corner twice within half a second, on the same spot, finishes the outline. Previously the finish depended on the browser reporting a double-click, and Safari reported two single clicks, so the shape stayed open. **Enter** and a click on the first corner still finish it, and two clicks on one spot more than half a second apart are still one corner.

### Report: the file name

- **A project dropped straight after the page opens is named with its site.** Report looks up a dropped project's folder to put the site in the title and the saved PDF name. That lookup was skipped when the file arrived before the page had finished reading its settings, which left the name as the `.esx` file name for the rest of the session. The lookup now waits for the settings (up to eight seconds) and then runs.
- **The tab title no longer flashes the file name alone while the folder is being looked up.** The saved revision arriving during the lookup used to rename the report from the file name before the site was known.

### Tests

- **A browser that disappears during a browser-test module is run again once.** `scripts/run_tests.py` re-runs a browser module a single time when every failure in it is a driver error saying the window or session went away (for example `NoSuchWindowError`). The first attempt's output is printed with a `RETRY` line, and a module that passes the second time prints that it did. A failed assertion, any other error, or a second loss of the browser is reported as a failure.

## Verified

- Capacity's and Prep's shape tools are run in the page's own event handlers with a click count of 1 on both clicks: the outline closes with three corners, two slow clicks do not close it, and a click elsewhere is a new corner. With the change removed, the first of these fails.
- Report's filename tests are run in Chrome, Edge and Firefox with the settings and the folder lookup both made slow, reproducing the file-name-only title. With the wait removed they fail in all three.
- The runner's retry is exercised on a throwaway project: a window lost once passes on the second attempt, a window lost twice fails, a wrong answer and a non-browser module are never re-run.
