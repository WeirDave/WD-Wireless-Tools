WD Report gains a **Phone Hotspots** template — one-click report of every iPhone / Android / MiFi tether picked up during an Ekahau passive survey.

## Why
On Friday's SITE-001 baseline survey the maintainer's boss asked for "a report of the phone hotspots you saw." That's a real recurring ask (security walk-arounds, compliance sweeps, "what personal Wi-Fi is bleeding into our space"), and WD Report already had the wizard, cover page, per-floor overlay, and print-to-PDF pipeline sitting there — it just didn't touch the measurement side of the .esx. Now it does.

## What's new
Third template card in the gallery, `status: ready`. Reads:
- `accessPointMeasurements.json` — one entry per unique BSSID picked up during the survey
- `measuredRadios.json` — links measurements to their parent AP records
- `surveys.json` — walking paths (used for the walk-path overlay + which floor each measurement was seen on)

Classifier is deliberately conservative — only flags SSIDs that match one of four default naming patterns:

| Category | Matches |
|---|---|
| **iPhone / iPad** | contains `iPhone` / `iPad` / `iPod`, or `'s iPhone` (curly + straight apostrophe) |
| **Android** | `AndroidAP_*`, `AndroidShare_*`, `DIRECT-xx-AndroidAP`, `Galaxy ...`, `Samsung Galaxy ...` |
| **Carrier hotspot / MiFi** | `HotspotXXXX`, `WiFi Hotspot NNNN`, contains `MiFi` / `Jetpack`, or `*-hotspot` / `*_hotspot` |
| **ATT (phone or gateway)** | `ATT[6-10 alnum]` — off by default, since AT&T uses the same pattern for phones and home gateways |

Deliberately excluded (returns `null`): car head units (Uconnect, MBUX, CarPlay, CarLink, myBuick, etc.), dashcams (ROVE, VANTRUE, 70mai), printers/scanners, business Wi-Fi, T-Mobile CellSpot femtocells, and other non-phone personal Wi-Fi.

## Report shape
- **Cover / inline header** — same shared helpers as the other reports
- **Summary strip** — total + per-category counts (iPhone / Android / Carrier)
- **Per-floor overlays** — floor plan with the surveyor walk path drawn on top in WD blue (SVG `<polyline>` over the plan image, same `aspect-ratio` trick as the antenna report's `.rep-overview-plan`)
- **Full device table** — SSID, BSSID, band (2.4 / 5 / 6 GHz), optional channel column, security, and which floors each device was seen on
- **Methodology footer** — explains how each SSID was classified so the reader can spot false positives

## Wizard change
`REPORTS.hotspot` sets `noApFilter: true`. The "APs to include" card in stage 2 (Configure) is meaningless for this report since it operates on measurements, not planned APs. `renderReportOpts()` now toggles `#apFilterCard.style.display` based on the current report's `noApFilter` flag.

## Verified in the browser
Loaded sample-project.esx (293 APs, 2 floors, 28 surveys, 3059 measurements) → gallery shows all three templates → Phone Hotspots → configure (AP filter hidden, 6 checkbox options visible) → review renders:
- Cover: ✓
- Summary: 40 total (2 iPhone, 16 Android, 22 Carrier)
- Floor plan overlays: 2 (aspect-ratio 5000/3750, both img and svg fill 902×676 at 1400px viewport)
- Walk path polylines: 28 (one per survey)
- Table rows: 40, sorted iPhone → Android → Carrier → AT&T then by SSID

## Design-only .esx handling
When a file has no `accessPointMeasurements.json` (planning file, no survey walks), the render function short-circuits with a "No survey data" empty state rather than crashing. Baseline Survey .esx files that were saved *without* scans hit this path.
