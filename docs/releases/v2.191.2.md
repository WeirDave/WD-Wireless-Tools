# Prep: CAD floor plans show on a white page, and Prep repairs plans an earlier trim left dark

Suite **2.191.2** ships **Prep 1.14.1**. The Prep page shows its own tool number, not the suite number.

## What changed

### Prep's floor plan view draws plans on white

- **Where:** Prep, card **2 — What that would do**, the floor plan view above the step cards. It appears when **Trim the canvas** is ticked.
- CAD floor plans are stored as SVG drawings, and parts of an SVG can be transparent. The view used to draw the plan straight onto its dark background, so those parts showed as black, and a line drawing looked like grey lines on black. The plan is now drawn on a white page, the same as PlanTrim's canvas since suite 2.190.0.

### Prep repairs CAD plans that an earlier trim left without their white page

- **Affected:** CAD floor plans trimmed by suite 2.91.0 through 2.189.1. Suite 2.190.0 describes the cause: the white page behind the drawing no longer covered the trimmed plan.
- Before this release, only PlanTrim could repair these plans. Prep kept a trim only when a floor was cropped. A floor that had already been trimmed had nothing left to crop, so Prep discarded the repair and the plan stayed dark.
- **Trim the canvas** in Prep now writes the repair, even when nothing on the floor is cropped. In card 2:
  - the Trim card's badge reads **"N to repair"** when repairs are the only change;
  - each affected floor is listed with the note that its white page is put back;
  - the floor strip above the plan labels the floor **Repair**.
- **Prepare and download** becomes available for a repair on its own. After the run, the summary gives the number of floor plans whose page was put back.
- As with every Prep run, a new copy is written and the original file is not changed. Nothing in the drawing itself changes: only the page behind it.

## Verified

- Prep's pipeline was run on a synthetic project holding a CAD plan in the state an earlier trim left it. The preview reports the repair, and the prepared copy contains the restored white page with the drawing byte-for-byte unchanged. A plan with nothing to crop and nothing to repair is still left alone, and no copy is written.
- The page's own preview code was run against a repair-only report. **Prepare and download** is enabled, and the card and summary name the repair. With nothing to crop or repair, the button stays disabled.
- Prep's plan-view drawing code was run against a recording canvas. White is filled over the whole plan before the plan is drawn.
- Four of the seven new tests fail against the previous version. The other three also pass on the previous version:
  - the preview's analysis already reported the repair;
  - a plan with nothing to do was already left alone;
  - with nothing to do, the button was already disabled.
