# Prep: Prepare waits until every stage has been opened, and a finished run ends with a Finish button

Suite **2.234.0**, Prep **2.8.0**. Every other tool is unchanged.

## What changed

### Prep

- **The Prepare button stays greyed out until each stage has been opened.** The three stage cards down the left of the editor ("1 · Trim the canvas", "2 · Requirement areas", "3 · Wall types") each carry a line reading "Click to check" until the stage has been opened, and "✓ Checked" afterwards. Keeping every default is still fine; the stages only have to be opened. Trim counts as opened when a project loads, because its settings are the ones on screen. A stage whose checkbox is unticked is not asked for, and a stage that cannot run for lack of a template is not asked for either. Opening another project starts again from nothing opened.
- **The footer says what is still to open.** While Prepare is locked, the footer reads "Prepare unlocks once every stage has been opened", followed by the stages still to click, above the usual "Will write: …" line. The same reason is the hover text of the greyed button. The note at the bottom of the stage rail now says the same.
- **A finished run ends on a "Done" card with a Finish button.** After a copy is written, the result above the footer is headed "✓ Done — the prepared copy is written" and names the file, what each stage did and where the copy is. **Finish** closes the project and returns to the start screen, ready for the next one. A run that finds nothing to write also offers **Finish**. If part of the pass did not run, the heading says so instead.
- **Running it again is stated on the card.** The page stays loaded after a run, and the Prepare button reads **Prepare again**. A project opened with **Open from disk…** asks before replacing the earlier copy; a dropped project downloads another copy, so the earlier one is the one to delete. The card says which applies.
- **The result area no longer scrolls its buttons out of reach.** It keeps its full height and the plan above it gives way, so **Finish** and **Show me the file** are visible on a short window. Its maximum height is 45% of the window.

## Verified

- The real `prep.js` is loaded in Node over a recording page. A project is opened, the stages are opened one at a time, and Prepare is pressed. Prepare is disabled until the last stage is opened, the footer names the stages still to open, and the button reads "Prepare again" afterwards.
- **Finish** is pulled back out of the rendered result and run. It restores the start screen, empties the result, tells the server to forget the picked path, and leaves Prepare disabled with nothing opened for the next project. This is checked for a project opened from disk and for a dropped one.
- Four deliberate breaks of the code (the gate always open, the opened-stages reset removed, the start screen not restored, the finished flag not set) each turn the new tests red.
- The three states (locked, one stage left, finished) were viewed in Chrome, Edge and Firefox.
