# Cloud Manager: Local → Cloud renames only what it should, and the two Sync buttons are coloured

Suite **2.176.0** ships **Cloud Manager 4.71.0**. The Cloud Manager page shows the Cloud Manager number, not the suite number.

## What changed

### Cloud Manager: the **Local → Cloud** button on the selection bar

The selection bar appears across the top of the list once any row is ticked. **Local → Cloud** renames each ticked cloud project to its local file's name, or sends a newer local file up. Three kinds of row are now left out of the rename, and the confirm dialog lists each one it left out, with the reason:

- **Pairs matched by guesswork.** These are rows whose middle-column badge reads **Same site code** or **Similar name**. A bulk run no longer renames their cloud project, because the two files may be different projects. To rename one, check the two names on the row, then use the row's own **Local → Cloud** in the band beneath it.
- **Projects owned by somebody else.** Ekahau lets only a project's owner rename it, so these used to fail partway through the run with `403 Forbidden`. The dialog names them.
- **Pairs whose names already agree.** A rename to the same name changed nothing except the cloud project's modified date. That made the row read "cloud newer" afterwards for no reason. These pairs are now skipped.

Pairs matched as **Same project**, **You linked it** or **Same name** on the user's own projects are renamed as before. **Cloud → Local** is unchanged: renaming a local file can be undone and affects nobody else.

If every ticked row is left out, nothing runs, and a message says which rows were skipped and why.

### Cloud Manager: the row's own **Local → Cloud**

This is the per-row rename in the band under a row whose names disagree. On a project owned by somebody else it is now greyed out, and clicking it shows `Owned by <owner>. Ekahau only lets the owner change a project.` The row's **Cloud → Local**, which renames the local file, is still available.

### Cloud Manager: the colours of the two Sync buttons

- **Cloud → Local** on the selection bar is now teal, and **Local → Cloud** is blue. Both used to be the same grey.
- Each button takes the colour of the column it writes to. The **Cloud Site** column heading above the list was already blue. The **Local Folder** heading is now teal to match.
- The labels read in screen order, source first: the cloud column is on the left and the local column on the right.
- Nothing needs to be turned on.

## Verified

- New tests drive the real Local → Cloud planner. A guessed pairing, somebody else's project and a pair whose names already agree are each left out of the cloud rename. A proven pair on the user's own project is still renamed, and the Cloud → Local direction is unaffected.
- A new test renders a real row whose names disagree. The row's Local → Cloud is live on the user's own project, and on somebody else's it is still shown, greyed out, with the owner's name.
- Each new test was confirmed to fail with its guard removed.
