# Home: jump to a tool by its first letter, a clear mark on the last tool opened, and tiles that say which tool to pick

Suite **2.245.0**. Tool versions are unchanged.

## What changed

### Home

- **A letter jumps to a tool.** Typing the first letter of a tool's name on Home focuses that tool's tile, and Enter opens it. The same letter again moves to the next tool that starts with it: **C** goes to Capacity, then Cloud Manager; **P** to PlanTrim, then Prep; **S** to Scale, then Squirrel. Typing in a field, holding Ctrl, Alt or Cmd, or having the menu open does not jump. A line under the tiles says so.
- **Tiles stay in alphabetical order.** The order is unchanged so that each tool stays where it is every day.
- **The last tool opened is easier to find.** Its tile now has an outline in the tool's colour and a **Last opened** label sitting on the tile's top edge. The label no longer adds a line to the tile after the page has loaded, so the row no longer shifts. Screen readers now read "Last opened" as part of that tile's description.
- **Tile outlines are neutral until hovered, focused, or the last tool opened.** Previously all nine carried a tinted outline, which made the last-opened tile hard to pick out and put red and green outlines on Scale and Quick Walls. The icon and the tool's name keep the tool's colour. The hover colour is now an opaque tint, so the page background no longer shows through the tile.
- **Tiles say which tool to pick when two overlap.** PlanTrim reads "Only the crop. Prep also adds areas and wall types.", Prep reads "Includes everything PlanTrim does.", and Quick Walls reads "To load a standard set at the start, use Prep." These lines previously appeared only in the hover tooltip, which touch screens do not show. Screen readers read them as part of each tile's description.
- **Nine tiles always fill their rows.** On a window about 1800px wide or more, Home uses three columns instead of four with one tile left alone on the last row. Between about 650px and 970px wide, where there are two columns, Squirrel spans the full last row. The check follows the width of the tile area rather than the window, so a visible scrollbar no longer leaves a lone tile.
- **Tool names wrap instead of being cut off** when the text size is large. On windows narrower than 348px, the tile area no longer forces the page to scroll sideways.
- **The line under the tagline is larger.** "Everything runs on this computer. Cloud Manager contacts Ekahau Cloud only when you tell it to." is now 13px instead of 12px.
- **The menu button on Home is larger** (40 by 36 pixels).
- **The footer link is named "Suite Settings"**, matching the menu entry.
- **Headings:** the tiles sit under one hidden **Tools** heading, and each tool's name is a level-3 heading under it, so heading navigation lists the tools as a group.

### Menus on every page

- **Esc returns keyboard focus to the menu button** when focus was inside the menu.
- **Arrow Up, Arrow Down, Home and End move through the menu items.**
- **Opening a menu from the keyboard moves focus to its first item.** Opening it with the mouse does not move focus.
- **Moving focus out of an open menu closes it.**

## Verified

- Home was checked in Firefox, Chrome and Edge, in the dark and light themes, at widths from 500px to 1920px: no sideways scroll, no tool name outside its tile, the Last opened label does not overlap the tool's name, and the letter jump, menu keys and Esc behave as described.
- A new browser test, `test_home_grid_browser.py`, checks at sixteen window widths in all three browsers that the last row of tiles is either full or a single tile spanning it. It fails when the window-width rule that preceded the tile-area rule is restored.
- Keyboard handling, the Last opened label and its screen-reader description, and the tile order are driven through the real functions in Node.
- The full suite passes.
