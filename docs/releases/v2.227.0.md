# The update panel lists what changed in every release newer than the installed one

Suite **2.227.0**. No tool version changes; every tool is unchanged.

## What changed

### About & Updates: the update panel

- **"What’s new since your version"** is a new list directly above the update button (**"Update now"**, **"Download and install update"** or **"Pull now"**). It appears under **Menu → About & Updates** after **"Check for updates"** finds a newer release, and shows what changed in every release newer than the installed one, newest first. Before, only the newest release's notes were available to the panel and none were shown.
- **Each release is a collapsible entry** headed by its version and one-line title. The newest entry is open; the others are closed until pressed. The list scrolls inside the panel, so the update button stays on screen in a short window.
- **The heading reads "What’s new in this update"** when exactly one release is newer, and gives the number of releases otherwise.
- **The text comes from the published release notes.** The **Files changed**, **Verified** and **Verification** sections are not shown. Release text is drawn as plain text; only bold and code formatting are applied.
- **Up to the 30 most recent releases are read.** When all 30 are newer than the installed version, the list ends with "Older changes are listed on the release page."
- **If the list cannot be fetched, the panel behaves as before.** The release notes are read from api.github.com, which some networks block; the update check itself still goes through git first, and a failed or slow notes lookup leaves the list out without delaying or failing the check. The lookup waits at most 8 seconds and is skipped when the notes lookup has just failed.

### Updates: server

- **`/api/update/status` reports `latest.changes`**: a list of `{version, title, notes, url}` entries, newest first, with `latest.changesTruncated` when a full page of newer releases came back. Each entry's notes are limited to 3000 characters, and the whole list to 24000; past that, older releases keep their version and title and lose their notes. `latest.notes` is unchanged.
- **The list is cached for 60 seconds** and re-checked with a conditional request, and it shares GitHub's rate-limit back-off with the existing release lookup.

### Update panel code

- **The list is drawn by `web/assets/js/release-changelog.js`**, with its stylesheet `release-changelog.css` beside it, loaded the first time the panel has releases to show.

## Verified

- The release list is checked against the same fixtures by the server's parser and by the shipped JavaScript parser run under Node: which releases, their order, titles, notes and links match, including notes that end at a **Verified** or **Verification** heading, a title with Windows line endings, and a heading in the middle of the notes.
- Drafts, pre-releases, tags that are not versions and releases at or below the installed version are left out; a full page of newer releases is flagged as possibly incomplete.
- A blocked or rate-limited API, an HTTP error, a malformed answer and an unexpected exception each leave the status check whole, with the reason in `changesError`; the list is not requested a second time when the notes lookup has just failed, or when nothing newer exists.
- The panel was opened at 1366 x 650 for a git install and a development checkout: the update button stays on screen, the newest release is open, and markup inside a release is shown as text.
- The suite passes.
