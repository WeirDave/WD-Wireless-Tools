# One current project shared by every tool, a read-only Project check, and a launcher that no longer stops work in progress

Suite **2.249.0**. Tool versions: Quick Walls **7.81.0**, Report **2.78.0**, PlanTrim **2.4.0**, AP Labeler **2.23.0**, Capacity **1.15.0**, Prep **2.11.0**. The other tools are unchanged.

## What changed

### The current project (Home, Quick Walls, Prep, PlanTrim, AP Labeler, Capacity, Report)

- **A chip in the page header names the project being worked on.** It sits to the left of the update pill and the theme button, and reads **No project** until one is chosen. Pressing it opens a menu: **Choose project…**, **Open in this tool**, **Check project**, **Show folder**, **Stop using**, and a **Recent** list of the last twelve projects with **Clear recent projects**. **Open in this tool** appears only on a page that can open a project.
- **Open in this tool** opens the current project in the tool on screen. Quick Walls and Prep read the file where it lies, as **Open from disk…** does; PlanTrim, AP Labeler and Capacity receive it as if it had been dropped in; Report opens it through the same route as its own file picker.
- **The file picker opens in the folder of the current project.** A project opened with **Open from disk…** in Quick Walls or Prep, or chosen in Report's picker, becomes the current one. A prepared copy written by Prep beside the original becomes the current project, so the next tool opens the prepared file.
- **A project dragged in from a folder cannot become current.** The browser does not say where a dropped file came from. The menu says so, and **Choose project…** is the way to make it current.
- **The list lives in `current_project.json` in the user folder** (`~/.wd_wireless_tools`), as file paths and times only. A listed project that has been moved or deleted is shown struck through and cannot be chosen.

### Project check (every page with the chip; also Prep)

- **A read-only check lists what is wrong with a project, worst first.** Open it from **Check project** in the chip's menu, or from **Project check** at the top of Prep once a project is open. Items marked **Fix**: access points sharing a name, directional antennas with no azimuth, and survey data missing from the file. Items marked **Check**: access points with no real name, on no floor plan, with no model or with no mount height, and wall types whose name states a height the file does not carry.
- **Each item gives the count, example names, why it matters and where it is fixed.** A link opens the tool that does it (**Fix in AP Labeler**, **Fix in Quick Walls**, **Fix in Cloud Manager**); items that are only fixed in Ekahau say so. A project with nothing to report says so.
- **The check reads the file and changes nothing.** Channel plans, transmit power and co-channel distance are design choices and stay in Report's design review.

### Launcher (Windows and macOS)

- **Starting the launcher while the app is running opens a browser tab on the running copy** and leaves it alone. Previously every start stopped the running copy, along with an upload, trim or sync in progress.
- **A running copy on older code than is installed is replaced, unless it is in the middle of work.** The launcher then says so and stops; start it again when the work has finished. `WD_FORCE_RESTART=1` replaces a copy that is stuck.
- **A restart from the app is unchanged.** The running copy marks itself as restarting before the new launcher starts, so the new launcher never attaches to the copy that is about to exit.

## Verified

- The full suite passes, including new tests that run the real server on a socket and ask it, with the launcher's own probe, whether it is busy while a request is open, and that a restart is reported as one.
- New browser tests press the chip, its menu, **Open in this tool**, **Check project** and Prep's **Project check** with real clicks in Chrome, Edge and Firefox. Reverting the menu to the shared menu class makes the first of them fail in all three.
- The Project check was run over a deliberately imperfect synthetic project and over a clean one, and its name rule is compared with Report's own over the same list of names.
