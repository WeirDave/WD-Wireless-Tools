WD Wireless Tools now tests every change automatically on **Windows and macOS**, across both the minimum supported Python 3.10 and current Python 3.14. The same four-platform matrix is also a required release gate: GitHub will not build or publish a release ZIP unless every test job passes first.

Suite `v1.29.8 → v1.29.9`. Tool versions are unchanged.

## What's new

### Automatic cross-platform tests

Every push to `main` and every pull request targeting `main` now runs the complete safety suite in four independent environments:

- Windows with Python 3.10
- Windows with Python 3.14
- macOS with Python 3.10
- macOS with Python 3.14

Each job installs the same `requirements.txt` shipped to users, runs all 34 tests, compiles the Python sources, and checks the installed dependency set for conflicts. JavaScript syntax remains part of the existing test suite and runs wherever Node.js is available on the hosted runner.

The first matrix run immediately exposed a Python-version difference in Base64 parsing: Python 3.10 tolerated trailing characters after an otherwise valid encrypted session token, while Python 3.14 rejected them. Cloud Manager now validates the token's canonical encoding before decryption, so a byte-modified cache is rejected consistently on every supported runtime.

### Releases are gated by tests

The test workflow is reusable by other workflows. When a `v*` tag triggers a release, `release.yml` calls the full Windows/macOS matrix first. The ZIP-building and GitHub Release job has a hard dependency on that result and starts only after all four jobs succeed.

This prevents a release from being published merely because a tag exists while its code fails on one of the supported operating systems.

### Current GitHub Actions runtimes

The new workflow uses the Node 24-based `actions/checkout@v6` and `actions/setup-python@v6`. The release workflow's checkout step was updated to `v6` as part of the same CI path.
