Squirrel now flags images and floor plans that aren't referenced by any `.esx` in the same site — potentially safe-to-remove cruft.

Suite `v1.16.0 → v1.17.0`. Squirrel `v1.15`.

## What's new

For any site folder containing at least one `.esx`, Squirrel now:

1. Opens each `.esx` and reads its `images.json`, extracting every `imageName` field.
2. Walks the site's `images/` and `floorplans/` subfolders.
3. Flags any file whose name (stem, case-insensitive) doesn't appear in any `.esx`'s `imageName` list.

The preview surfaces this in two places:

- **Summary chip**: a new grey `N unreferenced` chip appears in the summary bar, with a tooltip explaining the check.
- **Per-site block**: below the "Staying in root" table, each site with unreferenced files gets a dashed-border block listing every unreferenced file with its subfolder and size.

**Advisory only** — nothing gets moved, nothing gets deleted. This is a "here's what a rebrand might safely purge" hint, not an action. The label explicitly says "Advisory only" so no one confuses it with an orphan-cleanup command.

## Why it's specifically about referenced-by-.esx

Every previously proposed "orphan detection" heuristic had false positives. But Ekahau's `imageName` is a strong signal: it's the exact filename the user chose during import. If a matching file sits on disk, it's almost certainly the source. If a file doesn't match anything in `imageName`, either it was never imported into any project, or its name has drifted (rename, copy, etc.) — both cases are worth flagging.

## Verified end-to-end

Real test folder: 1 site with an `.esx` referencing `floor1.png` and `Building A.pdf` via `images.json`. Disk had:

- `images/floor1.png` — should be referenced ✓
- `images/screenshot.png` — should be unreferenced
- `floorplans/Building A.pdf` — should be referenced ✓
- `floorplans/unused_plan.pdf` — should be unreferenced

Scan result: `unreferenced_count: 2`, with exactly `screenshot.png` (in `images`) and `unused_plan.pdf` (in `floorplans`) flagged. Floor 1 and Building A correctly detected as referenced. Frontend rendered a grey summary chip + a dashed block under SITE1's staying table with both flagged files.
