## Role labels — match Ekahau's UI

Previously WD used a mix of terms ("Can edit", "Can edit & share", "Editor", "Editor + Share" depending on which surface). Ekahau's own web UI uses "View only", "Edit rights", "Full access". Now WD does too, single source of truth in `SHARE_ROLE_LABEL`, applied at every render site:

- Share modal per-user role dropdown (`_shareRender`)
- Share modal group-toggle role dropdown (`_shareRender`)
- "Share with someone" form's role dropdown (`cloud.html`)
- Owner pill still reads "Owner" (no Ekahau alternative to align to)
- Toast messages (`"X is now Edit rights"`) inherit the map automatically

| API role         | Old WD label       | New WD label   |
|------------------|--------------------|----------------|
| OWNER            | Owner              | Owner          |
| WRITE_SHARE_USER | Can edit & share / Editor + Share | Full access |
| WRITE_USER       | Can edit / Editor  | Edit rights    |
| READ_USER        | View only          | View only      |

## Hide "Not assigned" badge for non-owners

The red "Not assigned" pill signals a cloud project has no Ekahau site parent — a state only the OWNER can fix (Ekahau's site-assignment API rejects non-owners). Showing it on projects someone else owns just added noise the viewer couldn't act on.

The pill is now gated by `owner === me`. Same test as the existing "iAmOwner" check in the share modal's Danger Zone. Rendered where:

- Idle behavior for owned projects: unchanged (pill still shows on your own unassigned projects).
- Idle behavior for shared/other-owned projects: pill hidden.

Confirmed against sample-project.esx (owned by team-user-a now, still visible to the maintainer via share): previously showed `Design · Not assigned · (team-user-a@…) · +2 shared`; now shows `Design · (team-user-a@…) · +2 shared`.
