# AP Labeler: every floor plan displays, including vector plans

Suite **2.188.1** ships **AP Labeler 2.13.4**. The AP Labeler page shows the AP Labeler number, not the suite number.

## What changed

### AP Labeler: floors that showed a black canvas

- **Floor plans that came up as an empty black canvas now display.** This affected plans whose format recorded in the project did not match the image itself, most often a vector (SVG) plan recorded as PNG or with no format recorded at all. Other floors in the same project displayed normally, so one project could show some floors and not others. PlanTrim had the same fault and was fixed earlier. Both tools now use the same check.
- **The plan is now shown on a white background.** A plan with a transparent background, which is common for vector plans, used to show black lines on the dark canvas. It now shows on white, the way Ekahau shows it.
- Nothing changes in the `.esx` that is downloaded. This affects only how the plan is displayed while labelling.

## Verified

- A synthetic two-floor project was loaded into the real page in Chromium. One floor was an SVG plan with a transparent background recorded as PNG, and the other was a PNG plan. Before the change, the SVG floor showed only a black canvas with "Could not decode floor-plan image." After the change, both floors display on white, with the AP marker on the plan.
- New tests run AP Labeler's real image loader against the shared format check. An SVG recorded as PNG, an SVG with no format recorded, and a PNG recorded as SVG are each given the type that matches the file. Three of the four tests fail with the old loader restored.
- PlanTrim's existing format tests pass against the shared check.
- Firefox and Edge were not available where this was built and have not been checked.
