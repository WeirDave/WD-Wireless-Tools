WD Cloud Manager — checkboxes on tree-child rows, and bulk-delete now handles matched pairs. Follow-up to v1.9.18's matching rewrite: found while dogfooding the new UI.

Suite `v1.9.18 → v1.9.19`. WD Cloud Manager `v4.5.0 → v4.5.1`.

## The gap

the maintainer hit the SITE-001 E case: two `.esx` files in the same site folder, both matched to cloud counterparts, effectively the same project stored twice. Rename fixed the name mismatch; now he needed to delete the duplicate pair entirely — both the cloud project and its local `.esx`.

Problem: **tree-child rows (individual projects inside a site) had no checkboxes**. `renderTreeChildren` was hard-coding `noCheckbox: true`, so the only bulk-selectable rows were the top-level sites. Users had to delete each side by hand via the row's per-item action icons — one-at-a-time, one side at a time.

## The fix — three coordinated changes

**1. Enable checkboxes on tree-child rows.** Dropped `noCheckbox = true` in `renderTreeChildren`. Child rows use the `ct:` key prefix (already in place), so they can't collide with top-level `p:`/`c:`/`l:` keys in the selection Set.

**2. Index tree-child rows into `rowData`.** `indexRowData` used to only walk `data.matched` / `cloudOnly` / `localOnly` at the top level. Now it also recurses into each site's `children.matched / cloudOnly / localOnly` and registers each child under its `ct:` key. Without this, a checked child had a key in the selection Set but no matching entry in `rowData`, so `bulkDelete` silently filtered it out.

**3. Expand matched pairs in `bulkDelete`.** When a paired tree-child row is checked, deleting it means deleting *both* the cloud project *and* its local `.esx` — the "duplicate pair" case the maintainer hit. `bulkDelete` now expands each selected pair into two deletion items (one `cloud`, one `local`) with a clear confirmation: *"Delete 1 matched pair (both cloud and local sides)."*

Guardrail: pair-expansion only applies on the projects tab OR to tree-child rows (any key starting with `ct:`). Top-level `p:` pairs on the Sites tab are still excluded from bulk delete — nuking a whole site + its folder + all contents is a bigger action than any user wants from a check-and-delete, and the per-row 🗑 icon is still there for the one-at-a-time case.

## Files changed

- `web/assets/js/cloud.js`
  - `renderTreeChildren` no longer sets `noCheckbox` on child rows.
  - `indexRowData` recurses into every site's `children` and indexes matched/cloudOnly/localOnly children under their `ct:` keys.
  - `bulkDelete` expands `kind: 'pair'` entries into their two sides when the key is `ct:` (or the tab is projects), summarizes the mixed count in the confirmation dialog.
  - `updateBulkBar` counts tree-child pairs toward `deletableCount` so the toolbar button enables when only pairs are picked.
- `web/assets/versions.json`, `web/cloud.html` — version chip bump.

## Verified in the preview

- Every tree-child row now renders a checkbox in both cloud and local cells.
- Checking a single tree-child pair enables the **Delete selected** button (previously stayed disabled).
- Confirmation copy correctly says *"1 matched pair (both cloud and local sides)"* when a paired child is checked; falls back to the previous cloud/local-only phrasing for orphan children.
- Top-level Site-tab site rows still can't be bulk-deleted (as before).
