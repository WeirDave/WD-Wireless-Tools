# Quick Walls attenuation areas can be edited, deleted and kept as presets of your own

Suite **2.224.0**: Quick Walls **7.78.0**. Every other tool is unchanged.

## What changed

### Quick Walls: the Attenuation Areas tab

- **"Edit"** on an area in the **"In this project"** list opens the same dialog as **"+ Add Attenuation Area"**, filled in feet and dB per foot. Name, colour, lower and upper edge and the loss at 2.4 / 5 / 6 GHz can be changed; the type keeps its id, so areas already drawn with it keep working. Opening an area and pressing **"Save"** without changing anything changes nothing and says so. A name another area already uses is refused in the dialog.
- **"Delete"** removes an area type after one question that names it. It is greyed, with the reason on the button, when drawn areas use the type (the list shows **"drawn: N"** on every area), and also when the drawn areas cannot be read. A type is never removed from under an area that is drawn with it.
- **"Keep as preset"** keeps an area as a preset of your own. It then appears under **"Presets"**, marked *kept by you*, in every project. A kept preset has **"Remove"**; the two that ship with the app, marked *built in*, do not. Keeping a preset does not change the open project.
- **Presets have an "Add" button each**, and the button that adds them all is now **"+ Add All Presets"** (it was "+ Add Tree Canopy & Shrubbery"). A preset whose upper edge is empty shows *ceiling*.
- Kept presets are stored in `attenuation-area-presets.json` in your user folder, never in a wall template or the install folder, so an update does not touch them. The settings export carries the file.

### Tests

- **The Capacity template editor browser test waits for what it expects** instead of sleeping for a fixed fraction of a second. It had failed in a different step on two different runs, with a page that was simply slower than the pause.

## Verified

- The edit, delete, keep and remove controls are pulled out of the markup the real render produced and run: Edit opens filled in feet, saves with the id kept and the untouched values exactly as Ekahau stored them; Delete is refused for a type that drawn areas use, both from the greyed button and when the handler is called directly; Keep sends the area in feet and dB per foot; Remove is offered only on kept presets. Each rule turns its test red when removed.
- The preset store is checked on its own: replacing by name, the built-in protection, a damaged file costing only the bad entry, and an atomic write that leaves no temporary file.
- The suite passes.
