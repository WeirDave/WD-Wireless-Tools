# Cloud Manager's Live refresh now notices a project that was saved again

Suite **2.216.0**: Cloud Manager **4.86.0**. Every other tool is unchanged.

## What changed

### Cloud Manager

- **A project saved again is detected.** With **"Live"** on (the toolbar button, on by default), the check that runs when the countdown reaches zero compared only which projects exist, not what they look like. A project saved again from Ekahau keeps its cloud id and gains a newer date and a new size, so it was judged unchanged: the countdown restarted, no message appeared, and the list stayed as it was until the page was reloaded. The check now includes each project's name, modified date, size and owner on both the cloud and local side, so the bar **"Ekahau Cloud has changed since this list was drawn."** appears with its **"Show the changes"** button, as it does for a project added or removed.
- **A held poll says so.** While a project is ticked, a dialog is open or text is in the search box, Live skips its check so the list does not move under the selection. The button used to keep counting down as though it were running. It now reads **"Live · paused"** until the selection is cleared or the dialog is closed.
- The list is still never redrawn without being asked: a detected change waits behind **"Show the changes"**.

## Verified

- The real `cloud.js` is run in Node against invented projects: a cloud-only project with a newer date and size, a matched pair whose staleness is unchanged but whose cloud date moved, and a cloud rename each raise the bar; two identical polls raise nothing. Reverting the fix turns all of the changed-data cases red.
- The Live button text is checked while running, while a selection holds it, and after the selection is cleared.
- The full test suite passes.
