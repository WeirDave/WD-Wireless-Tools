# Report copies the file name to the clipboard when Print / Save PDF is pressed

Suite **2.232.0**, Report **2.73.0**. Every other tool is unchanged.

## What changed

### Report

- **The file name is copied when Print / Save PDF is pressed.** "Microsoft Print to PDF" and "Adobe PDF" are Windows printers, and their Save dialog leaves the **File name** box empty whatever the page is called. The report name (for example `Report - AP Installation - <site> - v1`) is now on the clipboard by the time that dialog opens, so **Ctrl+V** in the **File name** box fills it. A short message confirms the copy. If the browser refuses clipboard access, printing carries on unchanged.
- **The note under the Print step says so.** It still names the destinations that fill the name in by themselves (**Save to PDF** in Firefox, **Save as PDF** in Chrome and Edge) and now tells the reader to press Ctrl+V for the printers.
- **The name is unchanged.** The page title, which Firefox's **Save to PDF** and Chrome's and Edge's **Save as PDF** use, is the same string that is copied.

## Verified

- The real print handler is run against a recording clipboard: the name is copied after the title is settled and before the print dialog opens, a refused or missing clipboard never stops the print, and removing the copy turns the tests red.
- In Chrome, Edge and Firefox the page title at the moment the print dialog is requested equals the report name.
- The suite passes.
