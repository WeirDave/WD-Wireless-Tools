# Undo steps back through every Organize and Group; updates keep edited templates; saves no longer overwrite each other

Suite **2.248.0**. Tool versions: Cloud Manager **4.96.0**, Squirrel **1.32.0**, Quick Walls **7.80.2**, Report **2.77.2**, PlanTrim **2.3.3**, Prep **2.10.2**. The other tools are unchanged.

## What changed

### Squirrel (Organizer)

- **Undo now steps back through every Organize and Group, newest first.** Running Group and then Organize on the same folder used to leave only the Organize undoable, because each run replaced the one before it in the undo record. The record now holds the last 20 runs. **↶ Undo Last Organize** takes back the newest one, and the button stays available while earlier runs remain; the number on it is the file count of the run it will undo. An undo record written by an earlier version is read as a single run.

### Updating (Menu → About → Update)

- **A ZIP update keeps templates edited in place or added to the install's `templates` folder.** The update replaces that folder; an edited shipped template, or one saved into it by hand, was deleted with it. Each is now copied to the personal templates folder first, where it is read in preference to a shipped one, and the update result lists the files kept. A copy already in the personal folder is never replaced, and the update stops without installing if a copy cannot be made.
- **A ZIP install records the shipped templates** (`shipped_files.json` in the settings folder) so the next update can tell an edit from a change in the release. Until that record exists, only a template the new release does not contain is kept.
- **`install.sh` and `install.ps1` carry over wall templates** that exist in the install's `templates` folder but not in the new release.

### Saving

- **Two changes made at the same moment no longer cost each other.** Settings, remembered share addresses, wall-template visibility, PlanTrim crop boxes, Report grids, area presets, rename profiles, and Cloud Manager's not-a-match, manual-match and External marks each read the file, change it and write it back. Two requests doing that at once lost the first change. Each store now completes one change before the next begins.

### Cloud Manager

- **Share → Recent now has a "Forget all" button** that clears every remembered address after a confirmation. Projects already shared stay shared. Single addresses can still be forgotten with the × beside each.

### Quick Walls, Prep and Cloud Manager (large project files)

- **Wall height repair and Quick Walls' injection read only `wallTypes.json`.** The rest of the project, survey samples included, passes from the original file to the new one a member at a time and is unchanged byte for byte.
- **Comparing a local file with its cloud copy reads one member at a time** instead of holding every decompressed member of both files.

### Diagnostics

- **A missing-key fault inside a tool is written to the log.** It was answered to the page as a bad request and left no record. A request that simply omits a field is still answered the same way and is not logged.

### Removed

- Four server routes that no page calls: Rename's folder match listing, Settings' destination listing, Cloud Manager's External-override listing and the wall-template reset.
- Unused constants in the updater and two unused launcher fields in its configuration.

## Verified

- The full suite passes, including new tests that run the real update over an install with an edited template, the Organizer's Organize, Group and Undo over real files, and six threads changing each store at once.
- Each new test was checked by undoing its fix and confirming it fails.
