WD Cloud Manager — tree-child checkboxes now select each side independently, and the first-visit hint banner is retired.

Suite `v1.9.19 → v1.9.20`. WD Cloud Manager `v4.5.1 → v4.5.2`.

## What the maintainer asked for

Two things while dogfooding v1.9.19's tree-child checkboxes:

1. **"What if I only want to delete one of the files and keep the other one on either side? Every time I go to try to uncheck the other one it just unchecks the whole row."** — v1.9.19 shipped tree-child checkboxes but both cells shared one row-level key, so clicking either box toggled the whole row. That's the wrong mental model for the "duplicate `.esx`" case where you want to delete just the local copy or just the cloud copy.

2. **"That little blurb up there about matching being smarter — we don't need to have that. No one but me and a couple of the guys at work have utilized my file."** — The first-visit hint banner under the toolbar is unnecessary for the current audience.

## The fix — per-side checkboxes on tree-child pair rows

Tree-child rows that pair a cloud project with a local `.esx` now get two independent checkboxes — one on each cell — each with its own selection key:

- Cloud side → `ct-c:<cloud-id>`
- Local side → `ct-l:<local-path>`

`indexRowData` registers both keys alongside the existing row-level `ct:` entry (kept for sync buttons and other row-level actions). Selecting one side leaves the other untouched:

- Check only the cloud → **Delete selected** removes the cloud project, local `.esx` stays.
- Check only the local → local `.esx` gets deleted, cloud stays.
- Check both → both sides go (same effect as v1.9.19's whole-pair delete, now via user intent instead of automatic pair-expansion).

Orphan tree-child rows and top-level Sites-tab rows keep their existing single-row-key behavior — only matched pair rows on the tree needed the split.

## Hint banner retired

`_mhInit` now no-ops (and proactively removes the banner element if a previous session's DOM still has it). The ⓘ **How matching works** chip in the toolbar remains — clicking it opens the same explanation panel. If we ever want the banner back for a wider audience release, restoring the prior implementation from git is one revert away.

## Files changed

- `web/assets/js/cloud.js`
  - `cloudCell` / `localCell` use per-side keys when `r.cloudCheckKey` / `r.localCheckKey` are set.
  - `renderTreeChildren` sets those keys on matched pair rows only (`ct-c:` / `ct-l:` prefixes).
  - `indexRowData` registers both per-side keys AND the row-level `ct:` key for matched pair children.
  - `_mhInit` retires the auto-inserted hint banner (proactively removes any stale one).
- `web/assets/versions.json`, `web/cloud.html` — version chip bump.

## Verified in the preview

- Two independent checkboxes visible on every matched tree-child pair.
- Checking cloud side → cloud box only checked, local unchecked, "1 selected", Delete Selected enabled.
- Checking both sides → "2 selected", Delete Selected enabled.
- Toolbar hint banner not rendered on load.
