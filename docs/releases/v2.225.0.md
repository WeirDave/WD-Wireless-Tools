# Cloud Manager finds a browser sign-in as soon as it exists, and says what it found when it cannot

Suite **2.225.0**: Cloud Manager **4.87.0**. Every other tool is unchanged.

## What changed

### Cloud Manager: signing in through the browser

- **A sign-in made in Firefox is found straight away.** Firefox holds a cookie it has just written in a side file until its next checkpoint; Cloud Manager read only the main file, so it saw the previous, expired session and Ekahau refused it, sometimes for minutes after a successful login. The side file is now read too.
- **The waiting screen checks one at a time.** Each check used to start every three seconds whether or not the last had finished, and every extra click on **"Log in to Ekahau Cloud"** added another that never stopped. A check now starts two seconds after the previous one ends, and there is only ever one.
- **The waiting screen shows what it found.** After about twelve seconds of not finding a sign-in it lists, per browser, why: no Ekahau sign-in found, the cookie file locked while the browser is open, Ekahau not accepting the sign-in it was given, or Ekahau Cloud not reachable yet (a machine that has just woken from sleep). A saved sign-in that failed is named first. Browser names and plain reasons only; no paths or cookie values.
- **New "Check again now" button** on the waiting screen looks immediately, and returning to the Cloud Manager tab does the same.
- **New "Back" button** on the waiting screen stops looking and returns to **"Log in to Ekahau Cloud"**.
- **The wait ends after ten minutes** with a message, instead of polling indefinitely.
- The same reasons are written to the application log, once per change, so a repeat can be diagnosed from **About → Diagnostics**.

## Verified

- Firefox: a real SQLite database in WAL mode holds the expired token in its main file and the fresh one only in its log; read through the real `browser_cookie3`, the fresh session is the one found and saved. The test turns red when the log is not read.
- The waiting-screen functions are run from `cloud.js` under Node with virtual time: one check in flight at a time (including from the tab-focus and button paths), no second poll after repeated clicks, a check that finishes after **"Back"** does not reschedule, a failing status call is retried, the reason line appears only after the delay, and the ten-minute stop. Removing the in-flight guard turns its test red.
- The suite passes.
