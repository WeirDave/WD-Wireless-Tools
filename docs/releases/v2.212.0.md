# Cloud Manager pairs the right file when two share a project, and shows what a comparison found

Suite **2.212.0**: Cloud Manager **4.83.0**. Every other tool is unchanged.

## What changed

### Cloud Manager

- **Two local files from the same Ekahau project pair correctly.** Saving a project under a new name in Ekahau keeps its internal project ID, so a site folder can hold, for example, "Predictive Design" and "Predictive Design - with DWG" as the same project. The cloud project used to pair with whichever file came first alphabetically. The file actually saved to the cloud was then listed as local-only, the other file appeared to be missing, and **"Check what differs"** and **"Download over local"** acted on the wrong file. The cloud project now pairs with the local file of the same name, or, failing that, with the one whose date is closest to the cloud copy's. The other file gets its own row.
- **"What differs" lists every difference a comparison finds.** After **"Check what differs"** reports real changes, the row's detail line ends with a **"What differs (N)"** toggle. Opening it gives one line per part of the project, for example *"access points: 3 changed - fields: location"*. Previously the row gave only a one-line summary such as *"Real changes: access points, antenna types, application profiles, areas and 13 more"*, with no way to see the rest.
- **The fields that changed are named.** Each line lists up to four field names that differ on the changed items, most common first. Values are never shown.
- **Items that only got a new ID are counted.** Items are matched by ID, so a save that renumbers them used to read as every item removed and added again. Such a line now adds, for example, *"(4 of those are the same item under a new ID)"*.
- **Shown after a check in the current session.** A comparison remembered from an earlier session keeps only its summary, and **"Re-check"** brings the list back.

## Verified

- Two synthetic files carrying one project ID, read through the real folder scan, pair with the cloud project of the matching name in both directions. When the cloud project's name matches neither, the file nearest its date is paired. The tests fail against the previous matcher.
- Synthetic projects in which one access point moved, one was renamed, and every item was renumbered report the field that moved (`location`), name the renamed field without its value, and count the renumbered items. A replaced item with different content is not counted as renumbered.
- The real row renderer, run in Node, draws the list beneath the summary. The tests fail when the list is removed from the row or when renumbered items stop being counted.
- The full test suite passes.
