*"Can we make Squirrel also just add the sub folders? So that if the parent directory exists but the 3 subfolders are not there yet it will create those."* — Dave.

Before this: the **+ Create Folder** button in Squirrel refused with *"Folder 'X' already exists"* the moment the site folder was present, even if `images/`, `floorplans/`, and `reports/` weren't in it yet. Common on sites that were made outside Squirrel (dragged in from OneDrive, downloaded from Ekahau Cloud, or hand-created) — you had to bounce out to Explorer to mkdir the three folders yourself.

**Fix.** Create Folder is now idempotent. If the site folder doesn't exist, it's created and the picked subfolders are added — same as before. If the site folder *does* exist, Squirrel keeps it as-is and only creates whichever subfolders are missing. Nothing already on disk is touched. If a file with the site's name exists (not a folder), it still refuses with a clear error.

The success toast reports what happened distinctly, so you know whether Squirrel scaffolded a fresh folder or filled in gaps: *`"AcmeCorp 2026-08-03" already existed — added 2 subfolders: images, floorplans`*.

Suite `v1.30.0 → v1.30.1`. Squirrel `v1.21 → v1.22`.

## Files changed

- `tools/folder_organizer.py` — `create_project_folder(name, root, subfolders)` no longer errors when `target.exists()`. It now switches on `target.is_dir()`: if the target is a file, refuse; otherwise `target.mkdir(parents=True, exist_ok=True)`. Loops the picked subfolder names and records the ones that weren't already present into `added`. Returns two new fields alongside `subfolders`: `existed: bool` (whether the site folder was already on disk) and `added: list[str]` (subfolders newly created this call).
- `web/assets/js/organizer.js` — `doCreateFolder()` reads the new `r.existed` / `r.added` and picks one of three toast messages: fresh create with N subfolders, existing folder + N added subfolders, or existing folder with nothing to add.
- `web/organizer.html` — Squirrel version chip `v1.21 → v1.22`.
- `web/assets/versions.json` — suite `1.30.0 → 1.30.1`, organizer `1.21 → 1.22`.
- `web/pages/hosted-index.html` — landing-page version chip `v1.30.0 → v1.30.1`.

## Verified

Ran three end-to-end calls against a temp root via the local API:

1. Fresh site name → `existed: false`, `added: ['images', 'floorplans', 'reports']`, all three dirs on disk.
2. Same call again → `existed: true`, `added: []`, filesystem unchanged.
3. Deleted `images/` + `floorplans/` from the existing folder, called again → `existed: true`, `added: ['images', 'floorplans']`, missing dirs re-created, existing `reports/` untouched.
