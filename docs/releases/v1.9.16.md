WD Report Phone Hotspots — fixes two bugs that made yesterday's v2.2 template look broken on almost every .esx in the library.

## Bug 1 — floor-plan image rendered tiny in a huge white box

**Symptom:** `.rep-overview-plan` container filled the page width, but the floor plan drawing appeared as a small icon centered inside, with lots of empty whitespace around it.

**Root cause:** the shared CSS made BOTH the image and the SVG overlay `position: absolute` inside a container that only got its height from the inline `aspect-ratio:{W}/{H}` inline style. If anything about that inline style computed weird (browser quirk, cache, older browser support, print-media context, or just the container being restyled downstream), the container collapsed and both absolute children rendered relative to zero — the image ended up at intrinsic size floating in an empty box.

**Fix:** put the image back **in normal flow** (`display: block; width: 100%; height: auto`) so it sizes the container by itself via its own intrinsic aspect ratio. The SVG stays `position: absolute` and overlays on top. No more reliance on CSS `aspect-ratio` at all.

```
.rep-overview-plan img {
  display: block; width: 100%; height: auto;
}
.rep-overview-plan svg {
  position: absolute; top: 0; left: 0; width: 100%; height: 100%;
  display: block; pointer-events: none;
}
```

This also fixes the antenna report — same container, same class, same bug latent.

## Bug 2 — every floor showed "0 hotspots detected"

**Symptom:** on Bldg D and most other survey files, per-floor headers read "0 hotspots detected" even though the combined table listed the hotspots correctly. No walk-path polylines rendered on the overlay either.

**Root cause:** Ekahau ships surveys in two layouts and I only handled one.

Audit of your Projects folder (37 .esx with measurements):

| Layout | Files | Products |
|---|---|---|
| **per-survey files** (`survey-<uuid>.json`) | **36** | Ekahau AI Pro, Ekahau Connect, Ekahau Survey (mixed) |
| single `surveys.json` | **1** | Ekahau Survey 3.11.0 (sample-project.esx only) |

Same product/version emits both layouts depending on save context — the ONE outlier is sample-project.esx, which happens to be the file I tested with when building v2.2. Every other file in your library uses the per-survey layout.

**Fix:** `parseEsx()` now globs `esxZip.file(/^survey-[a-f0-9\-]+\.json$/)`, parses each one (they each have shape `{surveys: [<single entry>]}` with the same `routePoints` + `wifiTracks` + `accessPointMeasurementIds` fields), and concatenates the results into `proj.surveys`. If the old-style `surveys.json` is also present, it merges with that.
