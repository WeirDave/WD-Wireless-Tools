# Squirrel Rename works when a single site folder is picked as the root

Suite **2.175.3** ships **Squirrel 1.27.6**. The Rename page header shows the Squirrel number, not the suite number.

## What changed

### Squirrel → Rename (hamburger menu → **Rename…**, or `/squirrel/rename`)

The folder picked at the top of the Rename page can now be either **the folder that contains the site folders** (as before) or **one site folder on its own**. Nothing needs to be turned on.

- **File Convention renames a site folder's own files.** With a site folder picked, the Preview panel used to come back empty, because every folder inside it was one of Squirrel's `images/`, `floorplans/` or `reports/`. The preview now lists the site folder's top-level files, including the `.esx`, plus everything in its Squirrel subfolders. `{folder}` is filled with the site folder's name. **Apply Rename** and **Undo** work on all of them.

- **Folder Convention no longer offers to rename Squirrel's subfolders.** With a site folder picked, it used to list `images/`, `floorplans/` and `reports/` as folders to rename, and **Apply Rename** would have broken the layout Organize had built. Squirrel's subfolders are now never listed. If they are the only folders present, the Preview panel shows: "This is a site folder - its subfolders are Squirrel's and are not renamed. Pick the folder that contains your site folders to rename those." The same applies with a CSV site directory loaded. When the folder containing the site folders is picked, any Squirrel-named subfolder beside the sites is left out too.

- **Unchanged, by design:** **File Cleanup Rules** does not rename `.esx` files, the same as Organize. Use **File Convention** to rename the `.esx`.

This builds on 2.175.2, which added Squirrel's subfolders to the Rename preview and stopped **Apply Rename** from writing names that still had a blank token in them.

## Verified

- Preview, apply and undo were run against the rename endpoints with a site folder picked as the root. The site's `.esx`, its loose top-level files and the files in `images/` and `floorplans/` were all renamed and then restored.
- Three new automated tests cover a site folder picked as the root and Squirrel subfolders sitting beside sites. All three fail against the previous code.
- The full test suite ran as part of the release build.

## Files changed

- `tools/rename_manager.py`: works out which folders are sites, leaving Squirrel's destinations out, and handles a site folder picked as the root
- `web/assets/js/rename.js`: top-level files of a site folder are shown without a leading `./`
- `tests/test_rename_sees_organized_subfolders.py`: three new tests
- `web/assets/versions.json`, `README.md`: version numbers
