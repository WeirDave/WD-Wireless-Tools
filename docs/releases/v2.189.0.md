# AP Labeler: rename one floor, chosen floors, or the whole project

Suite **2.189.0** ships **AP Labeler 2.14.0**. The AP Labeler page shows the AP Labeler number, not the suite number.

## What changed

### AP Labeler: choosing which floors are renamed

- **A new section, "Floors to rename", decides which floors get new names.** Before this release every download renamed every floor, so labelling one floor added to a finished project renumbered all the others.
- **Where it is:** section **2** of the sidebar, between **Name Pattern** and **Numbering**. It has three buttons:
  - **"Whole project"**: every floor is renamed. This is the default and matches the old behaviour.
  - **"This floor only"**: only the floor on screen when the button is pressed. Switching floor tabs afterwards does not change it. To move it to another floor, go to that floor and press the button again.
  - **"Choose floors"**: a checkbox for each floor, with **"Tick all"** and **"Tick none"**. It opens with the floor on screen ticked.
- **Floors that are left out keep every name exactly** in the downloaded `.esx`. They show dimmed in the floor tabs, their AP markers are faded, and the preview heading reads **"this floor is not being renamed"**.
- If a new name matches a name on a floor that is not being renamed, the duplicate-name warning above the preview names it and suggests renaming that floor too.

### AP Labeler: "Scope" is now "Numbering"

- **The section formerly called "Scope" is now "Numbering"** (section **3**), and its buttons are **"Continuous"** (formerly **All APs**) and **"Restart each floor"** (formerly **Per Floor**). It only ever controlled how the counter runs. **Per Floor** never limited which floors were renamed, which is what the new section above is for.
- **Numbering now follows the project's existing names.** If two or more floors' numbers start from the same value, Numbering is set to **"Restart each floor"**. If the floors' ranges run on without overlapping, it is set to **"Continuous"**. The **"Read from this project"** note at the top of the sidebar says which was chosen. So a floor added to a project numbered per floor starts at 001, not where the floor below left off.
- With **"Continuous"**, a floor that is not being renamed still counts. A floor labelled on its own gets the numbers it would have had in a full run.

### AP Labeler: a wider sidebar

- The sidebar now opens 480 pixels wide, up from 340, and can no longer be dragged narrower than 380. Full AP names fit on one line in the preview. It can still be dragged wider, up to 60% of the window.
- The **"Current"** label in the name summary above the preview no longer wraps onto two lines.

## Verified

- A new browser test loads a synthetic three-floor project into the real page. Two floors are already labelled per floor, and the third still has placeholder names. The test reads the names back out of the `.esx` built by **Download labeled .esx**:
  - **"This floor only"** on the new floor renames only that floor, starting at 001, and leaves the other two unchanged.
  - Switching to another floor tab after choosing does not change which floor is renamed.
  - With **"Choose floors"** and nothing ticked, **Download** is unavailable; ticking one floor renames only that floor.
  - Numbering is set to **"Restart each floor"** from the project's names.
- The browser test was run in Chromium. Removing the floor choice from the naming code fails three of its four tests, and removing the numbering detection fails the other.
- Firefox and Edge were not available where this was built. The new test runs in both in CI.
