# Cloud Manager removes a sign-in Ekahau has turned away, and never sends an expired one

Suite **2.226.0**: Cloud Manager **4.88.0**. Every other tool is unchanged.

## What changed

### Cloud Manager: stale sign-ins

- **A saved sign-in that Ekahau no longer accepts is removed.** When Ekahau answers the saved session with a login redirect or a 401, the saved copy is deleted instead of being tried, and refused, again on every start. The waiting screen's reason line says *"Saved sign-in: Ekahau no longer accepts it, so it was removed"*. A saved sign-in is **kept** when the failure says nothing about it: no network yet (a machine just woken from sleep), a timeout, a server error or a 403.
- **Expired browser cookies are ignored.** A browser whose only Ekahau sign-in has expired is reported as *"its Ekahau sign-in has expired - log in again"* instead of *"Ekahau did not accept"*, and the expired cookie is never sent. Logging in again in that browser replaces it.
- **The newest of two sign-ins is the one sent.** When a browser holds an old and a current AccessToken (or CSRF token) side by side, the one that lasts longest is used, whichever the browser lists first. A session cookie with no expiry counts as current.
- **Browser cookie files are never edited.** They belong to the browser and are open while it runs, so nothing is deleted from them; only the saved copy kept by Cloud Manager is removed.

### Releases

- **Safari no longer holds a release back.** A release still runs all four suite jobs and the Firefox, Chrome and Edge browser jobs; the Safari job is left out of that run. It still runs, and shows its result, on every pull request and push.

## Verified

- Each rule is driven through the real functions and turns its test red when removed: a login redirect and a 401 remove the saved session and the legacy file with it; a dead network, a timeout, a 503 and a 403 keep it; a session saved by another thread while one is being refused is not the one removed; an expired-only token is reported as expired and never sent; an old token beside a current one, in either order, loses; the stale CSRF token is not saved.
- The release workflow turns Safari off, the input defaults to running it, and the condition cannot skip Safari on a pull request. Each of those turns a test red when changed.
- The suite passes.
