WD Cloud Manager — dashboard grows a "Name Matches" filter card so you can jump straight to the verify-eligible pairs without scanning the whole ledger.

Suite `v1.9.50 → v1.9.51`. WD Cloud Manager `v4.8.8 → v4.8.9`.

## the maintainer's ask

> "Hey since the name matches situation is a common one can we add a filter for them? Not sure what we call it really..."

**Name choice**: went with "Name Matches" since that's exactly what the badge on each such row already reads (`✓ Name matches`). Matching the badge's text meant one less concept for the user to hold — click a filter labeled the same as the pill it shows.

## What it does

Same-name pairs (matchType='exact' — cloud and local file share a filename but no hidden-id link) are the rows Ekahau *can't* prove are the same project, and the ones the Verify workflow can promote to Same-file with a byte-identical overwrite. They're common on the maintainer's ledger (~31 of his ~94 matched projects in Flat view) so a dedicated filter beats hunting through All.

- **Card placement**: right after Mismatches in the dashboard row — both are subsets of matched-pair states so they sit together.
- **Count**: matched pairs with `matchType === 'exact'` (owner-filter aware, matches every existing count's semantics).
- **Tab gating**: Projects (Flat) view only. Sites (Tree) view hides the card and reverts the filter to All if it was active when you switched. Same treatment as the existing "No Site" card, since matchType lives on tree-child project pairs, not on site-level rows.
- **Color**: `#4a90d9` (a slightly deeper blue than the existing `#6bb3e0` Cloud Only card, matching the blue tone of the row's `mb-exact` badge but distinct enough not to confuse the two).
- **Active behavior**: when clicked, the ledger shows ONLY matchType='exact' pairs. Verify (per-row ⇩ + bulk Verify pairs button) still works — this filter narrows what's visible but doesn't change the actions.

## Verified in the preview

Steps run in the browser pane on the maintainer's real cloud:

1. Reloaded `/cloud` — version chip: `v4.8.9`.
2. In Flat/Projects view: card visible, label reads "Name Matches", count reads `31`.
3. Clicked the card → active state applied; rendered 31 rows total, every one of them carries the `.mb-exact` badge (zero rows with any other badge type).
4. Switched to Tree/Sites view → card hides (`display: none`), and if the name-matches filter had been active it reverts to All so the sites tab doesn't show an empty ledger.
5. Switched back to Flat → card reappears with count intact.
