# Capacity: a headcount for each floor, and a re-run sets the device count instead of adding to it

Suite **2.179.0** ships **Capacity 1.5.0**. The Capacity page shows the Capacity number, not the suite number.

## What changed

### Capacity → Apply a template

- **Each floor now takes its own headcount.** Before this release one number was applied to every floor, so a three-storey building for 600 people was written with 600 people's devices on each storey, 1,800 in total. Each floor can now be sized for the people who are actually on it.
- **Where it is:** Capacity, step **3 — Apply a template to this project**. Every floor in the preview has a **People on this floor** box under its description.
- **Default:** blank. A blank box uses the number in **Each floor is for** at the top of step 3, which is shown greyed inside the box. This field was labelled **This building is for** in earlier releases; it now says **Each floor is for** because that is what it has always done.
- Type a number to size that floor for that many people. Type **0** to leave the floor alone: nothing is written to it, and the preview marks it "skip - no people on this floor".
- The preview updates when you leave the box. Each floor shows its own device count, and the line under the floors totals the people and devices across every floor that will be written. The result after **Apply and download** reports the same totals.
- Per-floor numbers are cleared when another project is opened, because floors belong to one project.
- Prep is unchanged: its **Requirement areas** step still applies one headcount to every floor.

### Capacity → floors that already have devices

- **Running Capacity again no longer compounds the device count.** Ekahau adds up every capacity area on a floor. The replace option rewrote only the first capacity area it found, so on a floor with two, the second kept its devices and each run added more on top. Replacing now sets the floor to exactly the new number: the largest capacity area takes the new devices, and every other capacity area on that floor has its devices cleared. Their outlines, names and colours are kept, and no area is deleted.
- **Where it is:** Capacity, step **3 — Apply a template to this project**, the **Floors that already have devices** dropdown directly under **Each floor is for**. It replaces the **Replace requirement areas that already exist** checkbox.
- **Default:** **Keep them as they are**, the same as leaving the old checkbox unticked, unless a different default has been saved in Settings (below). The other choices are:
  - **Replace device counts, keep the area outline**: new device counts, every outline left exactly as drawn.
  - **Replace device counts and redraw the area**: new device counts, and the area is redrawn from the walls, or from the APs where there are no walls.
- **Per floor:** every floor that already has devices shows how many it has and gets its own **This floor** dropdown with the same three choices, so some floors can be replaced and others kept. Changing the dropdown at the top resets every floor to that choice.
- **Saved default:** Settings → **Capacity** section → **Floors that already have devices**, with the same three choices. It sets what the Capacity dropdown starts on each time a project is opened, and ships as **Keep them as they are**. Changing the dropdown on the Capacity page affects that run only and is not saved; the Settings page is the only place the default is set. The Capacity step 3 hint links to it.
- A notice above the floor list says how many floors already have devices, and each of those floors states what it has now and what it will be set to, for example "Already carries 150 devices across 2 capacity areas. Set to 600 — replaced, not added to".

## Verified

- Two floors given 300 and 40 people are written with each floor's own device counts, read back from the downloaded project.
- A blank floor uses the building number; with no per-floor numbers every floor gets the building number exactly as before.
- 0 leaves a floor with no capacity area; a project where every floor has its own number needs no building number.
- The preview's per-floor device counts match what the writer puts in the file.
- On the real Capacity page, the **People on this floor** box sends its number with the preview and with **Apply and download**, sends 0 as 0, and returns the floor to the building number when cleared.
- A floor with two capacity areas (100 and 50 devices), replaced for 200 people, carries exactly the 200-person count afterwards; applying again to that result gives the same count, not double.
- Replacing device counts leaves every outline unchanged; redrawing sets the largest area's outline to the one measured from the walls and leaves the other areas' outlines alone.
- **Keep** writes nothing, a choice made for one floor applies to that floor only, and on the real Capacity page the dropdowns send their choice with both the preview and **Apply and download**.
- The Capacity page opens on the saved default, returns to it when another project is opened, falls back to **Keep them as they are** for a value it does not recognise, and never writes the setting. The Settings page saves each of the three choices and keeps the saved one if its dropdown has not rendered.
- These checks fail if the writer uses one headcount for every floor, if the page stops sending the per-floor numbers, or if the other capacity areas on a floor are left with their devices.
