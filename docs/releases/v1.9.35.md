Home page — each card's hover tint is now its own color in both themes. Fixed dark-mode "everything goes gray" hover and the too-faint light-mode hover.

Suite `v1.9.34 → v1.9.35`.

## The two bugs the maintainer hit

1. **Light mode: hover barely visible.** Every card on hover set `background: var(--surface-raised)`, which in light mode is `#f6f8fa` — a hair off `--surface` `#ffffff`. Faint enough that you had to hunt for which card you were hovering.
2. **Dark mode: hover turns gray instead of the card's color.** Same shared `--surface-raised` rule — but in dark mode, `--surface-raised` is `#252830` (a neutral gray). So the green card, purple card, teal card etc. all went to the SAME gray on hover instead of tinting with their own color.

Same root cause for both: sharing one neutral surface tint across every variant meant no variant got its own signature hover.

## The fix

Each card variant now has its own hover background tint using its category color at ~18-20% opacity in dark mode and ~14% in light mode. Both themes get the same **"this card, this color"** hover feel:

- Blue (Cloud): `rgba(30, 119, 172, 0.18)` dark / `0.14` light
- Green (Walls): `rgba(95, 171, 79, 0.18)` / `0.14`
- Teal (Report): `rgba(13, 148, 136, 0.20)` / `0.14`
- Purple (Scale): `rgba(139, 92, 246, 0.20)` / `0.14`
- Amber (Squirrel): `rgba(217, 119, 6, 0.18)` / `0.14`

Purple and teal get 20% (instead of 18%) in dark mode because those two colors sit lower on the perceptual brightness scale — needed a touch more opacity to read equivalently against the dark surface.

## Verified in the preview

All 10 hover rules (5 variants × 2 themes) confirmed present in the loaded stylesheet with the expected opacity values. Each variant tints with its own color; no more shared neutral gray.

## Files changed

- `web/assets/wd-tools.css` — `.card:hover` and each `.card.<variant>:hover` get color-tinted background plus a `[data-theme="light"]` override for the lighter light-mode tint.
- `web/assets/versions.json` — suite version bump.
