WD Cloud Manager — merge dialog auto-cleans the empty source folder in one click, and every local `.esx` row now has an inline Move-to-Site button.

Suite `v1.9.23 → v1.9.24`. WD Cloud Manager `v4.5.5 → v4.6.0`.

## Two quality-of-life improvements the maintainer asked for

**"When you merge a folder into another site, the source folder is always empty afterwards. Delete it for me — that's what I was doing anyway."**

The merge modal used to run the merge, then pop a *separate* Delete-Folder confirm dialog whenever the source ended up empty. That was one extra click for the near-universal case. Now the merge modal has a checkbox — **"Delete the source folder afterward if it ends up empty"** — that's checked by default. Merge finishes, the empty source disappears, done. If the merge leaves files behind (unticked conflicts, errors, source-only files), the folder is preserved even with the box checked.

Untick the checkbox to fall back to the old behavior (post-merge confirm-then-delete), which is useful when you deliberately kept the source folder for backup or dated snapshots.

The auto-delete runs through the Operations Deck (added in v1.9.22), so you see a *"Cleaning up empty '…'"* card fire and complete right after the merge card.

**"We don't have a way to move an individual `.esx` file to another folder while we're in here."**

We did — but only on the Projects flat view via the toolbar's *Move to site…* button after check-and-select. On the Sites tree view, the only per-row options for a local `.esx` were rename and delete. To move a file you had to either use the flat view or open Explorer manually.

Now every local `.esx` row (both flat view and tree children) has a ↪ button next to rename that opens the same Move-to-Site picker used by cloud projects and bulk moves. Same site list, same auto-suggest logic (matches by parent folder, then site code + fuzzy name), same confirmation copy. Backend op is `move_local_to_site` — a filesystem move, no cloud interaction.

## Verified in the preview

- Merge modal renders the new `#mergeDeleteSrc` checkbox, checked by default.
- 95 local `.esx` tree-child rows all display the ↪ Move icon linked to `startMoveLocalToSite(path, name)`.
- Function `startMoveLocalToSite` exists and mirrors the cloud-side entry point (`startMoveToSite`).

## Files changed

- `web/cloud.html` — new `#mergeDeleteSrc` checkbox row in the merge modal.
- `web/assets/js/cloud.js` — `confirmMerge` reads the checkbox and, on success + empty source, enqueues a `delete_local` op through the deck; falls back to the old confirm dialog when the box is unticked. New `startMoveLocalToSite(path, name)` mirrors `startMoveToSite` for local `.esx` files. `localCell` renders the ↪ Move button on every `!isDir` row.
- `web/assets/wd-tools.css` — new `.merge-cleanup` selector matching `.merge-remember` styling.
- `web/assets/versions.json`, `web/cloud.html` — version chip bump. Cloud minor version bumps to `v4.6.0` because this adds a new user-facing action, not just polish.
