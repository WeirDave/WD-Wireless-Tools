# Safer updates, settings imports and file handling; libraries and Python minimum updated

Suite **2.247.0**. Tool versions: Cloud Manager **4.95.0**, Quick Walls **7.80.1**, Squirrel **1.31.1**, Report **2.77.1**, PlanTrim **2.3.2**, Capacity **1.14.1**, Prep **2.10.1**. Scale and AP Labeler are unchanged.

## What changed

### Python and libraries

- **Python 3.11 or newer is now required.** Python 3.10 reached end of life in October 2026, and Pillow 13 needs 3.11. The installers, the launchers' dependency check, the README, the User Manual and the landing page say so. An install that runs on 3.10 will be told to upgrade Python.
- **Dependency minimums were raised:** Pillow 13.0.0 (was 12.3.0) and cryptography 50.0.2 (was 50.0.1). The other runtime minimums were already the newest releases. The test-only list moved to selenium 4.52.0 and pymupdf 2.1. A dependency audit of the new minimums reports no known vulnerabilities.
- **Bundled browser libraries were updated:** pdf.js 6.5.438 (was 4.10.38), JSZip 3.10.2 (was 3.10.1) and mammoth 1.13.0. pdf.js and mammoth read `.pdf` and `.docx` text in Squirrel's Organizer; text extraction was checked with both new builds. A new `web/assets/lib/VENDORED.md` records each library's version and file hash, and a test fails when a file changes without that record changing.
- **A dependency version check no longer treats `12.3` as older than `12.3.0`**, and no longer lets a release-candidate number count as a patch level.

### Updating (Menu → About → Update, the install scripts and the launchers)

- **An update now either installs completely or leaves the install exactly as it was.** Each shipped folder is renamed aside, the new one moved in, and the old ones deleted only when everything is in place. A locked file during the update no longer leaves a new `server.py` beside a half-removed `tools` folder.
- **Only one update can run at a time.** A second click or a second browser tab gets "An update is already running", and **Restart** is refused while an update is running.
- **A ZIP update is no longer run over a git install**, and update requests naming any channel other than the release channel are refused.
- **Downloads are limited:** HTTPS only, at most 500 MB and 15 minutes.
- **`install.sh` and `install.ps1` replace the shipped folders** (`tools`, `web`, `templates`, `docs`) instead of merging over them, so a page or module removed in a release no longer stays on disk. A failed copy puts the old folders back. Both scripts now refuse to switch a git install to a release when it holds commits that exist nowhere else, and `install.sh` checks release tags with the same strict pattern as `install.ps1`.
- **The macOS launcher stays executable** after an in-app update.
- **Start WD Wireless Tools.bat** and **.command** now stop a leftover instance only on the port the app will use (`PORT`, default 8675), and only when the process on it is running `server.py`. Previously every listener on 8675 was killed, which also stopped a second instance started with `PORT=8676`. The macOS launcher asks the process to stop before forcing it. Both launchers are read whole before running, so replacing them during an update cannot make a running window execute half a command.
- **Manual runs of the release workflow are limited to `main`.**

### Settings

- **Settings → Import settings** now writes only the files a settings export contains (templates, capacity and report folders, and the named list files). Anything else in the file is listed under "refused" in the preview and skipped. Credential files are refused whatever the capitalisation or trailing characters of their names. Each file is written atomically, and a full export of the current settings is saved before an import applies.
- **A change that replaced a group of settings with a single value is refused** instead of leaving settings unreadable. A settings file already in that state repairs itself the next time it is read.
- **Settings → General → Local project folder** refuses a drive root, the home folder and any folder that contains the app's own data directory.
- **Cloud Manager picks up a changed project folder immediately.** It read the folder once at start, and at the next start the browser's remembered folder overwrote a folder changed in Settings. The browser's copy now only fills in a folder when none is saved.

### Cloud Manager

- **Storage addresses no longer appear in error messages or the log.** The query part of any web address in an error is replaced with `?...`, which is where a signed storage address keeps its signature.
- **Uploads go straight to Ekahau's storage** over HTTPS without the signed-in session's headers, streamed from disk instead of read into memory first.
- **The Firefox sign-in cookie is read only from `ekahau.cloud` and its subdomains.** A host that merely contained that name could be matched before.
- **Delete, rename and list requests must name "projects" or "sites".** An unknown value used to be treated as sites.
- **Group sharing actions no longer act on a missing value.** Turning "My Sharing Group" on or off needs an explicit choice, and **refresh** is a preview unless a live run is requested.
- **Replace cloud copy refuses an upload that Ekahau does not report as a new project**, so the existing project is never verified against itself and deleted.
- **A project missing from the cloud now reads "That project is no longer in Ekahau Cloud"**, and an expired sign-in reads as such, during a download of the cloud copy. The raw status text appeared before.
- **Renaming the project inside a local file** refuses when the file was saved while the update was being prepared.
- **The type badge (Design, Measured, Hybrid) is refreshed** when a file is replaced within the same second.
- **A damaged recipients list no longer turns a share that succeeded into an error**, and pasting a long address list no longer slows the page down.

### Rename and Organizer (Squirrel)

- **Rename patterns that can run indefinitely are ignored.** In **Rename**, the fields **From the start (regex)**, **From the end (regex)** and **Find (regex) / Replace with** skip a pattern longer than 200 characters or one that repeats a group which itself repeats or chooses between alternatives (for example `(a+)+`). Ordinary patterns such as `^(IMG|DSC)_` are unaffected.
- **Bulk rename only renames files inside the folder shown.**

### Large and untrusted project files (Quick Walls, Squirrel, Cloud Manager, PlanTrim, Prep, Capacity)

- **Every place that opens an `.esx` now checks the archive first** (entry count, declared sizes and expansion ratio), where this was done only for files dropped on PlanTrim, Capacity and Prep. An archive that fails the check is treated as unreadable.
- **PlanTrim's analysis and Prep's preview no longer load the survey sample files into memory**; they pass through to the saved copy one at a time.
- **Report reads floor plan sizes and AP coordinates as numbers**; a value that is not a number becomes 0, so a crafted project file cannot add markup to a report.

### Saving

- **Wall templates, the hidden-templates list, capacity templates, rename profiles and undo logs, and the Organizer's settings and undo logs are saved atomically.** A failure partway through leaves the previous file instead of a truncated one.

### Removed

- Unused code in Cloud Manager, PlanTrim, Capacity, Quick Walls, Report, Organizer and the shared page script, and two obsolete maintenance scripts.
- `scripts/make_test_projects.py` refuses to wipe a folder it did not create unless `--force` is given.

## Verified

- The full suite passes on Python 3.12 with the new dependency minimums installed, including new tests that run the real update install with injected failures, the real launchers against stand-in processes, the settings import with hostile file names, every `.esx` reader against an archive the guard refuses, and the report's number handling in Node.
- Each new test was checked by undoing its fix and confirming it fails.
- Text extraction was run against sample `.pdf` and `.docx` files with the old and new bundled libraries.
