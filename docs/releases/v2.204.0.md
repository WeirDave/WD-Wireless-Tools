# The User Guide rewritten around the job; Cloud Manager and Capacity say what is true

Suite **2.204.0**: Cloud Manager **4.78.3**, Capacity **1.8.1**, User Guide, Settings.

## What changed

### User Guide

- **Rewritten chapter by chapter against the current screens.** Every button, label and default it names was checked against the tool as it is now. Controls that no longer exist are gone, renamed ones carry their real names, and controls that were never described (Squirrel's **Create Project Folder**, **Extract Floorplans** and **Acorn Notes**, AP Labeler's **Templates & Defaults**, Quick Walls' **Visual Swap** keys, Report's **Change / Audit Report**) are covered.
- **Every tool chapter opens with a Quick start**: the everyday job in three to six steps, naming the buttons to press. The details follow underneath for when they are needed.
- **A "Which tool do I need?" table** at the start, and **A site from start to finish** follows one job through the tools in order.
- **Warnings that matter are stated plainly**, including: a box drawn and cropped in PlanTrim or Prep removes whatever lies outside it on that floor; deleting a wall type in Quick Walls leaves walls drawn with it without a type; replacing a cloud project deletes the old one and everyone it was shared with loses access.
- **New screenshots** of Home, Quick Walls, Prep, PlanTrim, Capacity, Report and Scale, taken from the current version with invented projects.
- Version history and implementation notes are gone from the guide.
- Open it from **User Guide** on Home, or **User Guide** in any tool's menu, which opens it at that tool's chapter.

### Cloud Manager

- **No text promises a copy that is not kept.** The **Fix names inside files** tooltip and its confirmation said each file is backed up first; the **Overwrite from cloud…** tooltip and the **How matching works** dialog said the replaced file is kept as a `.previous-` copy. None of those copies is made. They now say that the cloud copy, which Ekahau still holds, is the other copy.
- **How matching works** now describes **Local newer · replace cloud**: it uploads the local copy as a new cloud project, checks it arrived, and only then deletes the old one, naming everyone who will lose access first. It used to say there was nothing to click.

### Capacity

- **A template that cannot be applied says where the reason is.** When the open project lacks profiles the template names, the footer said only "Nothing to apply." It now says the template cannot be applied to this project and that the reason is under **2 — Apply it to this project**.
- That reason now suggests opening the template with **Edit** while a project that has the profiles is open, and saving it, so the template carries its own copies.
- The shipped example's description suggests building a template with **New template**, or **Edit** to save a copy, instead of capturing one from a file.

### Settings

- The **Default view** hint under **Cloud Manager** says what happens: pressing **All**, **Mine** or **Others** in Cloud Manager's toolbar changes this setting too, so the list opens the way it was last left. It used to say the toolbar choice lasted only until a reload.

## Verified

- In headless Firefox, a project with none of the example template's profiles: the plan names the missing profiles, the footer says the template cannot be applied and where the reason is, and **Apply and download** is unavailable. Before the change the footer read "Nothing to apply."
- No sentence in Cloud Manager's page or script promises a `.previous-` copy or a file "backed up first"; the check now reads the page as well as the script, and fails on the previous text.
- The guide renders with every internal link landing on a heading, no unconverted markup, no promise of a backup copy, and only invented names.
- The full test suite passes.
