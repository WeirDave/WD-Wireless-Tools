# Cloud Manager: replacing a cloud project waits for a large upload to be listed

Suite **2.235.5**, Cloud Manager **4.90.3**. Every other tool is unchanged.

## What changed

### Cloud Manager (the **Local newer · replace cloud** action on a row)

- **A large project is waited for instead of abandoned.** After the upload, Ekahau lists the new project only once it has processed the file, which takes longer the larger the file is. The replace waited about 11 seconds for that, then reported "the upload finished, but Ekahau has not listed the new project yet". It now waits up to about two and a half minutes, with the progress line "Waiting for the cloud listing to show the upload" counting up, and continues as soon as the project is listed. The old cloud project is still deleted only after the new one is confirmed.
- **When the wait still runs out, the message says where the upload is and what to do.** The upload is under **Unassigned projects**, not yet renamed or filed into a site, and carries the name stored inside the file, which can differ from the file name. The message names both, lists the steps in order (rename it to the file name, assign it to the site, delete the older copy last), and says not to run the replace again, because that adds a third copy. Nothing is deleted in this case.

## Verified

- A listing that lags past the previous wait is now followed through to a completed replace, with exactly one upload and the old project removed afterwards. With the previous wait restored, that test and the one measuring the total wait both fail.
- A listing that never shows the upload leaves the old project in place, deletes nothing, and returns the instructions above.
