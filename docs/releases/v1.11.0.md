## The audit

The v1.10.0 release notes admitted the CSS reorganization was cut mid-session. This release does it properly — end-to-end read, structured findings, then fixes anchored to each finding.

### Silent bugs — undefined tokens

Five CSS custom properties were referenced with no root declaration. Everywhere they appeared they either fell through to a wrong-tint fallback or rendered as `initial`:

- `--accent` — used 5×, never defined. Broke `.btn-visual-swap`, `.swap-tool.active`, `.share-list-filter:focus`, `.swap-sel-count`. The visual-swap button had no fill color; the active swap tool had no accent tint; the share-list search focus ring never lit up. All fixed by adding `--accent: var(--nav-blue)` to `:root`.
- `--border-strong` — used 2× with inconsistent fallbacks (`#444` vs `var(--border)`). Now `#3a4a5e` dark / `#c9cdd2` light.
- `--surface-alt` — used 2× with divergent fallbacks (`rgba(255,255,255,0.04)` vs `0.02`). Consolidated to one token per theme.
- `--orange` — used 1× on `.owner-tag.other` as `var(--orange, var(--amber))`, so orange never actually rendered. Now `#ea7c1a`.
- `--card-bg` / `--card-hover` — declared only on `body.tool-home` but referenced by `.theme-toggle` and `.card` which appear on every tool. Fallbacks were carrying the load. Moved to `:root` so the fallback is the exception, not the rule.

`--teal` was declared inside a stray `:root { }` block at line 4141, mid-file. Moved to the main tokens section at the top.

### `!important` — non-print uses eliminated

Memory rule: `!important` outside print is evidence the audit wasn't done. Twelve non-print `!important` declarations found. Each traced to its actual specificity fight, then fixed at the source:

- `.ledger-row.verify-failed` (3×) — was fighting `.ledger-row:hover` at equal specificity, but source order already put verify-failed later. `!important` was cargo-cult.
- `.rep-bom-total td` (3×) — 0,1,1 selector losing to `.rep-ap-table td` (also 0,1,1) declared later. Fixed by raising specificity: `.rep-ap-table .rep-bom-total td` (0,2,1).
- `.rep-step[disabled]` (2×) — `transform`/`box-shadow` had no competing rule; `:hover` already used `:not(:disabled)`. Dropped.
- `.swap-topbar h1` (2×) — was tied with `.header h1, .dz-topbar h1` at 0,2,0. Raised to `.swap-modal .swap-topbar h1` (0,3,0).
- `.btn-swap-delete` (2×) — `border` and disabled `color` — no competing rule, dropped.

The only remaining `!important` outside `@media print` is a single global `[hidden] { display: none !important; }` (see next section). Print block keeps them by design — dark chrome must be forcefully replaced with printable white.

### `[hidden]` flash bug — fixed

Twelve `.dash-card` elements in `cloud.html` start with the native `hidden` attribute. But `.dash-card { display: flex; ... }` (specificity 0,1,0) beat the browser UA's `[hidden] { display: none }` (0,1,0 same, but UA sheet loses to author). Result: every filter card, type card, and duplicate card flashed visible on page load before JS wired up the filter state.

Fix: one global `[hidden] { display: none !important; }` at the top of the file, defended as a UA-behavior restore rather than a fight for specificity. The dashboard now paints cleanly on first frame.

### `.dash-card` variant table — DRY'd

Sixty-one rules for twelve variants, all following the same pattern: "border color per variant, active background per variant, active border-left per variant." Compressed to a two-line shared rule plus a sixteen-line table using per-variant custom properties `--dc` (variant color) and `--dc-active` (variant active background):

```css
.dash-card { --dc: var(--border); --dc-active: transparent; border: 1px solid var(--dc); … }
.dash-card.active { background: var(--dc-active); border-left-color: var(--dc); }
.dash-card.mismatches    { --dc: var(--amber);  --dc-active: rgba(217,119, 6,0.32); }
.dash-card.name-matches  { --dc: #4a90d9;       --dc-active: rgba( 74,144,217,0.28); }
…
```

61 rules → 20. Adding a new variant is now one line, not five.

Along the way: `.dash-card.dup-all` had a lone hover-color inconsistency (hover: `var(--amber)`, static: `#f0b85f`) that no other variant had — normalized to match the pattern.

### Print `@media` blocks — consolidated

Three separate `@media print` blocks scattered across lines 4804, 4919, and 5419. Merged into one block at the bottom of the file, ordered so that later rules (rep-cover, tighter margins) still override earlier ones (rep-doc-head base). The consolidated block is now searchable as "the print block" instead of hunting three places.

### Duplicate `.rep-logo-*` rules — the second-write bug

`.rep-logo-row`, `.rep-logo-btn`, and `.rep-logo-preview` were each declared twice with different values — once at ~line 4490, once at ~line 4844. The second set won by cascade order, so the first set was silently dead. Deleted the first (dead) set. Behavior identical, ninety fewer bytes.

### z-index scale — tokenized

Ten different z-index values scattered as literals (`50`, `60`, `90`, `100`, `200`, `300`, `500`, `9999`, `10000`, plus small local `1-10`). Extracted the global-stack values as tokens with named purpose:

```css
--z-sticky: 10; --z-header: 50; --z-menu: 60; --z-deck: 90;
--z-modal: 100; --z-popover: 200; --z-menu-top: 300; --z-swap: 500;
--z-toast: 9999; --z-emergency: 10000;
```

Callers now say `z-index: var(--z-modal)` instead of `z-index: 100`. Local stacking contexts inside scrolling regions (values 1–5) left alone — those aren't meant to compete with the global stack.

### File structure — section banners

The old file was 5498 lines of undifferentiated rules with no visible structure. Now sectioned:

```
RESET · TOKENS · SHELL · BUTTONS · MODALS · TOASTS · FIELDS
CLOUD · WALLS · SCALE · REPORT · ORGANIZER · HOME · GUIDE
PRINT
```

Each section starts with a heavy Unicode banner (`/* ═══ CLOUD ═══ */`), searchable in one keystroke. The top-of-file comment lists all sections and the two invariants the audit established: no `!important` outside print + [hidden] restore, no undefined `var()`.
