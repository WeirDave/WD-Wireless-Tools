# Cloud Manager: replace a newer cloud project with an older local file

Suite **2.188.0** ships **Cloud Manager 4.78.0**. The Cloud Manager page shows the Cloud Manager number, not the suite number.

## What changed

### Cloud Manager: keeping the local copy when the cloud copy is newer

- **A paired project whose cloud copy is newer can now be replaced with the local file.** Before this release, a **Cloud newer** row offered only the download, and replacing the cloud project was available only when the local file was the newer one.
- **Where it is:** in the line under a project row marked **Cloud newer**, under the Cloud column, beside **Cloud newer · download**. The button reads **"Replace cloud with local…"**.
- **What it does:** a confirmation names the local file, the cloud project, and the date each was last saved, and states that every change made in the cloud since the local save is lost. Nothing happens until **"Replace the cloud copy"** is pressed.
- The replace works the same way as **Local newer · replace cloud**. The local file is uploaded under its own name into the same site and checked. The old cloud project is deleted only after that succeeds. People the old project was shared with lose access and are named when it finishes.
- On a project owned by someone else, the button is shown greyed out, with the reason. Ekahau only lets the owner replace a project.
- **Local newer · replace cloud** is unchanged. It still stops without uploading or deleting if the cloud copy has been saved since the list was loaded.

## Verified

- New tests render the real row, read the button back out of it, and run it. The confirmation names the project, both dates, and that the cloud changes are lost. Confirming sends the replace for that project with the override. Cancelling sends nothing.
- Server-side tests confirm a newer cloud copy is still refused without the override, and replaced with it: upload first, delete after. The server accepts the override only when it is exactly `true`.
- Each new test was confirmed to fail with the override removed from the button, and with it removed from the server.
