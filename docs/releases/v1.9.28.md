WD Cloud Manager — jump-nav actually works when clicking a letter above the current scroll position. Sticky headers were corrupting every position measurement.

Suite `v1.9.27 → v1.9.28`. WD Cloud Manager `v4.6.3 → v4.6.4`.

## The bug the maintainer hit (across three browsers)

Clicked O → scrolled correctly. Clicked F afterwards → nothing moved (or moved 36px). Same in Chrome, Edge, and Firefox. Even from a fresh scrollTop=0, clicking N then F would skip past N to O, then fail to go back to F.

## Root cause

`.ledger-group-head` uses `position: sticky; top: 36px;` so the current section's header stays pinned to the top of the container as you scroll. But sticky positioning corrupts multiple layout measurements:

- `getBoundingClientRect().top` on a stuck header returns the stuck position (36px below container top), NOT the header's natural position in the DOM.
- `offsetTop` — surprisingly — also gets corrupted after a scroll. When I measured F's `offsetTop` after clicking O, it returned 5608 (near O's position) instead of F's natural 4461.

Both approaches drove the scroll calculation to the wrong value. `scrollTop` would be set to the current scroll position ±36px, so the container would barely move.

## The fix

Walk the container's DOM tree and sum the physical `offsetHeight` of every element that appears before the target in document order. `offsetHeight` is the rendered pixel height of the box and is unaffected by positioning tricks. That sum is the exact scrollTop needed to put the target at the container's top.

```js
let offset = 0;
const walk = (parent) => {
  for (const child of parent.children) {
    if (child === target) return true;
    if (child.contains(target)) return walk(child);
    offset += child.offsetHeight;
  }
  return false;
};
walk(scrollEl);
scrollEl.scrollTop = offset;
```

## Verified in the preview

Ran the exact sequences from the maintainer's report:
- 0 → O: scrollTop 5280 ✓
- O → F: scrollTop 4164 (correctly went UP) ✓
- F → W: scrollTop 8350 ✓
- W → A: scrollTop 174 (correctly jumped to the top) ✓
- A → Z: scrollTop 8648 ✓
- Z → M: scrollTop 5062 ✓

Every jump lands where the letter's section actually is, regardless of previous scroll state.
