# AP Labeler's dashed spacing lines match the numbering in Safari

Suite **2.221.0**: AP Labeler **2.19.2**. Every other tool is unchanged.

## What changed

### AP Labeler

- **The dashed lines now sit where the rows (or columns) really split, in every browser.** With **Ordering** on a Rows or Columns option and a number typed into **"Line Spacing"**, the dashes were placed using the size the browser reports for the plan image. Firefox and Chromium report the plan's own pixel size; Safari reports the size it is drawn at on screen. A 600 px plan drawn at 496 px in Safari showed 41 lines for a spacing of 12 where the numbering used 50, so the dashes marked rows that were not the ones being numbered. The lines are now placed from the same measurement the numbering uses, so the two cannot disagree.
- Nothing changes in Firefox, Chrome or Edge: the two measurements were the same there.

## Verified

- The line-drawing function is run with an image that reports Safari's size and must give the same lines as one that reports the real size; with the old code it gives 41 lines, with the fix 50. The same check runs in the real page in Firefox, with the image's size overridden to Safari's, and it fails with the old code (`41 != 50`).
- AP Labeler's Line Spacing box is now also driven with real key presses in Safari on macOS, in a Safari job of its own in CI, next to Firefox, Chrome and Edge. That job is what found this.
- The suite passes.
