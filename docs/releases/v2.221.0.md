# Quick Walls adds a "+ Add Attenuation Area" button

Suite **2.221.0**: Quick Walls **7.77.0**. Every other tool is unchanged.

## What changed

### Quick Walls

- **"+ Add Attenuation Area"** on the **Attenuation Areas** tab opens a dialog to create a new attenuation area type: **Name**, **Color**, **Lower edge (ft)**, **Upper edge (ft)** and the loss in dB per foot at **2.4 GHz**, **5 GHz** and **6 GHz**. Leaving **Upper edge** empty runs the area to the ceiling. Feet and dB per foot are converted to metres and dB per metre, and the new type is built the way Ekahau builds its own. **"Save the *.esx"** writes it, and the footer names the attenuation area types it will write.
- A name the project already uses, an upper edge at or below the lower edge, or a missing or negative loss is refused with the reason shown in the dialog, and nothing is added.
- Attenuation areas stay separate from wall templates: a new type is saved in the project's own attenuation area list and is never part of a wall template.
- The button is greyed, with the reason beside it, on a project that has no attenuation area type to copy the file layout from.

## Verified

- The dialog is opened, refused on a duplicate name and saved through the controls' own handlers. The saved type carries the converted edges and loss, no `key`, and no `upperEdge` when it is left empty. Skipping the dirty flag that makes Save write the file, or dropping the duplicate-name check, turns the tests red.
- The suite passes.
