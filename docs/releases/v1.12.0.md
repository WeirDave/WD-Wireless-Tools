## Squirrel: Undo last organize

Every `execute()` call now writes a rollback log to `~/.wd_wireless_tools/organizer_undo/<sha1-of-root>.json` recording every successful move (`from` → `to`) plus every subfolder Squirrel created. The results screen shows an amber **"↶ Undo Last Organize (N)"** button; the hamburger menu also gets an "Undo last organize" entry that appears whenever a rollback log exists for the current root.

Undo walks the log in reverse:

- Moves each file back to its recorded original path.
- Skips (doesn't error) if the current file no longer exists or if the original slot is now occupied — reports those in the toast.
- Removes any subfolders Squirrel created, only if now empty.
- Deletes the log file so undo can't fire a second time.

The confirm dialog on the main organize also changed from "This cannot be undone from the UI" to "Use Undo on the results screen to reverse this."

**Also fires for grouping** — see below.

### Verified end-to-end

I created a real test folder at `C:\tmp\wd_organizer_test_5093` with 9 mixed files across 3 site prefixes (SITE3/SITE2/SITE4) plus 2 unrelated files. Full flow:

1. `set_folder` → scan finds 1 "root folder" entry with 9 loose files.
2. `execute` classifies them: 4 → images, 2 → floorplans, 3 → reports. Undo log: 9 moves + 3 created dirs.
3. On-disk verify: files in the three subfolders as expected.
4. `undo` restores all 9 files back to root, removes all 3 subfolders. Response: `restored: 9, skipped: 0, errors: 0, removed_dirs: 3`.
5. On-disk verify: back to the original flat layout.
6. Second `undo` refused with "Nothing to undo for this folder" — one-shot guard works.

## Squirrel: Suggest-grouping mode

If Squirrel scans a folder and finds only loose files (no site subfolders — the "Downloads dump" case the maintainer was hitting), it now silently checks whether those files share common name prefixes. If ≥ 2 files share a leading token of 3+ chars, the preview screen renders a blue suggestion banner:

> **Looks like N sites in one folder.** Squirrel found X files sharing common name prefixes — group them into subfolders first?
> `[Dismiss] [Group into subfolders]`

Below the banner, each detected group is a checkbox row: `[SITE3]  3 files  ·  [SITE2]  2 files  ·  [SITE4]  2 files`. The user can uncheck any group they don't want, then click Group. Squirrel creates one subfolder per checked prefix, moves the matching files in, and records the moves to the same undo log — so an accidental group can be undone the same way as a regular organize.

The prefix detection is deliberately conservative: it takes only the leading `[A-Za-z0-9]+` token from each filename stem (so `SITE3-photo1.jpg` → `SITE3`, `SITE3 site notes.txt` → `SITE3`), requires ≥ 3 chars, and requires ≥ 2 files sharing the prefix. Anything shorter or lonelier stays put. The banner reports how many "unmatched" files will stay put so users know the tool isn't going to guess wildly.

### Verified end-to-end

Same test folder as above. After `set_folder` + `doScan()`, `pendingGroupSuggestion` was populated with 3 candidates: SITE3 (3 files), SITE2 (2), SITE4 (2). Screenshot confirms the banner + group list render correctly above the normal preview table. Then:

1. `apply_grouping` with all 3 groups → 7 files moved, 3 subfolders created, undo log written.
2. On-disk verify: 3 subfolders each containing the right files; `some-random.jpg` and `unrelated-file.docx` stayed in root as expected.
3. `undo` restored all 7 files, removed the 3 subfolders. Original layout back.
