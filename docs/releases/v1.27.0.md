Squirrel picks up **custom destinations**. Alongside the built-in `images/` `floorplans/` `reports/` triad, you can now define your own destination subfolders — each with its own extension list and optional PDF / JSON keyword rules — and every scan, review, and execute flow honors them.

Suite `v1.26.1 → v1.27.0`. Squirrel `v1.17 → v1.18`.

## What's new

### The end-to-end flow

Open **Settings** in Squirrel. Below the "Destination folder names" section (which lets you rename the three built-ins) there's a new **Custom destinations** section. Click **+ Add destination** and fill four fields:

- **Folder name** — the on-disk subfolder that gets created inside each site folder (e.g. `raw-data`, `docs`, `screenshots`)
- **Extensions** — comma-separated, dots optional (`.csv, .tsv` or `csv, tsv`, either form works)
- **PDF keywords** *(optional)* — a PDF whose filename contains any of these words routes to this destination
- **JSON keywords** *(optional)* — same, for `.json` files

Extension matches for a custom destination take precedence over the built-in mapping. Route `.csv` into a new `raw-data/` folder and Squirrel will send it there instead of `reports/`.

Add as many rows as you want. The `✕` on the right removes a row. Save applies immediately; the next scan uses the new mapping.

### Under the hood

`folder_organizer.py` grew a `custom_destinations: []` list in the config schema and a new `_get_destinations(cfg)` helper that merges the three built-ins with the user's customs, returning a normalized list of `{key, name, exts, pdf_keywords, json_keywords, builtin}` dicts. Every place that previously hardcoded `["images", "floorplans", "reports"]` — the totals dicts in `scan()` and `execute()`, the subfolder-creation loop in `_execute_dir` and `create_project_folder`, the duplicate detector, and the "skip directory names" set — is now derived from that list. A dedicated `_effective_skip(cfg)` builder folds every destination name (including customs) into the skip set so scans never recurse into a managed folder.

The classifier walks custom destinations first for extension matching, so a custom claim like `.csv → raw-data` correctly overrides the built-in `.csv → reports`. PDFs and JSONs fall through to per-destination keyword lists. Unmatched PDFs still default to `floorplans/` (backward-compat); unmatched JSONs still stay in the root.

On the frontend, `organizer.js` grew a `destinationList(cfg)` helper that prefers `scanData.destinations` (the server is authoritative on ordering and custom names) with a client-side fallback. The **bulk-destination button row** is now a `<span id="bulkDestRow">` that gets repopulated on every render — three buttons for the built-ins, one more per custom. Summary chips and the per-row `<select>` dropdown also iterate the same list. A `.dest-custom` teal accent covers any non-builtin key.

### Config schema (before → after)

```json
// v1.26.1 (before)
{
  "image_ext":  [".png", ".jpg", ...],
  "plan_ext":   [".dwg", ...],
  "report_ext": [".docx", ...],
  "report_keywords":       ["report", ...],
  "json_report_keywords":  ["waxframe", ...],
  "subfolders":      ["images", "floorplans", "reports"],
  "subfolder_names": {"images":"images", "floorplans":"floorplans", "reports":"reports"}
}

// v1.27.0 (after — legacy fields kept for backward compat + rename UI)
{
  "image_ext":  [...],
  "plan_ext":   [...],
  "report_ext": [...],
  "report_keywords":       [...],
  "json_report_keywords":  [...],
  "subfolders":      ["images", "floorplans", "reports"],
  "subfolder_names": {...},
  "custom_destinations": [
    { "key": "raw-data", "name": "raw-data",
      "exts": [".csv", ".tsv"],
      "pdf_keywords": ["export"],
      "json_keywords": [] }
  ]
}
```

Zero migration. Existing configs load unchanged; `custom_destinations` just defaults to `[]`.

## User-visible behavior change

- Settings modal has a new **Custom destinations** section between "Destination folder names" and "Create Folder naming template."
- Preview screen's bulk-move buttons and per-file destination dropdowns now include your custom destinations, styled in teal.
- Summary chips show one chip per destination (including customs) with per-destination file counts.
- Custom-extension routing takes priority over built-in routing.
- Every site folder now gets subfolders for the customs too when `execute()` runs.

## Verification

1. Open Squirrel → Settings. Scroll to **Custom destinations**. Click **+ Add destination**. Type `raw-data` in Folder name and `.csv, .tsv` in Extensions. Save.
2. Reopen Settings. The row is still there with the same values.
3. Point Squirrel at a folder containing a `.csv` file at the root of a site directory. On the Preview screen, that file's destination should read `raw-data` (in teal), not `reports`.
4. Click **Apply Moves**. The site folder now contains a `raw-data/` subfolder next to the built-in three, with the CSV inside.
5. Set an override on a per-row `<select>` — the dropdown includes `raw-data` alongside the built-ins.
