WD Report's template picker used to be a wall of near-identical blue cards. Now every report has its own color — pill, accent stripe, "Best for" callout, and CTA button all matched — so at a glance you can tell the four ready reports from the three coming-soon ones, and each one from the next.

Suite `v1.23.0 → v1.24.0`. Report `v2.9 → v2.10`.

## What's new

### Per-template color treatment

Every card in the **Choose a report template** gallery now carries a signature color that runs through the whole card:

- **Directional Antenna Installation** — nav-blue (`--nav-blue`, the wayfinding blue).
- **Site Summary Sheet** — green (`--green`, the all-good executive summary).
- **Phone Hotspots Detected During Survey** — purple (`--purple`, matches the "security walk-around" framing).
- **Bill of Materials** — amber (`--amber`, the procurement / invoice tone).
- **Antenna Aim Sheet** — teal (`--teal`, precision / targeting). Still coming soon.
- **Change / Audit Report** — red (`--red`, deltas and warnings). Still coming soon.
- **Coverage Cell Boundary** — orange (`--orange`, signal spread). Still coming soon.

Each card gets a 3px top stripe in its accent color, plus the AVAILABLE / COMING SOON pill, the "Best for:" left-bar and tint, and (on ready cards) the **Use this template →** button all pulled from the same palette. Hover raises the card with a matching colored shadow.

### How it's wired

Four CSS custom properties per template — `--card-accent`, `--card-tint`, `--card-shadow`, `--card-accent-hover` — are set on a `.tpl-{id}` modifier class on the card element. Every downstream selector reads from those variables, so re-skinning any card is one block of CSS.

```css
.rep-template-card.tpl-summary {
  --card-accent: var(--green);
  --card-tint: rgba(95,171,79,0.10);
  --card-shadow: rgba(95,171,79,0.28);
  --card-accent-hover: var(--green-dark);
}
```

No new hex literals — every color pulls from the token palette established in v1.13.0 (see [[wd-tools-hex-palette]]).

### JS change

`renderTemplateGallery()` in `report.js` adds `tpl-<id>` alongside `is-coming-soon` / `is-selected` when building each card's class attribute. That's the entire JS-side change.

## User-visible behavior change

- The template picker gallery on `/report` now shows seven visually distinct cards instead of seven blue ones.
- Coming-soon cards still dim to 0.65 opacity but the top-stripe color stays solid — you can still tell aim from audit at a glance.
- Both dark and light themes verified. The rgba() tints are theme-neutral, so the same accent reads correctly on the dark navy surface and on the light white surface.

## Verification

1. Load `/report` and drop any `.esx` file, or navigate directly to the template stage. All four ready cards should show distinctly colored borders, pills, best-for bars, and CTA buttons.
2. Scroll down. The three coming-soon cards below should also carry their accent colors on the top stripe, pill, and best-for callout.
3. Hover a ready card. The border-color and box-shadow should shift to that card's accent, not to the generic nav-blue.
4. Toggle to light theme via the topbar. All seven cards should still read cleanly — the tint alpha is picked to work on both surface colors.
