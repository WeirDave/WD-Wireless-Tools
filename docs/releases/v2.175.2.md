# Squirrel Rename previews organized site folders, and no longer applies names with a blank token

Suite **2.175.2** ships **Squirrel 1.27.5**. The Rename page header shows the Squirrel number, not the suite number.

## What changed

### Squirrel → Rename (hamburger menu → **Rename…**, or `/squirrel/rename`)

- **The Preview panel now lists files that Organize has already moved into subfolders.** Organize files everything except the `.esx` into `images/`, `floorplans/`, `reports/` and any custom destinations. Rename used to look only at the top level of each site folder, so on an organized folder the preview came back empty:
  - **File Cleanup Rules** showed "No files change", because it skips `.esx` files and nothing else was left at the top level.
  - **File Convention** listed only the `.esx`.

  Both tabs now also check each site folder's destination subfolders, using the same destination list Organize uses. They pick up anything added under **Suite Settings → Subfolder Structure → "Custom destinations (for Squirrel sorting)"** automatically. Preview rows show the subfolder in the path, for example `Alpha Site/images/IMG_0001.jpg`. **Apply Rename** and **Undo** work on those files. There is nothing to turn on.

- **File Convention works without a CSV site directory** if the format only uses `{original}`, `{index}`, `{folder}` or `{date}`. Before, it refused with "No site directory loaded". If a format uses a token that needs the CSV, such as `{site_code}`, the error now names that token.

- **Folder Convention works without a CSV** if the format only uses `{folder}` or `{date}`. Before, it gave the same "No site directory loaded" error.

- **A token with no value is no longer applied.** On **Folder Convention** with no CSV loaded, a token field left empty used to preview as a normal rename, for example `Alpha Site` → `__site_code__ - Alpha Site`, and **Apply Rename** wrote that placeholder onto the folder.
  - These rows now show the new name struck through, with the warning "Missing value for {site_code}", and the Preview count adds "N needs a value".
  - **Apply Rename** skips them and renames only the complete rows. If every row is missing a value, the button stays disabled until the field is filled in.
  - The same applies to **File Convention**, and to a CSV row whose cell for that token is empty.

## Verified

- The Rename page was loaded in a headless browser against an invented organized project folder. Before the change, all three tabs showed either an empty preview or an error. After it, every file in `images/` and `floorplans/` appears in the preview.
- Automated tests send the page's own requests to the rename endpoints, covering subfolder preview, apply and undo inside `images/`, and the no-CSV modes. A separate test runs the page's own preview code to check that **Apply Rename** stays disabled when every row is missing a value. Each test fails against the previous code.
- The full test suite ran as part of the release build.

## Files changed

- `tools/rename_manager.py`: subfolder scanning, the no-CSV modes, and the missing-value row status
- `server.py`: the rename preview endpoints no longer default to "no subfolders"
- `web/assets/js/rename.js`: the Preview count includes rows that need a value
- `web/assets/wd-tools.css`: styling for rows that need a value
- `tests/test_rename_sees_organized_subfolders.py`, `tests/test_rename_blank_token_is_not_applied.py`: new tests
- `web/assets/versions.json`, `README.md`: version numbers
