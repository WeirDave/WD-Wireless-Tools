Two things landed together. **Antenna Aim Sheet** graduates from coming-soon to a real, printable report — the clipboard sheet your installers can carry between mount locations. And the Cloud Manager **Sites-tab External counter** now agrees with the filter, both counting the same thing.

Suite `v1.24.2 → v1.25.0`. Cloud Manager `v4.12.2 → v4.13.0`. Report `v2.10 → v2.11`.

## What's new

### 1. Antenna Aim Sheet, for real

The `aim` template card in the /report gallery has been a stub since v1.22.0 — teal preview, section descriptions, no actual renderer. It's live now.

**The sheet.** One flat table across every floor, sorted by floor then AP name, with these columns:

- **#** — row number (also printed on the mini-map so a row and its pin match)
- **AP name**
- **Floor**
- **Azimuth** — degrees + compass heading (`137° (SE)`)
- **Tilt** — degrees
- **Height** — meters, feet in parentheses (`3.05 m (10 ft)`)
- **Antenna** — antenna type name from Ekahau
- **Installer initials** — blank cell with a solid underline
- **Date** — blank cell with a solid underline

**Per-floor mini-maps.** Below the table, each floor with directional APs gets a compact overlay: the floor plan, a teal dot per AP, and a short direction tick pointing along the azimuth. Each pin is numbered to match its row upstairs. Ceiling-mount and omni APs get a dot with no tick. Page-break-inside: avoid so a mini-map doesn't get cut in half at a page break.

**Sidebar controls.**

- Per-floor mini-maps (default on)
- Sign-off columns (default on — turn off if you're keeping this digital and don't need the initial/date slots)
- Show mount heights in both units (default on)
- Show compass headings alongside azimuth (default on)
- Include directional APs (default on)
- Include omni APs (default off — this sheet is for aiming; omnis don't need aiming)

**Empty state.** If every AP in the project is omni and "Include omni APs" is off, the report renders a "No directional APs" hint instead of an empty table.

Under the hood, `renderAimReport(aps, opts, ctx)` follows the same shape as the other renderers — reuses `ctx.primaryRadio`, `ctx.compass`, `ctx.floorPlanForAp`, and the shared cover / inline header primitives. New CSS in `wd-tools.css`: `.rep-aim-mark` / `.rep-aim-tick` / `.rep-aim-dot` for the mini-map pins, `.rep-aim-signoff` for the blank underline cells, `.rep-aim-map-section { page-break-inside: avoid; }` for the printed output.

### 2. Sites-tab External counter finally agrees with the filter

v1.23.0 shipped the External dash-card. Numbers looked right on the Projects tab (31 externals) but the Sites tab showed 3, and clicking External on Sites hid some sites you'd expect to see. Two bugs, one root cause: the sites-tab tallied and filtered externals at the individual project level, but a Site row is a *container* — it can be the maintainer-owned at the top but contain teammate-owned child projects underneath, and vice versa.

**Fix.** New helper `_siteHasExternal(cloudObj, localObj)` returns true if either the site itself is teammate-owned OR any of its child projects are. On the Sites tab:

- **Dashboard count** uses `_siteHasExternal` per site row (no more double-counting via `walkKids`). So the External count reflects the number of site rows the filter will reveal.
- **Filter (`pass()`)** uses `_siteHasExternal` too, so clicking External surfaces every site that contains external content — including the maintainer-owned sites with teammate-owned children.
- `externalOrphans` (which subtracts from the Orphans count) is tallied only at the top-level site loops, not inside `walkKids`, so it doesn't over-subtract.

On the Projects tab, nothing changes — `_isExternal` at the project level was already right there.

## User-visible behavior change

- **/report**: the Antenna Aim Sheet card is now colored "Available" in teal, not "Coming soon." Clicking it walks you into Configure → Review like the other four ready templates.
- **/cloud** on the Sites tab: the External dash-card count matches the number of rows you get after clicking it. Sites that are the maintainer-owned at the top but contain teammate-owned children now correctly surface under the External filter.
