Cloud Manager: Auto-assign banner is now owner-filter-aware, aligned under the Cloud column, and reworded to match the question it's actually asking.

## Owner-filter bug — count now matches visible pills
With **Owner: Mine** active in v1.9.13 the banner would say something like "Auto-assign 16" while only 14 red pills were visible in the tree. The 2 phantom entries were unassigned cloud projects owned by other people — the owner filter hides them from the tree, but the banner's counter was walking every matched child regardless of filter. Confusing at a glance ("I only see 14 — where are the other 2?") and, if you clicked, the batch would try to assign projects you couldn't see.

Extracted `buildPassOwner(own, me)` as a module-level helper so the ledger renderer, `_collectAutoAssignable(visibleSiteRows, passOwner)`, and `autoAssignAllMatched()` all build the exact same owner-filter predicate. The banner now reflects only projects the tree is rendering pills for, and the batch assigns exactly that set.

**Verified across all three owner modes:**

| Owner filter | Banner count | Rendered pills | Match |
|---|---|---|---|
| All | 16 | 16 | ✓ |
| Mine | 14 | 14 | ✓ |
| Others | 2 | 2 | ✓ |

## Layout — banner now spans only the Cloud column
The banner used to stretch the full width of the ledger, right across the local column. The action is cloud-only — the local side isn't affected — so stretching over both columns misrepresented the scope. Switched the row layout from flex to CSS grid (`grid-template-columns: 1fr 140px 1fr`) so the banner cell tracks the exact width of the "Cloud Sites" header (flex was fighting the banner's padding + border via min-content behaviour that `box-sizing: border-box` couldn't defeat; grid tracks don't have that quirk).

## Copy + visual tie
- New wording, phrased as the question the user is actually being asked:
  > 📎 **Auto-assign 14** — 14 unassigned cloud projects match local files/folders but are not assigned to a site. Do you want to automatically assign them to a site?
- Button moved to the left of the text (was right-justified) so the primary action reads first.
- Paperclip icon (📎) now lives inside the batch button as well as on the per-row 📎 button, so the eye connects "batch action" with "row action" at a glance.
