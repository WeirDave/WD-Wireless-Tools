WD Cloud Manager — post-op refresh no longer blanks the ledger to "Loading…" between ops. The cloud-column-flash bug the maintainer hit way back is finally gone.

Suite `v1.9.31 → v1.9.32`. WD Cloud Manager `v4.6.7 → v4.6.8`.

## The bug

Every file operation (rename / delete / move / etc.) called `_scheduleOpRefresh()` after completing, which called `refreshData()` non-silent — and that path clears the `#rowsContainer` to `<div class="empty-msg">Loading…</div>` before firing the fetch. For the ~500ms it takes Ekahau to respond, the ledger was completely blank. The Operations Deck card showed the op completed, then the ledger disappeared, then reappeared with the new data. Jarring.

## The fix

Pass `silent=true` from `_scheduleOpRefresh()` to `refreshData()`. The silent path skips the "Loading…" placeholder and just does an in-place swap when the new data arrives.

User-initiated refreshes (menu → Refresh) still use non-silent so there's clear feedback that the app is fetching. Live-refresh cycles already used silent. Only the post-op path was non-silent, and it shouldn't have been — the deck card is the fetch feedback.

## Verified in the preview

MutationObserver on `#rowsContainer` while triggering `_scheduleOpRefresh()`: `sawLoadingFlash: false`. Content stayed intact from before → after. Byte-for-byte the same initial and final sample.

## Files changed

- `web/assets/js/cloud.js` — one-line change: `_scheduleOpRefresh` passes `true` (silent) to `refreshData()`.
- `web/assets/versions.json`, `web/cloud.html` — version chip bump.
