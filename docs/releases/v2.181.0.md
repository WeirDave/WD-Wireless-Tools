# Cloud Manager: a folder renamed on disk can be sent up to its cloud site, from Sync everything or the Projects tab

Suite **2.181.0** ships **Cloud Manager 4.73.0**. The Cloud Manager page shows the Cloud Manager number, not the suite number.

## What changed

### Cloud Manager: Projects tab, a project whose cloud site and local folder disagree

- **These rows now have a band beneath them with the controls to fix the difference.** Before this release, a project whose local folder had a different name from its cloud site showed both names on the row (the site under the cloud name, the folder under the local name) and offered no action. Renaming a folder on disk puts every project inside it in that state.
- **When the folder looks renamed**, the band reads "The folder … and the cloud site … are named differently, and every project in that site is in this folder, so the folder looks renamed." A folder counts as renamed when every project in the cloud site sits in that one folder, no local folder still carries the site's name, and no cloud site already has the folder's name. The band has two controls:
  - **"Rename cloud site to match"**, under the Cloud column and the recommended action, renames the cloud site to the folder's name. The projects in the site stay where they are, and every row for that site clears at once.
  - **"Rename folder to match"**, under the Local column, renames the folder back to the cloud site's name. The files inside it move with it.
- **When a single project was moved instead**, the band offers:
  - **"Move file to match"** (Local column), which moves the local `.esx` into the folder named after its cloud site and creates the folder if it is missing.
  - **"Move cloud project to match"** (Cloud column), which assigns the cloud project to the site named after the local folder. It is shown unavailable, with the reason, when no cloud site has that name or when the project belongs to somebody else. To create the site, use the **"Cloud site"** button on the folder's row on the **Sites** tab.
- Nothing needs to be turned on. Rows whose site and folder agree show no band, as before.
- The Sites tab already offered **Local → Cloud** on a site row whose folder had been renamed (since 2.177.0). That only works while the renamed folder still pairs with its site. After a larger rename the folder and the site show as unpaired on the Sites tab, and the Projects tab is now where they can be settled.

### Cloud Manager: Sync everything renames cloud sites to match renamed folders

- **Sync everything** (the blue button in the toolbar) now includes cloud sites whose local folder has a different name. Before this release it left folders out entirely, so after a folder was renamed in Explorer or Finder it reported "Local and cloud already match" and the cloud site kept its old name.
- These appear first in the Sync everything dialog, in a section headed **"Rename N cloud sites to match your folders"**, with one row per site showing the cloud site's current name and the folder name it will take. Each row has its own checkbox.
- Rows are ticked by default. A site paired with its folder only by similar wording (no shared site code) arrives **unticked**, with a line saying so; tick it after checking both names are the same site.
- The projects inside each site stay where they are. The rename can be reversed the same way, or with **Cloud → Local** on the site row.
- This works from the **Sites** (Tree) view, which is where folders and sites are paired.

### Cloud Manager: Expand all and Collapse all moved to the letter bar

- **Expand all** and **Collapse all** now sit at the left end of the A–Z letter bar, on the same line as the letters, instead of in the toolbar above. They still appear only in the Sites (Tree) view. When the bar wraps on a narrow window, the two buttons stay at the start of it.

## Verified

- New tests render real Projects-tab rows, read each control back out of the markup and run it against a recording server stub. **"Rename cloud site to match"** reaches the server as a rename of the cloud site to the folder's name. **"Rename folder to match"** reaches it as a rename of the folder to the site's name, with forward slashes even when the path came from Windows.
- A site whose projects are in more than one folder is never offered the site rename. Nor is a site whose old folder still exists, or one whose new name is already taken by another cloud site. Those rows get the move controls instead, and the cloud move is refused on another user's project.
- The listing now carries each project's site id and every cloud site's name, empty sites included. It still falls back to the dataset listing when the site list cannot be read.
- New tests run the real Sync everything end to end: the dialog is built, confirmed, and the ticks are read back off the checkboxes it rendered. A renamed folder reaches the server as a rename of its cloud site to the folder's name; a site paired on wording alone arrives unticked and is not renamed; a site whose name already agrees, and a project file, are left alone.
- The letter bar was rendered in Chromium at 1366 and 700 pixels wide: the two buttons sit at the left of the letters on one line, and the bar hides on the Duplicates tab and hides the buttons in the Flat view.
- Each new test was confirmed to fail with the change it covers reverted.
