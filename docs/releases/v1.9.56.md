Suite `v1.9.55 → v1.9.56`. WD Cloud Manager `v4.9.3 → v4.9.5`.

## Bulk Share button

New **Share…** button in the bulk toolbar (between Verify pairs and Delete selected). Opens a modal with:

- Multi-email textarea (comma / semicolon / space / newline separators, deduped) + role select — one API request per role tier adds every email to every owned selected project.
- "Share with your Sharing Group" toggle + role select — one API request applies the group to every selected project.
- Owner-gated: button only enables when the selection contains cloud projects you own; non-owned projects are silently skipped server-side.

Bulk group-share now does **OFF-then-ON** on the toggle-userGroup endpoint (2 API calls per batch, not per project) — guarantees the current group membership gets pushed to every affected project, since Ekahau doesn't auto-propagate group changes to already-shared projects.

## Sync group shares — one-click membership refresh

New chip in the share modal's group section, right beside "Manage members":

`Manage members (2) ▸    ↻ Sync group shares`

Clicking it:

1. Runs a dry-run to count affected projects (backend enumerates owned projects, cross-checks each via `list_project_shares` for a real `groupId` match — authoritative, not heuristic email overlap).
2. Confirms the count with the user.
3. Batches OFF-then-ON on the whole set in two API calls.

Result: after adding a teammate to your group, one click and every project that used to only share to a teammate now shares to both. On the maintainer's account this identified **83 affected projects** in a scan of 124.

The button lives in the sharing modal because that's where the mental model is — the natural flow is *add member → click Sync group shares → done*. An earlier iteration tried a toolbar chip too, but that was redundant.

## Danger Zone — quiet at rest, alarming when armed

Opening the share modal on a project you own used to show a big red "Danger Zone" section with "Transfer ownership — hand this project to another user…" copy. the maintainer: that's alarmist for the default view, since you probably opened the modal to do something completely different.

Now:

- **At rest**: a single compact row at the bottom — `Transfer ownership to  [Choose recipient…]  [Transfer…]`. No red container, no scary label. Just an available option, like every other control in the modal.
- **After clicking Transfer…**: the full red-framed container appears with `CONFIRM OWNERSHIP TRANSFER`, the warning about being demoted to View only + group associations breaking, and the big `Transfer to <email>` / `Cancel` buttons.

CSS-wise this is a `.is-armed` class toggle on `#shareDangerSlot` — same JS logic, different presentation depending on stage.

## Select All in Tree view now skips site headers

Previously clicking "All" in the toolbar checked every visible checkbox including site-level rows. Sites can't be shared/verified/etc — only projects can — so this inflated the "N selected" count and made bulk actions confusing. Now in Tree view, Select All only ticks tree-child (project) rows. In Flat view (where top-level rows ARE projects), behavior is unchanged.
