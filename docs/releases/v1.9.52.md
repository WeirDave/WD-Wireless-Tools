WD Cloud Manager — three new dashboard filter cards for the main Ekahau project types: Design / Measured / Hybrid. Click any one to narrow the ledger to just that kind of project.

Suite `v1.9.51 → v1.9.52`. WD Cloud Manager `v4.8.9 → v4.9.0`.

## the maintainer's ask

> "we also might want filters for 'Design' 'Hybrid' 'Measured'"

Straight follow-up to the Name Matches filter — same pattern, different axis. Instead of filtering by pair-state (matched / mismatched / orphan), these filter by project type (Ekahau's `SIMULATED_PROJECT` / `MEASURED_PROJECT` / `HYBRID_PROJECT`, which WD already surfaces as the purple/orange/teal `.ptype-tag` badges on every row).

## Cards

- **Design** — purple `#a855f7`, mirrors the existing `.ptype-tag.pt-design` background tone
- **Measured** — orange `#f59e0b`, mirrors `.ptype-tag.pt-measured`
- **Hybrid** — teal `#14b8a6`, mirrors `.ptype-tag.pt-hybrid`

Same three-line CSS pattern as every other filter card (border-color / hover / active tint), just with per-type colors.

**Count semantics** — a row counts if EITHER side (cloud OR local) reports that projectType. Matched pairs where the cloud says "Design" but the local .esx metadata is silent still count as Design. Owner-filter aware, same as every other count.

**Placement** — right after "Synced" in the dashboard row, before "No Site". State filters (matched/mismatch/orphan) → then Type filters → then context-specific cards (No Site, Duplicate variants).

**Filter behavior** — a row is shown iff either side's projectType equals the selected filter's type. Overrides all other state filters (radio-button style like every other filter). Cards mutually exclusive (clicking one deactivates whatever else was on).

**Tab gating** — Projects (Flat) view only. Sites (Tree) view hides all three cards; if a type filter was active, reverts to All. Same as Name Matches / No Site — project type is a per-project attribute, sites are aggregations.

## Verified in the preview

Steps run in the browser pane on the maintainer's real cloud:

1. Reloaded `/cloud`, version chip: `v4.9.0`.
2. Switched to Flat view — three type cards visible, counts: Design 81, Measured 27, Hybrid 14 → 122 total = full ledger (proof that every project is exactly one of the three types).
3. Clicked Hybrid — filter activated (`data-filter="type-hybrid"` shows `.active` class), ledger renders exactly 14 rows, every one carrying a Hybrid `.ptype-tag`, zero rows with any other type. Perfect predicate.
4. Cards use their palette colors as border (verified in DOM via the CSS class).

## Files changed

- `web/cloud.html` — three new `.dash-card` elements with `data-filter="type-<design|measured|hybrid>"`, hidden by default.
- `web/assets/js/cloud.js`:
  - `updateDashboard` — three new counters (`typeCount = { Design, Measured, Hybrid }`) using a `bumpType(a, b)` helper that prefers cloud's type but falls back to local. Applied to matched pairs + cloudOnly + localOnly rows.
  - `updateDashboard` — new show/hide + filter-revert block for the three cards, keyed off `isProj`.
  - `renderLedger` — new `typeFilter` derivation from `activeFilter` (`type-hybrid` → `Hybrid`); `pass()` now short-circuits to `rowMatchesType(row)` when a type filter is active.
- `web/assets/wd-tools.css` — three new `.dash-card.type-<design|measured|hybrid>` rules (border-color / hover / active tint) mirroring the existing `.ptype-tag` palette.
- `web/assets/versions.json`, `web/cloud.html` — version chip bump (minor cloud rev to 4.9.0 since it's a new dashboard capability, not a bugfix).
