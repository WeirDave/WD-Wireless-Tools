WD Cloud Manager — empty-letter alphabet placeholders only show on the "All" filter now. Filtered views (Local Only, Mismatches, Orphans, etc.) are clean.

Suite `v1.9.35 → v1.9.36`. WD Cloud Manager `v4.6.10 → v4.6.11`.

## The problem the maintainer hit

Clicked the Local Only filter chip. Result: 2 matching sites buried inside 25 dimmed empty letter placeholders — total 27 letter headers, 9× more chrome than content, tons of vertical scanning to find the two real rows.

The alphabet-completeness placeholders (added in v1.9.27) solved the jump-nav "dead click" and late-letter-scroll problems on the default view. But they're pure noise on any narrowed view — a status filter that leaves 2 hits shouldn't wrap them in 25 empty scaffolds.

## The fix

Skip empty-letter placeholders when a status filter (`mismatches`, `orphans`, `orphans-cloud`, `orphans-local`, `synced`) is active. Only the "All" default view still shows the full alphabet.

Rationale: filtered views are inherently narrow — the user already knows they're looking at a subset. Showing complete alphabetical scaffolding around a small result set is noise. The "All" view is where the full alphabet + jump-nav coverage matters most.

## Verified in the preview

| Filter | Total headers | Empty placeholders | Ledger height |
|---|---|---|---|
| All (baseline) | 28 | 11 | 9973 px |
| Local Only | 2 | 0 | 847 px |
| Orphans | 3 | 0 | (all real content) |
| Mismatches | 0 | 0 | (0 mismatches to show) |

Applied identically to both `renderSitesTree` and `renderLedger` (tree and flat views).
