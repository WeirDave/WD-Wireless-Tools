WD Cloud Manager — renames and deletes now show up in the Operations Deck so you actually see progress instead of a silent app while Ekahau thinks.

Suite `v1.9.21 → v1.9.22`. WD Cloud Manager `v4.5.3 → v4.5.4`.

## The gap the maintainer hit

Renamed a cloud project. Clicked OK. The app just… sat there. The user couldn't tell if the rename was in flight, if it had errored silently, or if he'd have to click again. The Live refresh eventually ticked and the new name appeared, but that's a bad UX — the deck was invented specifically to prevent this.

Turns out the deck was only wired up for cloud transfers (uploads, downloads, bulk sync). Everything else — per-row rename, per-row delete, bulk delete — still ran the old "call `pyApi` and toast when done" pattern, which shows nothing while the request is in flight.

## The fix — deck cards for renames + deletes

Every `syncRow`, `confirmRename`, and `confirmDelete` call path now goes through `opEnqueue`:

| Operation | Card title while running | Card title when done |
|---|---|---|
| Per-row rename (cloud) | *Renaming cloud to "…"* | *Renamed cloud to "…"* |
| Per-row rename (local) | *Renaming local to "…"* | *Renamed local to "…"* |
| Rename via dialog | *Renaming to "…"* | *Renamed to "…"* |
| Single delete (cloud site) | *Deleting cloud site* | *Deleted cloud site* |
| Single delete (cloud project) | *Deleting cloud project* | *Deleted cloud project* |
| Single delete (local) | *Deleting local file* | *Deleted local file* |
| Bulk delete | One card per item | One card per item |

The bulk delete now emits **one card per item** rather than a single "Deleting N items" card — same pattern the upload/download flows use, so users see which specific file is currently being processed and can spot which one errored if one does.

All cards use `pollBackend: false` (these ops are simple request/response, no backend progress endpoint) and `undoable: false` (deletes and renames are one-shot; if you renamed to the wrong thing you rename again, no destructive undo needed).

## Verified in the preview

Fired `syncRow` with a stubbed 1.5s fetch delay, confirmed deck body contents:

- During flight: `↻ Renaming local to "…" · Starting… · Cancel`
- After completion: `✓ Renamed local to "…" · Done · ×`

Card transitions from running (spinner + cancel) to done (check + dismiss) automatically as the op resolves.

- `web/assets/js/cloud.js` — `syncRow`, `confirmRename`, `confirmDelete` (both single and bulk paths) all wrapped in `opEnqueue`. Toast calls removed from the same paths — the deck card is the notification now.
