# Report: wide-beam antennas are treated as directional, and cones say when they cannot be drawn

Suite **2.250.0**, Report **2.80.0**. The other tools are unchanged.

## What changed

### Report

- **An antenna whose pattern is a beam is directional, whatever Ekahau's library label says.** Ekahau labels some wall-mount access points, such as a wide-beam outdoor model, as not directional while their stored radiation pattern peaks in one direction, with a half-power beam of roughly 100° and about 20 dB less gain behind it. Those access points were treated as omni: the **Antenna Aim Sheet** left them off, **AP Installation** and the **AP Placement Map** drew no cone, and the directional counts excluded them. They are now listed on the Aim Sheet with their azimuth and tilt, drawn as directional markers, and given an aiming cone along the azimuth set in Ekahau. An antenna counts as directional by pattern when the horizontal pattern differs by at least 10 dB between its loudest and quietest direction and the arc within 3 dB of the peak is no wider than 200°. A flat pattern, a gentle lean, and a notch behind an otherwise round pattern all stay omni. An antenna Ekahau labels directional is never overruled.
- **The Antenna specs reference shows beam widths for those antennas.** The project file stores no beam width, only the pattern, so the horizontal and vertical widths are measured from it and printed with a leading "~", for example "~96° h-beam". A width stored in the file is printed as stored, without the "~". Projects that contain only omni antennas still show no beam widths, and the **Antenna specs reference** option stays unavailable for them.
- **AP Installation has a "Show aiming cones on directional APs" option.** It is in the options panel, below **Show channel & TX power columns**, and is on by default. Switching it off removes the cones from the maps.
- **A directional AP that has no cone is named under its map.** A cone is drawn from the azimuth stored in the project. When a directional antenna has none, the map keeps the directional marker and a note reads, for example, "2 directional APs have no azimuth saved in the project, so no aiming cone is drawn for them: AP-101, AP-102. Set the antenna direction in Ekahau and run the report again." Up to twelve names are listed, then the remainder is counted. The note appears under whole-floor maps and under the section index of a floor split into sections, on **AP Installation** and on the **AP Placement Map** when its **Show aiming cones on directional APs** option is on.
- **The map key agrees with the markers.** A directional AP with no azimuth was drawn as a directional marker but its colour was listed under the omni swatch. It is now listed under **Directional antenna**, and the key adds "(the cone points the way it is aimed)" when a cone is drawn.
- The **User Manual** has a new **Aiming cones** section.

## Verified

- The full suite passes. New tests build invented antennas with a stored pattern and check that a beam labelled omni is listed on the Aim Sheet and drawn with a cone at its azimuth, that a flat pattern, a gentle lean and a deep notch behind a round pattern stay omni, that a label of directional is kept, that measured beam widths are printed with "~" and stored ones without, and that an omni-only project still has no beam widths. Further tests render the real **AP Installation** report and check the cone option, the note on whole-floor and sectioned maps, the twelve-name cut, the silence when there is nothing to report, and the key. Each fails when the rule it covers is removed.
- The classification was also run on the antenna and radio records of a real wide-beam project: the access point is listed on the Aim Sheet and drawn with a cone at its stored azimuth.
