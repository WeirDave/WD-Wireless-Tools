WD Cloud Manager — Manage Sharing modal title now includes the project name, and every role dropdown surfaces Ekahau's own role descriptions as hover tooltips.

Suite `v1.9.49 → v1.9.50`. WD Cloud Manager `v4.8.7 → v4.8.8`.

## the maintainer's ask

Both polish items I flagged at end of v1.9.49 — the maintainer: *"Yes please fix teh nice to haves"*.

## Modal title carries project name

Previously the modal just said "Manage Sharing" — fine when you have one modal open, less fine when the project name is out of sight and you have several in your head. Now the title reads `Manage Sharing — <projectName>` (falls back to `Manage Sharing` if the caller doesn't pass a name — belt & braces).

Implementation: added `id="shareModalTitle"` to the h3, then `openManageShares(projectId, projectName)` sets `textContent` to the new format on every open. The caller already had `projectName` (from the share-btn's onclick), just wasn't using it visually.

## Role descriptions on hover

Every role `<option>` now carries a `title` attribute with Ekahau's own canonical description (from the screenshot the maintainer shared earlier). Native `<option title="...">` renders as a browser tooltip on hover — ugly-native but universally supported, no custom picker component. Applied at every share-role site:

- Per-user role dropdown in share modal
- Group toggle role dropdown
- "Share with someone" outer form dropdown
- Owner pill (also gets a description tooltip)

New helper `_roleOption(value, currentValue)` builds each `<option>` with the correct label + tooltip + `selected` state, so the four sites stay in sync via one function. New `SHARE_ROLE_DESC` map alongside the existing `SHARE_ROLE_LABEL` map:

| Role              | Description                                              |
|-------------------|----------------------------------------------------------|
| OWNER             | Owns the project — can transfer ownership to any current member |
| WRITE_SHARE_USER  | Complete control over project and settings               |
| WRITE_USER        | Collaborative access without sharing privileges          |
| READ_USER         | Read-only access with option to create a copy            |
