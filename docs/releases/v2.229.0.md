# The Windows launcher opens as a Windows Terminal tab

Suite **2.229.0**. Every tool is unchanged.

## What changed

### Launcher (Windows)

- **`Start WD Wireless Tools.bat` opens in a tab of the Windows Terminal window already on screen.** It runs `wt.exe -w 0 new-tab`, which uses the most recently used Windows Terminal window and starts one when none is open. The window the launcher was double-clicked in closes once the tab is running.
- **A launcher started inside a terminal runs there.** Typed into an open PowerShell tab, started from a Windows Terminal tab, or started from VS Code's terminal, it keeps running in that window or tab and opens nothing new.
- **A restart opens a fresh tab and closes the old one.** The old tab ends with a clean exit, so Windows Terminal closes it instead of leaving it open at "process exited".
- **Nothing changes without Windows Terminal.** With no `wt.exe`, on macOS, or with the setting off, the launcher behaves exactly as before.

### Settings

- **New: "Open the launcher in a Windows Terminal tab"** under **Settings → General**. It is on by default. Turn it off to always run in the window the launcher was started from. It applies the next time the suite starts or restarts.

## Verified

- Each rule for when the launcher hands off is driven through the real function and turns its test red when removed: already inside Windows Terminal, inside another terminal, the `--in-tab` guard, the setting off, no `wt.exe`, not Windows, and a `;` in the install path.
- The tab command is asserted argument by argument. A `wt.exe` that fails to start leaves the launcher running in place. The restart path is run with the OS and process exit replaced, both when the tab opens and when it does not.
- The setting ships on, reads back as off through the real settings loader, and an unreadable settings file leaves it on. The Settings page shows the saved value and sends it back on save.
- The suite passes.
