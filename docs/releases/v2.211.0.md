# Cloud Manager sees a local edit even when the date inside the file does not move

Suite **2.211.0**: Cloud Manager **4.82.0**. Every other tool is unchanged.

## What changed

### Cloud Manager

- **A local copy saved after it was downloaded now shows as changed.** Cloud Manager decided which side was newer only from the date stored inside each `.esx` (`history.modifiedAt`). A save that did not update that date left the pair looking in step. Downloading, pulling and pushing now also record the local file's size. A size that has changed while the date has not counts as a local edit: the row shows **"Local newer · replace cloud"**, and the detail line reads *"Your local copy has been saved since it was last synced, although the date inside it did not change."* If the cloud copy has also changed, the pair is reported as changed on both sides and left out of **Sync everything**.
- **"Download over local" no longer overwrites such an edit.** The pull refuses with the same "local is newer" message it already gives when the local date is later, and the local file is left untouched.
- **Plain downloads are now sync points.** A project downloaded into a site folder is recorded as matching its cloud copy, so the first edit after a download can be detected. Previously only a pull or a push recorded this.
- **A stored "Check what differs" result is discarded after such an edit**, so a "same design" verdict from before the save no longer stays on the row.
- **Applies from the next sync of each pair.** Pairs last synced by an earlier version have no recorded size and are judged by their dates, as before.

## Verified

- A synthetic project downloaded through the real download path, then rewritten with the same internal date and a different size, is listed as "Local newer" with the local side changed. A pull against it is refused and the file's bytes are unchanged. An untouched download still lists as in step and still pulls.
- The row's detail line is rendered with the real function in Node. The new tests fail when the size check, the download's sync point, the pull refusal, the listing change or the row text is removed.
- The full test suite passes.

- `tools/cloud_manager.py`: the listing, the pull guard and the download use it
