## 1. Immediate click feedback

The Sync group shares chip now transitions the moment you click it:

- Button goes from `↻ Sync group shares` → `↻ Checking…` (disabled)
- Toast fires: *"Checking which projects share the group…"*

The backend dry-run does one `list_project_shares` API call per candidate project (85+ on the maintainer's cloud, ~150ms each = 15-30s total). Without visible feedback users assume the click didn't register and click again. Now the state is unambiguous.

## 2. Picker modal (replaces native confirm)

Once the dry-run resolves, WD opens a proper modal instead of a native `confirm()` dialog:

- **Title**: `Sync "My Sharing Group" — N projects`
- **Sub**: *"Your group has M members. These are all the projects you own that currently share the group. Uncheck any you want to skip."*
- **Toolbar**: `Select all` / `Select none` quick-toggle buttons + live count `N of M selected`
- **List**: one row per affected project, each with a checkbox (all checked by default) + the real project name (cross-referenced against the loaded ledger data)
- **Note at the bottom**: *"Everything you check gets an OFF-then-ON group-share toggle, which pushes the current group members to that project. Anything you uncheck is left as-is. You can still individually toggle the group off on any specific project later via that project's share modal."*
- **Actions**: `Cancel` / `Sync selected` (or `Sync all N` when everything is checked). Button disabled when 0 are selected.

The three-tier control model the maintainer described is now complete:

- **Global**: click the chip, hit `Sync all N` — one click, done.
- **Batch subset**: uncheck the ones you want to skip, hit `Sync N selected`.
- **Individual**: use each project's own share modal group toggle for one-off changes.

## 3. Backend `refresh_group_shares` accepts a subset

Signature grew a `project_ids` parameter:

```python
def refresh_group_shares(self, group_name="My Sharing Group", dry_run=False, project_ids=None):
```

When provided, skips the auto-discovery pass and only operates on those IDs — still ownership-validated per project so a stale or malicious frontend list can't drive shares we don't own. The picker modal uses this to commit exactly the user's checked set.

## Frontend cross-reference walker fix

While building the picker, hit two bugs worth documenting:

- `window.data` was `undefined` because `data` is a module-scoped `let`. Changed the check to `typeof data !== 'undefined'`.
- The walker only recursed into `data.matched` and `data.cloudOnly`, missing projects that live under `data.localOnly[i].children` (cross-tree matches where an unassigned cloud project was paired to a local .esx) and `data.orphans` (top-level cloud projects with no site parent). Expanded to walk both. Confirmed sample-project.esx now resolves to its real name in the picker.
