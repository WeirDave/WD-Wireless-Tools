# Updating no longer leaves a full copy of the app beside the install

Suite **2.175.7**. No individual tool's version changed; this is the updater, which every tool shares.

## What changed

### Updating (Menu → About & Updates → **Update now**, `install.ps1` and `install.sh`)

- **The copy of the install folder made during an update is now removed once the update succeeds.** Before this, every update of an install set up from a ZIP left a full copy of the app next to the install folder, named `<folder>.previous-v<old version>-<date>-<time>`, and nothing ever deleted them. The same applies to **Switch to git updates** under **Other ways to update** on the same panel.
- **If an update fails partway through, the copy is still kept.** The error names where it is, because at that point it is the only complete version on disk.
- **Copies left by earlier updates are not deleted.** They are ordinary folders beside the install folder, each holding an older version of the app; nothing reads them, and they can be deleted by hand. Settings, templates and logs are not in them. Those live in the `.wd_wireless_tools` folder in the user's home folder.
- Installs that update through git never made this copy and are unchanged. Nothing needs to be turned on.

## Verified

- An update was run end to end against a real release archive. On success the install held the new version and no copy was left beside it. With the install made to fail partway through, the copy was kept, held the version being replaced, and was named in the error.
- Automated tests cover both cases, and each fails if the behaviour is reversed.

## Files changed

- `tools/updater.py`: removes the copy after a successful update or switch, and keeps it on failure
- `install.ps1`, `install.sh`: the same for the command-line installers
- `web/assets/js/wd-shared.js`: the About panel no longer promises a kept copy, and names one only if it could not be removed
- `docs/USER_MANUAL.md`: the Update section describes the new behaviour
- `tests/test_release_archive_paths_are_contained.py`, `tests/test_zip_update_installs_only_what_it_verified.py`: success and failure cases
- `web/assets/versions.json`, `README.md`: version numbers
