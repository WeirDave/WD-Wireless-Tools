WD Report Phone Hotspots — floor plan overlays now auto-crop to the actual drawn content, so oversized Ekahau canvases stop rendering as tiny drawings in a sea of white.

## The problem
the maintainer loaded SITE-001 F102 into the report and the two floor plan overlays showed the building drawing as a small centered rectangle inside a huge white container. Pixel scan confirmed the source `.esx` image (5000×3750) has the actual building drawing occupying only 26%×40% (Floor 2) and 20%×32% (Floor 1) of the pixels — the rest is white. Same story on many other files: Ekahau saves floor plans on an oversized canvas and the drawing lands wherever the source PDF originally sat.

The v2.3 render was technically correct (image filled the container edge-to-edge) but the content the reader actually wants to see was tiny.

## The fix — auto-crop overlay to non-white content ∪ walk-path extent
New `postRender` hook on the hotspot report runs after the report HTML lands:

1. Downsample the floor plan image (longest side to 500 px) into an offscreen canvas.
2. Scan pixels for the bbox of anything not "near-white" (any channel < 245 — allows JPEG noise and antialiased edges).
3. Union that bbox with the extent of the walk-path polylines already drawn on top, so we never crop off a survey walk that went into the whitespace margin.
4. Add 2% padding, clamp to the source canvas.
5. If the crop bbox is < 90% of either width or height, replace the img with a JPEG blob URL of the cropped region (downscaled to 2000 px longest side) and shift the SVG viewBox to the crop rect so the polylines still map correctly.

New sidebar option `Auto-crop empty margins around each floor plan` (on by default). Users can disable it if their floor plan legitimately has empty regions they want visible (e.g., outdoor site walks across parking lots).

## Registry plumbing
The main `renderReport()` now looks for an optional `postRender` function on the current report and calls it with `(host, opts, ctx)` after `host.innerHTML = r.render(...)`. This is generic — future reports can hook it too.
