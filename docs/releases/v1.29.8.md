Cloud Manager no longer keeps an Ekahau Cloud session in a readable JSON file. **v1.29.8 encrypts the saved session and protects its encryption key with Windows Credential Manager or macOS Keychain**, while preserving the same automatic browser-login workflow.

Existing users are migrated automatically. Cloud Manager verifies that the new encrypted cache can be decrypted before removing the old plaintext file, and an interrupted migration safely finishes on the next launch.

Suite `v1.29.7 → v1.29.8`. Cloud Manager `v4.13.1 → v4.13.2`.

## What's new

### Cross-platform secure session storage

- The session cookie jar is encrypted with authenticated encryption before it is written to `~/.wd_wireless_tools/cookies.enc`.
- A small random encryption key—not the cookie jar—is stored in Windows Credential Manager or macOS Keychain through the maintained Python `keyring` integration.
- Keeping only the key in the system vault avoids Windows Credential Manager's payload-size ceiling as Ekahau's browser cookie set changes.
- A modified or damaged encrypted file is rejected instead of being treated as a valid login.
- If secure storage is unavailable, a newly discovered browser session remains memory-only. Cloud Manager never silently recreates the old plaintext cache.

### Safe automatic migration

On the first launch after upgrading, Cloud Manager:

1. Reads the existing `cookies.json` session locally.
2. Creates or retrieves the per-user encryption key from the operating system vault.
3. Writes the encrypted cache atomically.
4. Reads it back, decrypts it, and verifies the complete cookie payload.
5. Deletes the plaintext file only after that verification succeeds.

If the vault cannot be reached or the write cannot be verified, the plaintext file is retained so the migration can be retried rather than destroying a working login.

### Forget Cloud Login

Cloud Manager's main menu now includes **Forget Cloud Login**. After confirmation, it disconnects the current process and removes the encrypted cache, any remaining legacy cache, and the corresponding system-vault key. The browser login remains available whenever the user wants to reconnect.

## Platform support

- **Windows:** Windows Credential Manager, verified with the native `WinVaultKeyring` backend.
- **macOS:** macOS Keychain through the same supported keyring interface; `run.command` installs and checks the required packages automatically.

Safari browser-cookie extraction is still not supported. Mac users should remain logged into Ekahau Cloud in Chrome, Edge, or Firefox, just as before.
