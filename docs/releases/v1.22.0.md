## What's new

Three additional entries in the Report gallery, all `status: 'coming-soon'`:

### 1. Antenna Aim Sheet (purple)

A single flat table designed for **the installer's clipboard, not the binder**. One row per AP with `Floor · Azimuth (with compass) · Tilt · Mount height · Antenna model`, plus a compact per-floor mini-map at the bottom, plus an initials + date column so the printed sheet doubles as an as-built.

Best for: on-site installers who want one page they can carry between mount locations.

### 2. Change / Audit Report (green + amber)

Diff two `.esx` files (or two survey rounds of the same project). Sections:

- **Compare stats** — Before/after side-by-side: AP counts, radios, floor counts, band mix. Deltas rendered with signed arrows.
- **Added / removed / moved** — One row per change with AP name, floor, and what changed.
- **Overlay diff** — Per-floor overlay showing removed APs faded, unchanged green, moved with a dotted line to the new position, added bright orange.

Best for: post-remediation write-ups, redesign hand-offs, "prove we did what we said" audits.

### 3. Coverage Cell Boundary (teal)

Per-floor overlay showing each AP's coverage cell:

- **Cell diagram** — Translucent circle per AP sized by estimated primary-service radius. Overlapping circles show handoff zones.
- **Signal-strength bands** — Concentric rings per AP (strong / good / fair / weak, dBm thresholds tied to real Cisco/Ekahau defaults).
- **Utilization notes** — Estimated client-count per cell based on radio power + antenna gain + walk-path density.

Best for: client presentations, capacity conversations, "why do we need N APs on this floor" justifications.

## Why ship the stubs before rendering

Every real WD Report already shipped (Antenna → Site Summary → BOM → Hotspot) started as a stub in the gallery. Having the coming-soon card visible means:

1. the maintainer sees the direction the tool is heading each time he opens the Report gallery.
2. If any of the three doesn't feel right, he can flag it before I burn hours on rendering.
3. When one lands as `ready`, the change is visible: the "Coming soon" chip flips to "Available" and the button becomes clickable.

Full rendering for each of these is 4-10 hours depending on Ekahau data availability. Change/Audit especially depends on comparing two `.esx` files, which needs a UI flow to pick the second file. Best to confirm priority before building.
