# Prep: the wall-type list shows which types are Ekahau defaults, and drawing a box is explained

Suite **2.238.0**. Prep **2.9.0**. Other tools are unchanged.

## What changed

### Prep: Wall types stage

- **The wall-type list now separates Ekahau's default types from the types only the template carries.** Open **3 · Wall types** and the list under the template picker has two groups: **Ekahau default types** (the types every Ekahau project starts with) and **Only in this template**. Each group states how many types it holds and how many are to be added, updated or already match.
- **Every type is a row with a swatch of its colour and a badge.** **Add** marks a type the project does not have, **Update** a type the project has that the template changes, and **Matches** a type that is already exactly as the template has it. Previously only the types that would change were listed, as plain names.
- **An update says what it changes.** The line under the name reads, for example, "changes colour, number key". The possible items are name, colour, number key, attenuation, thickness, height and other settings. When the project calls the type by an older Ekahau name, the row also gives that name.
- **What Prepare writes is unchanged.** The same types are added and updated as before; only the preview is different.

### Prep: Trim stage

- **A new note, "Drawing a box, and getting around the plan", is at the top of the Trim panel.** It explains the four things that were not stated anywhere together:
  - A box is drawn by pressing on one corner, dragging to the opposite corner and releasing. A click without dragging draws nothing.
  - Holding **Space** turns the cursor into a hand, and dragging then moves the plan. Dragging with the middle or right mouse button does the same. **Space** has to be held before the mouse button is pressed; it cannot be added part-way through drawing a box.
  - The mouse wheel zooms at the pointer and does not scroll the plan.
  - A box larger than the zoomed view is drawn roughly, then each corner is brought into view with **Space** and dragged into place by its handle.
- **The hint under the plan now says how to move the plan.** It names **Space** and the hand cursor instead of "Space-drag".

## Verified

- The wall-type plan is built from the two templates that ship (the WD template onto Ekahau's defaults). Every template type appears exactly once, the types Ekahau does not ship are exactly the ones marked as the template's own, and each kind of difference produces its own label.
- The real renderer is run over that plan. Each type lands in the correct group, every row carries its colour, a name or colour containing markup is neither rendered nor passed into a style, and a response that does not say which types are Ekahau's still lists the names.
- Changing the stock-type test or the grouping makes those tests fail.
- The list and the new note were checked in the dark and light themes.
- The full suite passes.
