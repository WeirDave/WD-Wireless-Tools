WD Cloud Manager — the row itself now highlights red when a Verify operation fails on it. Visual pointer to the deck-card error, cleared when you dismiss the card via **Clear done**.

Suite `v1.9.42 → v1.9.43`. WD Cloud Manager `v4.8.0 → v4.8.1`.

## the maintainer's ask

Verify skipped a "local newer than cloud" case correctly (great — data-safe). The deck card stayed put until dismissed (great — no fleeting error). But the specific row on the ledger that failed wasn't visually distinguishable from its neighbors, so tracking the deck error back to the offending row took some hunting.

## The fix

A `_verifyFailedPairs` Set holds pair keys (`cloudId||normalized-localPath`) for any verify op that errored. When populated, both the tree and flat row renderers add a `.verify-failed` class to the matching row, which paints:

- Background: red at 14% opacity (dark) / 10% (light)
- Left border: solid `--red` 3px

Row lifecycle mirrors the deck card:
- **Set** when the verify op's `run()` throws (both per-row `verifyReplaceLocal` and bulk `bulkVerifyNameMatches` paths). Immediate `renderRows()` after so the highlight appears the same instant the deck card does.
- **Cleared** when the user hits the deck's existing **Clear done** button (`_deckClearDone` now clears the Set and re-renders). If a user runs verify again on the same pair and it succeeds, the row also re-renders sans class because the pair key stops being in the set on next add-only cycle.

## Bug caught during verification

First implementation stored raw `localPath` in the key, but the onclick handler passes local paths through `pj()` which converts Windows backslashes to forward slashes. The row-renderer's lookup used the raw backslash path, so the two never matched and the highlight silently didn't appear. Fixed by normalizing to forward slashes in a shared `_verifyFailedKey(cloudId, localPath)` helper used by both add and lookup.

## Verified in the preview

- Marked a real name-match pair as failed via `_markVerifyFailed`. Row gained `.verify-failed` class, `backgroundColor` computed to `rgba(220, 38, 38, 0.14)`, `borderLeftColor` to `rgb(220, 38, 38)`.
- Called `_deckClearDone`. Row lost the class, background back to normal `rgb(24, 33, 44)`.
