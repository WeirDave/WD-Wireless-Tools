WD Cloud Manager — dashboard filter cards are now alphabetized (All stays first), and the Synced card is retired.

Suite `v1.9.54 → v1.9.55`. WD Cloud Manager `v4.9.2 → v4.9.3`.

## the maintainer's ask

> "Can you put the filters in alphabetical order please also not sure why we still need synced"

Both changes together in one release.

## Alphabetized order

Old order was rough: All, Mismatches, Name Matches, Orphans, Cloud Only, Local Only, Synced, Design, Measured, Hybrid, No Site. Adjacency was accidental (mostly ship-order over successive releases). Alphabetizing means users can scan-to-find without knowing the growth history.

New order (with counts from the field-test):

| # | Card         | Filter        | Count |
|---|--------------|---------------|-------|
| 1 | All          | `all`          | 124   |
| 2 | Cloud Only   | `orphans-cloud` | 1    |
| 3 | Design       | `type-design`   | 54    |
| 4 | Hybrid       | `type-hybrid`   | 13    |
| 5 | Local Only   | `orphans-local` | 2     |
| 6 | Measured     | `type-measured` | 27    |
| 7 | Mismatches   | `mismatches`    | 1     |
| 8 | Name Matches | `name-matches`  | 4     |
| 9 | No Site      | `unassigned`    | (Projects tab) |
| 10 | Orphans     | `orphans`       | 3     |

The Duplicates tab's cards (Clusters / Cloud-Only Clusters / Local-Only Clusters / Mixed Clusters) also alphabetized on the same rule — Clusters stays first as the summary/reset, the rest sort.

Note: "All" stays first as the neutral reset — even though alphabetically "A" would still put it near the top, its role is functionally distinct (no filter applied) so anchoring it as first regardless of alphabetization is intentional.

## Synced retired

The Synced card counted matched-and-not-mismatched pairs — the default "everything looks fine" bucket. On any real ledger this is 80–95% of the total, so it's essentially "everything except the interesting subsets" — same info the All card conveys minus the noise. Never seen the click, and every state you might want to see synced rows in (browsing, comparing, verifying) works from All anyway.

- Card removed from the dashboard row.
- `dSynced` count assignment removed from `updateDashboard`.
- `.dash-card.matched` removed from the `stdCards` visibility list (it's what the Synced card used).
- `pass()` in `renderLedger` — `showSynced` now unconditionally tied to `activeFilter === 'all'`; you can't select "only synced" anymore but synced rows still show under All (unchanged default behaviour).
- `setFilter('synced')` is guarded: passes through to `'all'` if anyone ever calls it (stale in-memory or URL) so nothing breaks.
