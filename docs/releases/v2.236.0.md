# The restart screen after an update lists the release notes of what was installed

Suite **2.236.0**. No tool version changes; every tool is unchanged.

## What changed

### About window (**About** in any tool's menu): after an update installs

- **The release notes stay on screen at "Restart to finish".** Before, the list headed **What's new since your version** was shown only above the update button (**Update now**, **Download and install update** or **Pull now**) and disappeared the moment the update ran. The same list now appears below the **Restart to finish** button, headed **What's new in this update**, so the notes can be read before restarting. Each release is a collapsible entry with the newest open, as before, and the list scrolls inside its own box so the button stays in view.
- **Only what was installed is listed.** A release newer than the version the update actually landed on is left out.
- **A pull that brought commits but did not change the version number shows no list.** There is nothing new to describe, and the screen says so as before.
- **A "Full release history" link** below the list opens the GitHub releases page for every earlier release.
- **The notes list loads once.** Pressing the update button before the list had finished loading could draw it twice, the second time under the heading for the earlier screen. The list is now loaded once and only the current screen draws it.

## Verified

- The About window is opened in Chrome, Edge and Firefox with five invented releases offered. The update button is pressed with the install request answered by a stand-in, and the restart screen is read: the list sits after the **Restart to finish** button, is headed "What's new in this update (5 releases)", and links to the releases page. When the install reports an older version than the newest release offered, that newest release is not listed. When the version does not change, no list and no link are shown. With the change removed, the first two checks fail in all three browsers.
