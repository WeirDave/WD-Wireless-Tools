# Cloud downloads now include survey signal and noise samples; files missing them are flagged

Suite **2.236.0**. Cloud Manager **4.91.0**. Other tools are unchanged.

## What changed

### Cloud Manager: downloads

- **Downloaded projects now contain every survey's signal-strength and noise samples.** A survey's samples are separate files inside the `.esx` (`track-<id>.bin` for each Wi-Fi track, `spectrum-<id>.bin` for each spectrum chunk, and `wcs-<id>.csv` for a Cisco radio-mapping file). Cloud Manager previously downloaded the project data and floor plan images only, so every `.esx` it downloaded, pulled over a local file, or synced back after an upload kept its survey records and had none of the samples they refer to. Each survey is now written as its own `survey-<id>.json`, as Ekahau writes it, instead of a single `surveys.json`. Surveys marked deleted in the cloud are left out.
- **An incomplete download is an error, not a file.** If any sample file cannot be fetched, the download fails with the name of the file, and nothing on disk is changed. The finished archive is also checked against its own survey records before it is saved.
- **Progress counts every file.** The progress line reads, for example, "Downloading 3 floor plan images and 40 survey files…" and "Downloading file 12 of 43…".

### Cloud Manager: finding files that are already missing data

- **A local file whose surveys refer to missing samples is marked on its row** in the Projects list: *Survey data is missing from this local file: N files …*. The marker is read from the file itself, so it appears even when the file's date matches the cloud's.
- **Re-download survey data** (on that row) takes the cloud copy over the local file. It uses the same safeguards as the existing download: a local file that is newer than the cloud copy is not overwritten.
- **Out-of-step counts include these files.** The list's out-of-sync filter and site totals count a file missing survey data even when the dates agree.
- **Sync everything** now lists these files under *Replace local files with the cloud copy*, with the verdict *survey data missing*, where previously they were counted as already matching.
- **A newer local file that is missing survey data is not sent up by Sync everything.** The dialog names it and explains why. On its own row, **Local newer · replace cloud** asks for confirmation first, states how many sample files are missing, and says the cloud project will be deleted; confirming proceeds as before.

### Cloud Manager: Check what differs

- **Two copies that are both missing the same samples are no longer reported as identical.** The result now says *Survey data is incomplete: the local file is missing N survey files its surveys refer to …* and does not count as settled. When only one side is missing files, that side is named, and the missing files appear in the list of differences.

## Re-downloading existing files

Files downloaded before this version remain without their samples until they are downloaded again. Use **Re-download survey data** on a marked row, or **Sync everything** and tick the listed files. If a re-download fails because a sample file cannot be fetched, the local file is left as it was.

## Verified

- The download test runs the real `download_project` against a fake Ekahau that serves different bytes for every file, and checks each sample file arrives under the right name with the right bytes, that deleted surveys fetch nothing, and that a failed fetch returns an error and no archive.
- A pull test replaces a short local file through the real `verify_replace_local` and confirms the result contains every sample file; a second confirms a failed fetch leaves the local file untouched.
- The rule for what a file should contain was run over real Ekahau-saved `.esx` files that contain surveys: none were reported as missing data, and a Cloud Manager download made before this version was.
- The row, the Sync everything plan, the out-of-sync count and the replace confirmation are each driven through the real `cloud.js`. Each of six deliberate breakages fails its test.
- The full suite passes.
