# Prep: floors that already have devices, from the saved default

Suite **2.183.0** ships **Prep 1.13.0**. The Prep page shows the Prep number, not the suite number.

## What changed

### Prep → Put a requirement area on every floor

- **Prep can now replace the devices on a floor that already has them.** Before this release Prep always kept such a floor as it was, whatever was chosen in Capacity or saved in Settings.
- **Where it is:** Prep, step **1 — What to do**, **Put a requirement area on every floor**, the **Floors that already have devices** dropdown under the headcount. The choices are the same as in Capacity:
  - **Keep them as they are**
  - **Replace device counts, keep the area outline**
  - **Replace device counts and redraw the area**
- **Default:** the value saved in **Settings → Capacity → Floors that already have devices**, the same default Capacity starts on. That setting ships as **Keep them as they are**, so nothing changes until it or the dropdown is changed. The dropdown returns to the saved default when another project is opened; changing it affects that run only and is not saved.
- Replacing works exactly as it does in Capacity: the floor is set to the new number and never added to, and any second capacity area on that floor has its devices cleared, keeping its outline. Preparing the same project twice gives the same count.
- The step 2 preview names what happens to each such floor, for example "replace 150 devices with 600, keep the outline".
- The Settings page note for **Floors that already have devices** now says it applies to Capacity and Prep.

## Verified

- With nothing chosen, a floor carrying 100 + 50 devices is kept at 150, as before.
- With **Replace device counts, keep the area outline**, the same floor carries exactly the new count, read back from the prepared project; the second area's devices are cleared and its outline kept; preparing the result again gives the same count.
- **Replace device counts and redraw the area** redraws the outline; a whole-plan placeholder that Prep re-measures is replaced by one area at the new count, not two.
- On the real Prep page, the dropdown starts on the saved default, falls back to **Keep them as they are** for a value it does not recognise, sends its choice with the preview and with **Prepare**, returns to the saved default on the next project, and never writes the setting.
- These checks fail if the pipeline stops passing the choice to the writer, or if the page stops reading the saved default.
