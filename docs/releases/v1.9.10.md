Cloud Manager: Design / Measured / Hybrid pills now show on local .esx rows too — the same badge you already had on the cloud side, matched by reading the .esx contents.

## What changed

### Local project-type pills
Every local `.esx` row now carries a `Design`, `Measured`, or `Hybrid` pill next to its filename, matching the pills the cloud side already shows. Same colors, same tooltip pattern, same CSS — so a matched cloud↔local pair is now visually consistent end-to-end.

The type comes from what's actually inside the `.esx` (which is a zip):
- `simulatedRadios.json` present → **Design** (planned/simulated APs)
- `measuredRadios.json` present → **Measured** (survey data)
- both present → **Hybrid**
- neither → no pill (empty projects, templates, and any older-format files stay unbadged rather than mislabeled)

Scan is cached by `mtime` alongside the existing `_esx_author` cache, so a cold pass on ~150 files runs once and every follow-up read is instant. Re-saving an `.esx` (mtime bumps) re-parses that one file only.

### Version bumps
- Suite `v1.9.9 → v1.9.10`
- Cloud Manager `v4.1.0 → v4.2.0` (visible enhancement to the ledger)

## Files changed
- `tools/cloud_manager.py` — new `_esx_project_type(path, mtime)` reads the .esx zip and returns `"Design" | "Measured" | "Hybrid" | None`; wired into both `get_local_esx_files()` (used by the Sites tree's per-folder children) and the flat Projects view's local-item build. Cached in `_ESX_TYPE_CACHE`, separate from the author cache so neither shadows the other.
- `web/assets/js/cloud.js` — `localCell()` now emits the same `.ptype-tag pt-<type>` span the cloud side already renders when `l.projectType` is populated. Sites/folder rows stay unbadged; only individual `.esx` rows get the pill.
- `web/assets/versions.json` — suite + cloud bumps.
